# 巡查管理

## 文档定位
- 本文档是后台管理巡查管理模块的主 PRD，统一收敛巡查记录列表、上传巡查记录页、巡查记录详情页的页面规则和共享口径。
- 原型继续按独立页面 HTML 维护；本文档按模块整合页面规则，不再单独维护页面级 md。
- 历史迁移来源主要为 `../../90-归档记录/2026-03-28-流程图决策.md`。

## 模块定位
- 本模块负责后台侧巡查记录管理与查看，承接 App 上传后的后台记录治理能力。
- 数据治理闭环流程以 [../../00-项目总览/业务流程.mmd](../../00-项目总览/业务流程.mmd) 为准。

## 模块边界
- 后台侧承接巡查记录列表、上传巡查记录页和巡查记录详情页。
- App 侧登录、项目选择、拍照上传、个人中心等页面不在后台管理端展开。

## 通用规则
### 巡查记录生成规则
| 规则项 | 说明 |
|--------|------|
| 口径引用 | 巡查记录归属沿用巡查记录判定规则，后台与 App 一致 |
| 生成条件 | 点击保存且当前至少 1 张成功图片时，生成 1 条巡查记录 |
| 项目关联 | 后台上传与移动端上传都必须关联到一个项目 |
| 来源字段 | 记录来源为后台上传 / 移动端上传，用于列表与详情展示 |
| 时间字段 | 巡查时间为主显示时间，上传时间为辅助展示时间 |
| 部分失败 | 失败图片在选图当次即被拦截并集中提示，成功图片可保留并直接保存当前记录 |
| 项目状态联动 | 项目是否已巡查取决于是否存在巡查记录 |

### 区域权限与项目选择规则
- 巡查记录从关联项目继承行政区域，用于列表筛选和账号服务区域权限判断；巡查记录本身不单独维护行政区域。
- 巡查记录列表默认只展示当前账号服务区域内项目产生的巡查记录；平台管理员可查看全量巡查记录。
- 行政区域筛选项按当前账号服务区域裁剪；普通账号只能筛选自己服务区域内的区域，平台管理员可全量筛选。
- 上传巡查记录页搜索/选择项目时，仅展示当前账号服务区域内的项目。
- 巡查记录详情页编辑态修改关联项目时，仅允许选择当前账号服务区域内的项目。
- 选择项目后，`巡查人` 候选按项目行政区域匹配巡查人员服务区域；项目选择权限与巡查人候选匹配是两个独立校验，均必须满足。

### 上传巡查记录页


###### 对应原型
- [查看原型](../../04-原型效果图/后台管理/巡查管理-上传巡查记录页.html)

###### 设计内容
**页面定位**：后台新增巡查记录的唯一入口；图片校验统一在选图与上传阶段完成，不设置失败列表或失败处理区。

###### 页面状态

| 状态键 | 状态名称 | 用途 |
|------|------|------|
| `empty` | 空状态 | 未上传图片时的默认状态 |
| `uploaded` | 已上传状态 | 已选择图片后的缩略图预览状态 |
| `save-confirm` | 保存确认 | 保存前二次确认弹窗状态 |
| `upload-fail-size` | 大小超限反馈 | 本次选图存在 `>10MB` 图片时的集中提示弹窗 |
| `upload-fail-count` | 数量超限反馈 | 本次选图导致总数超过 `50` 张时的集中提示弹窗 |
| `upload-fail-mixed` | 混合失败反馈 | 本次选图同时存在大小超限与数量超限时的集中提示弹窗 |
| `upload-limit-full` | 达到上限 | 当前已选 `50` 张图片，上传入口禁用 |

- 原型右上角状态切换浮窗仅用于演示多状态，不属于实际交付 UI。

###### 巡查记录生成规则映射（迁移自归档记录）

| 规则项 | 现行规则落位 |
|------|------|
| 口径引用 | 巡查记录归属沿用“巡查记录判定规则”，后台与移动设备 App 一致 |
| 状态字段 | 巡查记录不设置独立状态字段 |
| 生成条件 | 点击 `保存` 且当前至少存在 `1` 张成功图片时，生成 `1` 条巡查记录 |
| 项目关联 | 后台上传与移动设备 App 上传都必须关联到一个项目 |
| 来源字段 | 记录来源为 `后台上传 / 移动端上传`，用于列表与详情展示 |
| 时间字段 | `巡查时间` 为主显示时间，`上传时间` 为辅助展示时间 |
| 部分失败 | 失败图片在选图当次即被拦截并集中提示，不进入持久失败列表；已成功图片可直接保留并继续保存当前记录 |
| 项目状态联动 | 项目是否 `已巡查` 取决于是否存在巡查记录 |
###### 字段规则

| 字段 | 规则 |
|------|------|
| 项目编号/名称 | 必选，通过项目搜索选择；仅展示当前账号服务区域内项目；选定后自动带出项目编号、施工类型、项目名称、项目地址、行政区域 |
| 巡查时间 | 默认当前时间，可手动修改；时间选择控件不得选择晚于系统当前分钟的时间，保存时按分钟粒度兜底校验 |
| 巡查人 | 选择项目后加载候选；仅展示服务区域覆盖该项目行政区域的巡查人员；当前后台操作人符合条件时默认选中，否则为空并要求手动选择 |
| 巡查人员库入口 | 位于 `巡查人` 控件下方；当当前项目服务区域暂无可选巡查人员时，可点击“去巡查人员库添加”跳转至巡查人员库维护服务区域 |
| 备注 | 选填，多行文本输入，位于 `巡查人员库入口` 下方、`上传人` 上方 |
| 上传人 | 固定记录为当前后台操作人，只读展示 |
| 上传图片 | 仅支持 `jpg`、`png`；未上传时显示 `点击上传 / 拖拽上传` 与 `暂未上传图片`，上传后切换为缩略图预览区，并保留 `＋` 上传占位卡 |

###### 行政区域与巡查人员显示规则

| 规则项 | 说明 |
|------|------|
| 判断基准 | 以当前已选择项目的 `行政区域` 作为判断基准；巡查记录本身不单独维护行政区域 |
| 数据来源 | 项目行政区域来自项目主数据；巡查人员服务区域来自 [用户中心-巡查人员库](用户中心.md#巡查人员库) |
| 显示范围 | `巡查人` 下拉仅显示服务区域覆盖当前项目行政区域的巡查人员 |
| 覆盖定义 | 巡查人员服务区域等于项目行政区域、属于项目行政区域上级区域，或为 `全国` 时，视为覆盖 |
| 多服务区域 | 巡查人员配置多个服务区域时，任一服务区域覆盖项目行政区域即可显示 |
| 平级或跨区 | 巡查人员服务区域与项目行政区域为平级、下级但不覆盖项目、或跨区域时，不显示 |
| 项目变更 | 上传页或详情编辑态变更项目后，必须按新项目行政区域重新加载巡查人候选 |
| 无候选 | 当前项目行政区域下无可选巡查人员时，提示先维护巡查人员服务区域，并提供巡查人员库入口 |

示例：项目行政区域为 `广东省 / 深圳市 / 南山区 / 粤海街道` 时，服务区域为 `全国`、`广东省`、`深圳市`、`南山区` 或 `粤海街道` 的巡查人员可显示；服务区域为 `福田区`、`宝安区` 或 `上海市` 的巡查人员不显示。

###### 巡查人候选规则

- 未选择项目时，`巡查人` 控件禁用或提示“请先选择项目”。
- 选择项目后，以项目行政区域反向匹配巡查人员服务区域；巡查人员任一服务区域等于项目行政区域，或为项目行政区域的上级区域时，视为覆盖。
- `全国` 服务区域覆盖全部项目行政区域；多服务区域巡查人员按服务区域并集判断，任一服务区域命中即可进入候选。
- 候选项展示为 `巡查人姓名（命中服务区域）`；巡查人员存在多个服务区域时，仅展示与当前项目行政区域匹配的服务区域，不展示无关服务区域。
- 同一巡查人员存在多个命中服务区域时，优先展示最细层级的命中区域；例如同时命中 `深圳市` 与 `南山区` 时展示 `南山区`。
- 若无可选巡查人员，提示“当前项目行政区域下暂无可选巡查人员，请先维护巡查人员服务区域”，并提供“去巡查人员库添加”入口；未完成维护前不允许保存。
- 点击“去巡查人员库添加”跳转至巡查人员库页面，用于新增巡查人员或维护已有巡查人员服务区域；返回上传页后需重新加载巡查人候选。
- 保存时后端必须校验所选巡查人的服务区域覆盖当前项目行政区域；不覆盖时拦截并提示“巡查人服务区域不覆盖当前项目行政区域”。

###### 上传规则

##### 1. 校验顺序

1. 先校验图片格式、是否可读等基础可用性。
2. 再校验单张大小：`>10MB` 的图片直接拦截，不进入缩略图区。
3. 对剩余合格图片按本次选择顺序尝试加入当前记录。
4. 若加入后总数会超过 `50` 张，则仅保留仍可加入的图片，超出部分不添加。

##### 2. 图片大小

| 图片大小 | 处理方式 | 说明 |
|----------|----------|------|
| `≤10MB` | 原图直接上传 | 保证清晰度 |
| `>10MB` | 拦截，不进入缩略图区 | 批量选图结束后在弹窗中按原因分组提示 |

##### 3. 图片数量上限

| 规则项 | 说明 |
|--------|------|
| 单条记录图片上限 | 单条巡查记录最终可保存图片不超过 `50` 张 |
| 上限统计口径 | 仅统计最终成功加入缩略图区的图片；`>10MB` 图片不占用 50 张名额 |
| 超限处理 | 当已有图片 + 本次合格图片超过 `50` 张时，仅保留前 `50` 张，超出部分不添加，并在弹窗中提示 |

##### 4. 批量选图失败反馈

- 若仅存在 `>10MB` 图片：合格图片保留，弹出「部分图片未能添加」弹窗，按“超过 10MB 未添加”分组列出文件名与大小。
- 若仅存在数量超限：可添加图片保留，超出上限的图片不添加，并按“超过 50 张上限未添加”分组列出文件名。
- 若两类问题同时存在：先保留符合大小要求且仍在 50 张名额内的图片，再在弹窗中用“结果 + 原因拆分”的方式提示，例如“本次成功添加 X 张；未添加图片中，A 张超过 10MB，B 张因超过当前记录 50 张上限未添加”。
- 弹窗仅含 `我知道了` 一个按钮；关闭后不保留失败列表，不提供失败图片重传、删除或单独管理区。

##### 5. 上传区状态行为

- 已选图片支持在保存前逐张删除。
- 删除后即时刷新缩略图列表；当删除至 `0` 张时，上传区自动恢复 `empty` 空状态。
- 当已选图片达到 `50` 张时，上传入口置灰/禁用，并提示 `已达 50 张上限，请先删除后再上传`。
- 删除至低于 `50` 张后，上传入口恢复可用。

###### 保存规则
- 点击 `保存` 前置条件：`巡查时间` 不得晚于系统当前分钟，且当前至少存在 `1` 张成功图片。
- 所选巡查人的服务区域必须覆盖当前项目行政区域。
- 满足条件后进入 `save-confirm`，展示 `项目名称 / 项目地址 / 巡查时间 / 巡查人 / 图片数量`。
- 保存确认弹窗不展示 `备注` 字段。
- 确认后生成 `1` 条新的巡查记录。
- 已有巡查记录不支持追加图片；记录生成后仅支持删图，不支持再追加。

###### 保存结果与异常
- 巡查时间晚于系统当前分钟时点击保存：显示 toast“巡查时间不能晚于当前时间”。
- 巡查人服务区域不覆盖当前项目行政区域时点击保存：显示 toast“巡查人服务区域不覆盖当前项目行政区域”。
- 无成功图片时点击保存：显示 toast“请至少上传1张图片”。

###### 详情规则
- 展示字段：`项目编号`、`施工类型`、`项目名称`、`项目地址`、`来源`、`巡查人`、`巡查时间`、`备注`、`上传人`、`上传时间`、`更新人`、`更新时间`。
- 行政区域从关联项目继承，用于列表筛选和账号服务区域权限判断；巡查记录本身不单独维护行政区域。
- 页面不展示 `项目ID`。
- 详情态底部按钮位于页面右下角，包含 `上一条 / 下一条 / 编辑 / 删除记录`。
- 点击 `上一条 / 下一条` 不离开当前页面，按巡查记录列表当前顺序切换内容；第一条时 `上一条` 置灰，最后一条时 `下一条` 置灰。

###### 图片管理规则
- 仅支持删除当前巡查记录下的图片，不支持追加或替换。
- 编辑态中单图可标记删除，底部显示 `取消 / 保存`。
- 编辑态不展示系统信息，仅展示当前可纠错字段与图片删除区。
- 编辑态中，若当前仅剩 `1` 张图片，点击该图片删除入口时不删除图片，并 toast 提示“巡查记录至少保留 1 张图片，如需清空请使用「删除记录」”；`delete-blocked` 状态应保留最后 `1` 张图片用于表达受阻结果。
- 仅当标记删除后仍至少保留 `1` 张图片时，`保存` 按钮才可点击；尝试删除最后 `1` 张图片时不产生删除标记。
- 巡查记录图片与标注训练样本属于不同业务资产。删除巡查记录图片仅影响巡查记录展示与图片数量；未进入标注链路的图片不再可生成新标注任务；已进入标注链路的样本图片不自动删除、不自动失效，标注、质检和入池记录继续保留，并在来源追溯中标记 `来源巡查图片已删除`。

###### 编辑规则
- 编辑态用于“巡查记录纠错”，不是编辑项目主数据。
- 可编辑项为：`关联项目`、`巡查时间`、`巡查人`、`备注`。
- 编辑态修改关联项目后，`巡查人` 候选必须按新项目行政区域重新加载；原巡查人不再覆盖新项目行政区域时，清空巡查人并要求重新选择。
- 编辑态同样在 `巡查人` 控件下方提供“去巡查人员库添加”入口；当前服务区域无可选巡查人员时，可跳转至巡查人员库维护后再返回重新选择。
- 编辑态保存时同样校验所选巡查人的服务区域必须覆盖当前关联项目行政区域。
- 编辑态时间选择控件同样不得选择晚于系统当前分钟的时间，保存时按分钟粒度兜底校验，避免通过纠错入口生成未来巡查记录。
- `项目编号 / 施工类型 / 项目名称 / 项目地址` 由所选项目自动带出，只读展示，不支持手工直接修改。
- `备注` 为选填多行文本输入，位于 `巡查人员库入口` 下方、`上传人` 上方。
- `上传人` 只读展示，不允许修改。
- 详情态点击 `编辑` 后进入编辑态；原型中的“批量管理态”语义统一视为“编辑态”。

###### 保存确认规则
- 编辑态点击 `保存` 后进入 `save-confirm`。
- 保存确认弹窗展示字段为：`项目名称 / 项目地址 / 巡查时间 / 巡查人 / 待删除图片数量`。
- 保存确认弹窗不展示 `备注` 字段。
- 弹窗中显示的项目信息取当前编辑结果：
  - 若未变更关联项目，则显示原项目的项目名称与项目地址。
  - 若已变更关联项目，则显示变更后项目的项目名称与项目地址。
- 弹窗中显示的 `巡查时间 / 巡查人` 同样取当前编辑后的值。
- 确认保存后，统一提交 `关联项目变更 + 巡查时间修改 + 巡查人修改 + 图片删除结果`。

###### 删除记录规则
- `删除确认` 与 `删除受阻` 作为独立状态页用于演示删除结果，不与编辑态保存确认混用。
- 点击 `删除记录` 后进入 `delete-confirm`，提示删除将同时移除该记录及关联图片且不可恢复。
- 用户确认后删除该巡查记录及关联图片，成功后返回巡查记录列表。
- 删除某项目最后一条巡查记录后，该项目状态自动回写为 `未巡查`。

###### 决策原因
- 巡查记录定义为一次完整上传会话结果，记录生成后边界保持稳定。
- 允许通过编辑态纠正关联项目、巡查时间、巡查人，并允许删图用于纠错，但不允许追加，避免改变巡查语义与统计口径。
- 保存确认弹窗按当前编辑结果展示，避免用户在变更关联项目后仍看到旧项目信息，降低误操作风险。


## 跨页面状态与数据流
- 巡查记录列表页是后台巡查数据主管理入口。
- 上传巡查记录页创建新记录后回到列表；列表进入详情页查看与删图管理。
- 巡查记录删除和删图结果会反向影响项目状态与图片数量展示。

## 异常与边界
- 上传页不保留失败列表区，失败图片必须在上传阶段当场拦截或处理。
- 巡查记录保存后不支持继续追加图片，只支持删图与删除记录。
