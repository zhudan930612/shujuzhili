# 项目编辑字段决策

## 决策背景
- 项目管理原规则将 `项目地址`、`施工单位` 与 `施工类型`、`关联保险公司` 一并列为编辑态不可修改字段。
- 需求评审发现该口径过于粗糙：项目地址和施工单位存在运营纠错、补录和名称规范化诉求，不应要求删除项目后重新创建。
- 同时，行政区域已被确定为统计、辖区权限、巡查任务派发和法规匹配的结构化归属字段，修改影响大于普通地址文本。
- 进一步评审后确认：项目一旦已有巡查记录，代表线下服务已按当时项目事实开展，普通编辑入口不应再修改关键事实字段，避免历史巡查语义、权限、统计和交付归属漂移。

## 决策结论
| 字段 | 无巡查记录 | 有巡查记录 | 决策原因 |
|------|------------|------------|----------|
| 项目编号 | 只读 | 只读 | 系统生成，作为项目唯一追溯编号，不允许人工修改或回收复用 |
| 施工类型 | 只读 | 只读 | 参与项目编号前缀和分类统计，创建后应保持稳定 |
| 关联保险公司 | 可编辑，必填 | 只读 | 无巡查记录时属于主数据纠错；已有巡查记录后影响服务采购方、交付归属和统计口径 |
| 项目名称 | 可编辑，必填 | 只读 | 已巡查后代表线下服务已按当时项目名称开展，不在普通编辑入口改写历史语义 |
| 项目地址 | 可编辑，必填 | 只读 | 已巡查后代表线下服务已按当时现场地址开展，不在普通编辑入口改写历史语义 |
| 行政区域 | 可编辑，必填，至少到街镇 | 只读 | 属于结构化归属字段，影响统计、辖区权限、巡查任务派发和法规匹配 |
| 施工时间 | 可编辑 | 只读 | 已巡查后不再改写当时项目周期背景，避免影响筛选和统计 |
| 施工单位 | 可编辑，必填 | 只读 | 已巡查后不再改写当时服务对象和现场责任主体 |
| 负责人姓名 / 电话 | 可编辑，选填 | 可编辑，选填 | 属于当前联系人维护，不改变历史巡查事实 |
| 备注 | 可编辑，选填 | 可编辑，选填 | 仅承载补充说明 |

## 已巡查项目冻结规则
- 未巡查项目允许修正项目主数据，包括 `关联保险公司`、`项目名称`、`项目地址`、`行政区域`、`施工时间`、`施工单位`、`负责人姓名 / 电话` 和 `备注`。
- 项目已有巡查记录后，关键事实字段在编辑态置为只读，包括 `项目名称`、`项目地址`、`行政区域`、`施工时间`、`关联保险公司` 和 `施工单位`。
- 已巡查项目仍允许维护 `负责人姓名 / 电话` 和 `备注`，用于后续运营联系和补充说明。
- 冻结原因：已有巡查记录代表线下服务已按当时项目事实开展，关键字段变更会影响历史巡查语义、辖区权限、巡查任务派发、后台统计、法规匹配和保险公司交付归属。
- 若确需调整已巡查项目关键事实字段，应先处理关联巡查记录或走后续专项数据修正流程，不纳入普通编辑弹窗。
