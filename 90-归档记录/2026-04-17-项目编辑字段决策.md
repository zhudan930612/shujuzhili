# 项目编辑字段决策

## 决策背景
- 项目管理原规则将 `项目地址`、`施工单位` 与 `施工类型`、`关联保险公司` 一并列为编辑态不可修改字段。
- 需求评审发现该口径过于粗糙：项目地址和施工单位存在运营纠错、补录和名称规范化诉求，不应要求删除项目后重新创建。
- 同时，行政区域已被确定为统计、辖区权限、巡查任务派发和法规匹配的结构化归属字段，修改影响大于普通地址文本。

## 决策结论
| 字段 | 编辑态规则 | 决策原因 |
|------|------------|----------|
| 项目编号 | 禁止修改 | 系统生成，作为项目唯一追溯编号，不允许人工修改或回收复用 |
| 施工类型 | 禁止修改 | 参与项目编号前缀和分类统计，创建后应保持稳定 |
| 关联保险公司 | 禁止修改 | 表示服务订单和采购方归属，影响业务责任边界 |
| 项目地址 | 允许修改，必填 | 属于详细地址文本，允许运营纠错，不单独触发二次确认 |
| 行政区域 | 未巡查项目允许修改，已巡查项目禁止修改；必填，至少到街镇 | 属于结构化归属字段，影响统计、辖区权限、巡查任务派发和法规匹配 |
| 施工单位 | 允许修改，必填 | 施工单位是服务对象核心信息，必须从施工单位库选择或匹配 |
| 负责人姓名 / 电话 | 允许修改，选填 | 属于现场联系信息，允许随项目实际情况更新 |
| 施工时间 | 允许修改 | 属于项目计划信息，允许按实际工期纠正 |
| 备注 | 允许修改，选填 | 仅承载补充说明 |

## 行政区域冻结规则
- 未巡查项目允许修改 `行政区域`，保存时必须至少选择到街镇层级。
- 项目已有巡查记录后，`行政区域` 在编辑态置为只读，不允许修改。
- 冻结原因：行政区域变更会影响后台统计、巡查任务派发、辖区权限过滤和法规匹配。
- 若确需调整已巡查项目行政区域，应先处理关联巡查记录或走后续专项数据修正流程，不纳入普通编辑弹窗。
