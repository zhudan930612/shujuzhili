# 2026-04-20 行政区域层级与辖区权限决策

## 背景
- 平台后续可能在不同省、市、区开展安责险事故预防服务，需要统一项目属地、巡查服务区域、后台区域筛选和法规适用地区口径。
- 巡查人员只能处理其服务区域内项目，后台上传巡查记录和详情编辑也需要受同一辖区规则约束。
- 不同地区可能存在地方性法规或监管要求，法规库需要具备适用地区字段，并在报告或识别结果中按项目所在地匹配。

## 决策结论
- 行政区域字典作为统一基础数据，供项目管理、巡查人员服务区域、巡查记录筛选和法规适用地区共同引用。
- 项目行政区域采用 `省 / 市 / 区县 / 街镇 / 社区` 五级结构；项目新增、未巡查编辑和批量导入至少到 `街镇`，`社区` 选填。
- 项目地址是详细地址文本，行政区域是标准结构化属地；项目批量导入不依赖地址解析生成行政区域。
- 巡查人员 `服务区域` 复用为可见辖区和后台数据权限范围，口径为 `服务区域 = 巡查员可见辖区 = 后台数据权限范围`。
- 巡查记录从关联项目继承行政区域；列表筛选、项目选择和详情查看均按当前账号服务区域过滤。
- 新增或编辑巡查记录时，巡查人候选必须按项目行政区域匹配巡查人员服务区域；实际巡查人服务区域不覆盖项目行政区域时不得保存。
- 法规库 `适用地区` 支持 `全国 / 省 / 市 / 区县`，不支持街镇和社区；法规唯一性包含 `适用地区`。
- 法规匹配默认按项目行政区域路径逐级匹配，优先级为 `区县 > 市 > 省 > 全国`；非项目路径地区法规默认不展示。
- 人工选择其他适用地区仅影响当前法规候选或当前报告结果，不反向修改项目行政区域或法规库适用地区。

## 已关闭问题
- 历史项目区域补录：当前没有存量数据，暂不设计人工补录或批量补录流程；后续若导入历史项目，按项目导入规则补充所属行政区域。

## 后续扩展问题
- 当前后台数据权限先按行政区域 / 服务区域执行；是否叠加保险公司、服务机构或项目来源作为数据隔离维度，留待权限模型专项确认。
- 用户中心当前仅承接巡查人员库与服务区域；如后续需要完整用户 / 角色 / 组织管理，应新增角色与权限专项 PRD。
