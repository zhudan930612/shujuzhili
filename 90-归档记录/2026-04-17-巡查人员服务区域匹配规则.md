# 2026-04-17 巡查人员服务区域匹配规则

## 背景
- 巡查记录必须关联项目，项目已维护标准行政区域。
- 巡查人员账号已配置 `服务区域`，该字段同时承担可见辖区和后台数据权限范围。
- 新增或编辑巡查记录时，原规则只明确项目选择受当前账号服务区域限制，未明确实际巡查人是否需要覆盖项目行政区域。

## 决策
- 新增巡查记录选择项目后，`巡查人` 候选仅展示服务区域覆盖该项目行政区域的巡查人员。
- 巡查记录详情页编辑态修改关联项目后，`巡查人` 候选按新项目行政区域重新过滤；原巡查人不再覆盖新项目行政区域时，清空并要求重新选择。
- 保存时必须后端兜底校验：所选巡查人的服务区域覆盖当前项目行政区域。
- 巡查人员服务区域支持多区域选择；多个服务区域取并集，任一服务区域命中即可进入候选。
- 候选项展示 `巡查人姓名（命中服务区域）`；多服务区域巡查人员只展示与当前项目行政区域匹配的服务区域。

## 匹配口径
| 场景 | 规则 |
|------|------|
| 服务区域等于项目行政区域 | 可选 |
| 服务区域为项目行政区域的上级区域 | 可选 |
| 服务区域为 `全国` | 可选 |
| 巡查人员配置多个服务区域 | 任一服务区域命中即可选 |
| 服务区域与项目行政区域为平级或跨区域 | 不可选 |

## 候选展示规则
| 场景 | 展示方式 |
|------|----------|
| 只有一个服务区域命中 | 展示 `巡查人姓名（命中服务区域）` |
| 多个服务区域中仅一个命中 | 只展示命中的服务区域，不展示其他无关服务区域 |
| 多个服务区域同时命中 | 展示最细层级的命中区域 |
| 命中 `全国` 且无更细区域命中 | 展示 `巡查人姓名（全国）` |

## 多区域选择规则
| 场景 | 规则 |
|------|------|
| 多个非重叠区域 | 允许保存，权限范围取并集 |
| 上级区域与下级区域同时选择 | 下级区域被上级区域覆盖，保存时可自动去重或提示移除重复项 |
| 选择 `全国` | 覆盖全部区域，不再叠加其他区域 |
| 已选其他区域后选择 `全国` | 以 `全国` 覆盖原有区域 |

## 取舍说明
- 不采用“只按当前操作账号服务区域过滤巡查人”：当前操作账号和实际巡查人可能不是同一人，无法保证巡查记录归属正确。
- 不允许平台管理员绕过巡查人员服务区域直接指定跨区巡查人：管理员可操作全量项目，但实际巡查人仍应受其服务区域约束。
- 临时跨区巡查暂不纳入本阶段；如后续需要，应通过临时授权或扩展服务区域配置承接，而不是绕过本规则。
