# AI辅助产品工作流设计

## 核心原则

- **产品经理只关注功能文档**：决策、审阅、拍板
- **AI管理项目结构**：自动归档、更新知识库、加载背景
- **渐进式沉淀**：每个功能过审后自动融入产品知识库

---

## 场景A：从0→1（冷启动建产品）

输入：原始素材（录音/政策/PPT/竞品分析）
输出：完整产品知识资产 + V1.0功能规划

```
原始素材 → AI提取信息 → 业务背景文档
                      ↓ 用户确认
              需求与目标讨论
                      ↓
              业务流程梳理
                      ↓
              产品架构设计
                      ↓
              功能清单与优先级
                      ↓ 用户选定迭代范围
              具体功能详细设计（单功能完整文档）
                      ↓ 用户确认"过审"
              AI自动融合归档 + 更新知识库
```

---

## 场景B：从1→2（持续迭代）

输入：新需求描述 + 已沉淀的产品知识资产
输出：当前迭代的PRD + 更新的知识资产

```
用户："做个功能：XXX"
         ↓
AI自动加载产品知识库
         ↓
背景校准（确认理解现状）
         ↓
需求分析 → 业务流程 → 详细设计 → PRD文档
         ↓ 用户确认"过审"
AI归档 + 更新知识库
```

---

## 功能文档标准结构

每个功能模块输出一份完整过审文档：

| 章节 | 内容 | 用户决策点 |
|-----|------|-----------|
| 1. 需求分析 | 问题本质、用户场景、不做会怎样 | 确认理解对吗？ |
| 2. 目标与验收 | 成功指标、验收标准 | 指标可衡量吗？ |
| 3. 业务流程 | 正常流程、异常分支、状态机 | 流程完整吗？ |
| 4. 功能设计 | 页面/交互、字段、规则 | 符合用户习惯吗？ |
| 5. 技术对接 | 接口、数据模型、依赖模块 | 技术可行吗？ |
| 6. 迭代计划 | 优先级、MVP范围、后续优化 | 节奏合理吗？ |

---

## 协作指令约定

| 用户说 | AI响应 |
|--------|--------|
| "从0开始，XXX产品" | 请求素材 → 生成业务背景 |
| "做个功能：XXX" | 加载知识库 → 需求分析 → 输出完整文档 |
| "确认，过审" | 归档 → 更新知识库 → 告知完成 |
| "这里不对..." | 修改当前文档，继续讨论 |
| "看现在有哪些功能" | 读取知识库 → 输出功能全景 |

---

## 项目文档结构（AI维护，用户透明）

```
项目架构/
├── 01-产品基座/              # 业务背景、产品定位、用户角色、系统架构
├── 02-功能模块/              # 每个功能独立过审文档
│   ├── F01-XXX/
│   │   └── PRD-过审.md
│   └── F02-XXX/
│       └── PRD-过审.md
├── 03-知识库视图/            # AI自动维护的聚合视图
│   ├── 功能全景图.md
│   ├── 接口汇总.md
│   ├── 数据模型总览.md
│   └── 迭代路线图.md
└── index.md                  # 项目入口索引
```

**用户无需关注此结构，所有背景由AI自动加载。**
