# Layer Governance Rules

## 唯一判断规则

以下 6 条规则是当前仓库分层治理的唯一判断标准：

1. 凡是「每个会话都应该知道」的东西，进顶层默认层；当前仓库默认优先放 `AGENTS.md`，如果没有合适的 `AGENTS.md` 承载位，再考虑 `CLAUDE.md`。
2. 凡是「多步流程、专题检查、分支决策」，进 `skill`。
3. 凡是「只对某目录或某类文件生效」，进 `path-scoped rules`；`nested CLAUDE.md` 只是某些 CLI/harness 支持该层的一种实现，不是唯一形式。
4. 凡是「必须每次执行、不能靠模型自觉」，进 `hook`。
5. 凡是「模型需要真实执行或查询」，进 `CLI`、`MCP` 或 `scripts`。
6. 凡是已经从「专题经验」变成「所有相关任务都应该遵守的通用约束」，从 `skill` 上移到顶层默认层；当前仓库默认优先上移到 `AGENTS.md`，只有 `AGENTS.md` 不适合承载时才考虑 `CLAUDE.md`。

如果以上 6 条都不命中，不要强行升级。应明确说明当前暂不沉淀，保留在当前对话、本轮过程文档或现有位置。

## 当前仓库默认映射

- 规则 1 在当前仓库中默认优先落到 `AGENTS.md`；`CLAUDE.md` 主要作为薄指针或兜底入口，不作为首选主承载位。
- 规则 2 默认落到 `.claude/skills/*/SKILL.md`。
- 规则 3 在当前仓库中默认优先通过目录 `README.md` 承担 `path-scoped rules`；如果未来引入 `nested CLAUDE.md`、其他路径级规则文件或 IDE/CLI 原生 path rules，仍视为同一层。
- 规则 4 当前主要作为 `hook` 候选输出，默认参考 `.claude/settings.local.json`。
- 规则 5 默认优先落到 `06-工具脚本/*.py`、`python 06-工具脚本/run_checks.py --scope ...` 等现有执行入口。
- 规则 6 在当前仓库中默认理解为：当一条专题经验已反复复用且所有相关任务都应遵守时，优先上移到 `AGENTS.md`；只有 `AGENTS.md` 没有合适承载位时才考虑 `CLAUDE.md`。

## 当前仓库补充出口

以下内容不属于上面 1-6 条里的协作规则层，而属于当前仓库必须单独处理的正式主定义出口：

- 稳定业务规则
- 页面规则
- 字段规则
- 流程主定义
- 历史决策原因

这些内容不应长期留在 `03-工作台/*.md`。应根据内容拆回：

- `00-项目总览/`
- `01-产品架构/`
- `02-PRD文档/`
- `90-归档记录/`

审计或分诊时，如果判断对象本质上是业务主定义而不是协作规则、流程规则或执行动作，必须明确指出“应拆回正式主定义层”，不要误判到 `AGENTS.md`、README、skill、hook 或 script。
