# 工作台

## 目录定位
当前目录用于承接当前轮次的需求沟通、候选需求和评审记录。

## 主要内容
| 文件 | 用途 |
|------|------|
| [需求沟通模板.md](需求沟通模板.md) | 需求沟通骨架模板，用于复制后新建每轮沟通文档 |
| [需求池.md](需求池.md) | 候选需求、已规划需求和已拒绝需求 |
| [评审记录.md](评审记录.md) | 方案、PRD、原型或结构调整的评审意见 |
| [错误治理清单.md](错误治理清单.md) | 已犯错误的制度化治理动作索引 |
| [页面架构文档.md](页面架构文档.md) | 单页面需求架构沟通骨架，仅用于页面级需求沟通模板，不是正式主定义 |

## 归位规则
- 未稳定的讨论先放在本目录。
- 结论稳定后拆回 [../00-项目总览](../00-项目总览/)、[../01-产品架构](../01-产品架构/) 或 [../02-PRD文档](../02-PRD文档/)。
- 定稿后的会议、方案、政策和参考资料归档到 [../05-来源资料](../05-来源资料/)。

## 协议驱动区
- 产品设计、PRD、原型、模板、需求沟通类任务，默认先看 [任务执行协议.md](任务执行协议.md)，结束前回到 [任务完成检查.md](任务完成检查.md) 收尾。
- 每轮需求沟通应先基于 [需求沟通模板.md](需求沟通模板.md) 新建沟通文档，再承接过程、背景、取舍、待确认项和拆回清单；模板本身不直接写具体需求。
- [评审记录.md](评审记录.md) 承接评审判断、反对意见、取舍原因和后续处理。
- [错误治理清单.md](错误治理清单.md) 承接“已经犯过的错如何制度化”，用于把口头纠正升级成规则、模板或脚本检查。
- 稳定结论必须拆回正式文档；`run_checks.py --scope all` 通过只代表结构闭环基本成立，不代表业务判断已经正确。
- 具体需求沟通文档出现大体量 warning 时，默认动作是拆回或归档，不是长期保留。

## 维护约定
- 本目录不作为业务规则主定义长期存在。
- 需求沟通模板应保持“模板骨架”定位；每轮新建的需求沟通文档应保持“过程记录 + 结论摘要”，避免与正式 PRD 重复完整规则。
- 新建需求沟通文档默认命名为 `YYYY-MM-DD-需求主题-需求沟通.md`。
- 需求池只记录需求项，不展开完整方案。
