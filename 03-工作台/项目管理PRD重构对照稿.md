# 项目管理模块 PRD 重构对照稿

## 文档定位
- 本文档只用于对比 [../02-PRD文档/后台管理/项目管理.md](../02-PRD文档/后台管理/项目管理.md) 的重构方式。
- 本文档不是正式主定义，不替代模块 PRD。
- 本文档确认后，再按这里的结构和迁移规则去正式调整 `项目管理.md`。

## 一、当前结构概览

### 1. 当前模块级结构
当前 [项目管理.md](../02-PRD文档/后台管理/项目管理.md) 已具备模块主 PRD 的基本壳结构：
- 文档定位
- 模块定位
- 模块边界
- 通用规则
- 页面清单与原型映射
- 页面设计
- 跨页面状态与数据流
- 异常与边界
- 历史迁移说明

### 2. 当前页面清单
当前模块内共维护 3 个页面：
- 项目列表页
- 项目详情页
- 批量导入项目

### 3. 当前结构的主要问题
当前文档的问题不在“有没有内容”，而在“页面章节内部的组织方式仍是旧写法”，主要表现为：

#### 模块级结构基本正确，但页面级结构不统一
- 模块壳已经是“一个模块一个 PRD”的形态，这一层不需要推翻。
- 真正要调整的是页面章节内部结构。
- `项目列表页`、`项目详情页`、`批量导入项目` 三页的写法风格明显不同，研发阅读成本高。

#### 列表页把弹窗态混进了页面状态
- 当前 `项目列表页` 的 `页面状态` 表同时写了：
  - `list`
  - `create`
  - `edit-uninspected`
  - `edit-inspected`
  - `delete-confirm`
  - `delete-blocked`
- 其中 `create / edit / delete-confirm / delete-blocked` 本质上是弹窗或阻断交互，不是页面本体状态。
- 这会导致页面状态、弹窗规则、操作规则混在一起。

#### 正式 PRD 中仍保留大段 ASCII 草图正文
- `项目列表页`、`项目详情页` 中仍保留整段 `ASCII原型` / 原型说明块。
- 这些内容一部分是页面结构表达，一部分是实际业务规则。
- 正式 PRD 继续长期维护草图正文，后续会和 HTML 原型双维护漂移。

#### 页面字段、操作、异常没有按统一骨架归位
- `项目列表页` 把 `列表字段 / 历史扩展字段 / 筛选条件 / 分页规则 / 操作规则` 分散写开了。
- `项目详情页` 仍带有较多“原型说明式”描述，没有按页面字段、页面操作、页面异常归位。
- `批量导入项目` 更偏流程说明，和其他两个页面的写法不一致。

#### 页面与模块共享规则仍有继续收口空间
- 当前模块级已经上提了部分通用规则，例如项目行政区域规则。
- 但像 `项目编号生成规则`、`状态判定与回写`、部分导入与新增共用规则，仍可以更明确地作为跨页面共用规则沉淀。

## 二、目标结构草案

### 1. 重构后的模块级骨架
`项目管理.md` 保持“一个模块一个 PRD 文件”，目标结构建议调整为：

1. 文档定位
2. 模块定位
3. 模块边界
4. 通用规则 / 跨页面共用规则
5. 页面清单与原型映射
6. 页面需求
7. 跨页面状态与数据流
8. 待确认问题清单

调整说明：
- `历史迁移说明` 不再单独占大节，可并入 `文档定位` 说明来源。
- `页面设计` 改为 `页面需求`，强调按页面骨架写规则，而不是按旧稿拼接。
- `异常与边界` 不再只保留模块级一小节；真正页面级异常回到各页面章节。

### 2. 重构后的页面级骨架
模块内每个页面统一按以下章节展开：

1. 页面基本信息
2. 页面入口
3. 对应原型
4. 页面状态
5. 字段与展示规则
6. 操作规则
7. 异常与边界
8. 页面弹窗 / 抽屉
9. 权限相关行为
10. 模块衔接
11. 暂缓 / 待研发确认项
12. 页面待确认问题

页面级落位原则：
- 正式 PRD 不再保留页面 ASCII 草图正文，只引用原型文件。
- 页面字段按区域各自写，不额外抽“通用字段口径”。
- 页面状态只写页面本体的正常展示状态。
- 新增、编辑、确认删除、删除受限等进入 `页面弹窗 / 抽屉`。

### 3. 三个页面的目标展开方式

#### 项目列表页
建议按以下顺序重写：
1. 页面基本信息
2. 页面入口
3. 对应原型
4. 页面状态
5. 字段与展示规则
   - 筛选字段
   - 列表字段
   - 分页相关展示
6. 操作规则
   - 查询
   - 重置
   - 查看
   - 新增
   - 编辑
   - 删除
   - 批量导入
7. 异常与边界
8. 页面弹窗 / 抽屉
   - 弹窗 / 抽屉清单
   - 操作类弹窗：新增项目、编辑项目（未巡查）、编辑项目（已巡查）
   - 确认类弹窗：删除确认、删除受限提示
9. 权限相关行为
10. 模块衔接
11. 暂缓 / 待研发确认项
12. 页面待确认问题

#### 项目详情页
建议按以下顺序重写：
1. 页面基本信息
2. 页面入口
3. 对应原型
4. 页面状态
5. 字段与展示规则
   - 基本信息展示
   - 巡查数据展示
6. 操作规则
   - 返回
   - Tab 切换
   - 巡查记录定位
   - 图片预览
7. 异常与边界
8. 页面弹窗 / 抽屉
   - 若无独立弹窗，可明确“当前页面无独立弹窗 / 抽屉”
9. 权限相关行为
10. 模块衔接
11. 暂缓 / 待研发确认项
12. 页面待确认问题

#### 批量导入项目
建议按以下顺序重写：
1. 页面基本信息
2. 页面入口
3. 对应原型
4. 页面状态
5. 字段与展示规则
   - 模板字段
   - 预览字段
6. 操作规则
   - 下载模板
   - 上传文件
   - 预校验
   - 确认导入
7. 异常与边界
8. 页面弹窗 / 抽屉
   - 若仅有结果提示或阻断提示，在这里列出
9. 权限相关行为
10. 模块衔接
11. 暂缓 / 待研发确认项
12. 页面待确认问题

### 4. 页面弹窗的归类方式
项目管理模块涉及的弹窗应统一分成两类：

#### 操作类弹窗 / 抽屉
- 新增项目弹窗
- 编辑项目弹窗（未巡查）
- 编辑项目弹窗（已巡查）

这类弹窗按完整子结构展开：
- 基本信息
- 触发入口
- 字段与展示规则
- 操作规则
- 异常与边界
- 权限相关行为
- 数据联动

#### 确认类弹窗
- 删除确认弹窗
- 删除受限提示

这类弹窗按简版结构展开：
- 触发入口
- 触发条件 / 阻断条件
- 提示文案
- 按钮
- 结果反馈

### 5. 模块级迁移原则
正式调整 `项目管理.md` 时，统一遵循以下原则：
- 模块 PRD 继续保持一个文件，不拆成多个页面 md。
- 正式 PRD 不保留页面 ASCII 草图正文，只引用对应原型图文件。
- 模块共享规则上提，不在多个页面重复展开。
- 新增、编辑、确认删除等属于弹窗，不再混入页面状态。
- 页面字段按区域各自写，不额外抽“通用字段口径”。
- 页面权限只写“权限相关行为”，不写角色矩阵。

## 四、对照使用方式
1. 先对照本稿确认 `项目管理.md` 的目标结构是否接受。
2. 再按本稿逐块改正式 `项目管理.md`，不边改边临时设计结构。
3. 正式改造时优先做“模块共享规则上提”和“三个页面结构统一”。
4. 正式改造完成后，本稿可保留为一次性工作记录，或归档到 [../90-归档记录](../90-归档记录/)。
