# 质检方案沟通稿

## 1. 核心口径
- `通过`：当前轮质检认为结果可以继续向下游流转。
- `退回`：当前轮质检认为部分标注对象需要返工，并生成对象级质检退回子任务。
- `不入池`：当前图片结束为不可进入高质量数据池。
- `无效`：该对象不通过、不退回、不进入下一轮，仅用于无修正价值的对象（明显重复、明显误标、已被更优对象替代）；选择时必须填写无效原因。
- `打分`：质检人员按标注对象打分，用于记录对象质量，不直接自动决定 `通过 / 退回 / 无效`。
- `主任务`：图片级质检任务，用于控制一检、二检、三检和最终入池流转。
- `子任务`：对象级质检退回任务，用于承载未通过标注对象的返工。

## 2. 标注阶段

### 分配与提交
- 同一图片分配给多名标注员，采用多人标注模式。
- 返工提交沿用正常标注提交校验：不允许 `待确认类别` 提交，不允许图片加载失败时提交。

### 返工操作权限
- 返工人员可查看整图全部对象上下文，包括已 `通过` 对象和本次 `退回` 对象。
- 返工人员对未通过对象可执行正常标注操作：移动、缩放、调整节点、修改类别、修改属性、删除对象。
- 返工人员允许新增对象，包括顺手补充同图内其他明显漏标对象；新增对象归属当前返工子任务。
- 已通过对象可查看、不可修改、不可删除、不可替换为返工结果。
- 若删除全部未通过对象，允许以空结果提交；空结果只表示本次退回对象已清空，不等同 `无效图片`。

## 3. 一检阶段

### 状态与入口
- 一检查看同一图片下多个标注员的原始标注结果，直接按各标注员提交的原始标注对象逐个处理，不先合并为统一候选对象集。
- 第一版暂不要求系统预先判断多个标注对象是否属于同一目标，由质检人员结合上下文自行判断并选择 `通过 / 退回 / 无效`。

### 操作权限
- 只对标注对象执行 `通过 / 退回 / 无效` 裁决，不允许修改、删除、新增标注对象。
- `通过 / 退回 / 无效` 由质检人员手动选择；`无效` 采用显式开关或按钮操作，不默认自动选中。

### 裁决与退回
- 对被裁决为 `退回` 的标注对象生成质检退回子任务，随机分配给标注人员。
- 退回只针对未通过对象生成对象级返工子任务，不整张图片退回、不整条标注记录退回。
- `无效` 不阻断主流程流转；只有 `退回` 对象才阻断当前图片进入下一轮。

### 流转规则
- 当前图片下所有标注对象均完成 `通过 / 退回 / 无效` 裁决，且不存在待处理退回对象时，图片进入二检。
- 存在退回对象时，图片级主任务保持等待状态；返工人员重新提交子任务后，整图按当前最新对象结果重新进入一检。
- 返工提交后，不区分是否新增对象，均重新执行一检、二检、三检后续质检流程。
- 只有全部退回对象闭环且重新通过后，图片级主任务才进入二检。
- 等待返工期间，仅保留当前轮通过对象集合；待返工结果重新完成一检前，不写入新的当前轮确认结果。

### 返工复核
- 返工人员提交子任务后，不单独停留在局部复核分支，而是整图回到一检按当前最新对象结果重新审核。
- 重新进入一检后，按最新对象结果重新形成当前轮通过对象集合，并继续判断是否满足进入二检条件。

## 4. 二检阶段

### 状态与入口
- 默认先展示一检确认的通过对象集合，同时允许切换查看全部原始标注记录和来源标注员。
- 只有一检不存在 `退回` 状态对象时，图片才进入二检。

### 操作权限
- 只对标注对象执行 `通过 / 退回 / 无效` 裁决，不允许修改、删除、新增标注对象。
- 对一检 `通过` 对象，二检可重新打分，并改判为 `通过`、`退回` 或 `无效`。
- 对一检 `无效` 对象，二检可见只读记录；若不同意一检 `无效`，仅允许改判为 `退回`，不允许直接改判为 `通过`。

### 裁决与退回
- 对被裁决为 `退回` 的标注对象生成新的质检退回子任务，随机分配给标注人员。
- 二检将一检 `通过` 对象改判为 `无效` 时，必须填写无效原因。
- 当前图片存在退回对象时，不能进入下一轮；必须等所有退回对象闭环后才可继续流转。

### 流转规则
- 当前图片下所有标注对象均完成 `通过 / 退回 / 无效` 裁决，且不存在待处理退回对象时，图片进入三检。
- 存在退回对象时，主任务停留在二检并等待子任务；子任务提交后整图重新回到一检，重新执行后续质检流程。

### 对一检无效的改判
- 一检标记为 `无效` 的对象，二检可见，展示时至少保留对象内容、分数、裁决结果、无效原因、裁决人和裁决时间。
- 查看一检 `无效` 记录时，对象内容只读，不直接修改对象本身。
- 若不同意一检 `无效` 裁决，允许改判为 `退回` 并生成新返工子任务。
- 不允许将一检 `无效` 直接改判为 `通过`；若不同意其 `无效`，必须先退回标注员修正，再由当前轮重新复核。

## 5. 三检阶段

### 状态与入口
- 默认先展示二检确认后的通过对象集合，同时允许切换查看全部原始标注记录、来源标注员、一检处理结果和二检处理结果，据此做最终裁决。
- 三检工作台提供对象列表视图，明确区分并展示当前 `通过` 对象和 `无效` 对象，便于终审人员查看各对象当前状态。
- 只有二检不存在 `退回` 状态对象时，图片才进入三检。

### 操作权限
- 三检对标注对象执行 `入池 / 退回 / 无效` 裁决，不允许修改、删除、新增标注对象。
- 对二检 `通过` 对象，三检可重新打分，并改判为 `入池`、`退回` 或 `无效`。
- 对二检 `无效` 对象，三检可见只读记录；若不同意二检 `无效`，仅允许改判为 `退回`，不允许直接改判为 `入池`。
- 三检进入入池路径时，仅可从二检 `通过` 对象中选择最终入池对象；二检 `无效` 对象仅用于查看和辅助判断，不可直接纳入最终结果。
- 三检同一轮不允许对象级 `入池` 与 `退回` 同时存在；终审结论要么进入入池路径，要么进入退回返工路径。

### 裁决与退回
- 对被裁决为 `退回` 的标注对象生成新的质检退回子任务，随机分配给标注人员。
- 三检将二检 `通过` 对象改判为 `无效` 时，必须填写无效原因。
- 若三检认为某个二检 `无效` 对象应保留，必须通过 `退回` 触发前序返工与复核，不能在三检直接改为 `入池`。
- 若三检存在任一 `退回` 对象，则当前图片本轮不得 `入池`，需返工后重新走前序质检流程，再次进入三检终审。

### 流转规则
- 当前图片下所有标注对象均完成 `入池 / 退回 / 无效` 裁决，且不存在待处理退回对象时，图片可执行最终图片级裁决。
- 存在退回对象时，主任务停留在三检并等待子任务；子任务提交后整图重新回到一检，重新执行后续质检流程。
- 若当前图片不存在 `退回` 对象，且最终未保留任何对象级 `入池` 对象，则图片结束为 `不入池`。

### 终局裁决
- 三检是整套质检流程的终审环节，负责最终对象级 `入池 / 退回 / 无效` 裁决和图片级是否入池的最终判断。
- 三检的核心操作就是对对象做 `入池 / 退回 / 无效` 裁决，其中对象级 `入池` 表示该对象进入最终结果。
- 三检作为最终放行关口，可对当前图片做入池或退回裁决；若本轮选择退回，则需完成返工并重新经过前序质检流程后，再次进入三检终审。
- 当前图片不存在 `退回` 对象，且最终仍保留至少 1 个对象级 `入池` 对象时，图片可选择结束为 `入池`。
- 三检的 `不入池` 仅作为图片级终局结果使用，不作为对象级裁决使用。
- 当前图片不存在 `退回` 对象，且最终未保留任何对象级 `入池` 对象时，图片结束为 `不入池`。

## 6. 主子任务关系

- 质检主任务始终是图片级，控制一检、二检、三检和最终入池流转；返工任务是对象级，承载未通过对象的返工。
- 设计原因：图片是否入池本质上是图片级决策，但返工问题已定位到具体对象，无需整图或整条记录重做。
- 三轮分工：一检负责基础问题识别和首轮对象裁决；二检负责规则一致性校准和返工结果复核；三检负责最终训练价值裁决和入池确认。目的是通过多轮审核逐步建立判断能力，避免三轮同质化造成重复劳动。
- 后续轮次虽主看前一轮确认结果，但必须可追溯原始标注来源，否则无法明确退回给谁。
- 主任务与子任务的等待关系：无退回对象时主任务进入下一轮；有退回对象时主任务停留等待子任务；子任务全部复核通过后主任务继续流转；子任务再次不通过则生成新子任务，主任务继续等待。
- 子任务提交后，整图按当前最新对象结果重新回到一检，不区分本次返工是否新增对象。
- 图片级 `入池` 明确等价于“该图最终至少产出 1 个可用对象”，不要求整图全部对象都进入最终结果。
- 所有操作均以追加任务记录方式留痕，不覆盖历史任务记录；标注、返工、一检、二检、三检、改判、评分等操作都必须可追溯。

## 7. 打分逻辑

### 标注人员评分
- 标注人员评分由一检执行；评分记录落在标注对象上，但考核归属对象是对应标注人员。
- 一检对每个标注对象都必须留下评分记录，用于评价对应标注人员本次产出质量。
- 标注对象无论当前裁决结果为 `通过`、`退回`、`无效` 还是三检 `入池`，都必须有对应评分记录。
- 标注对象评分采用十分制；第一版评分阈值先在代码中写死，不提供页面配置能力。
- 分数大于或等于当前阈值，视为达到阈值；分数低于当前阈值，视为低于阈值。
- 对象级分数仅记录质量判断，不自动生成 `通过 / 退回 / 无效` 结果，由质检人员基于分数和实际判断单独操作。
- 允许出现“低于阈值但通过”或“大于等于阈值但退回”的情况；当裁决结果与分数是否达到阈值明显不一致时，质检人员必须填写裁决理由。
- 分数大于或等于阈值的对象被裁决为 `退回` 时，必须填写退回理由；分数低于阈值的对象被裁决为 `通过` 或三检 `入池` 时，必须填写通过理由或入池理由。
- 标注人员评分不存在统一“最终分数”；每一轮留下的分数都是独立评分记录，仅用于还原当轮判断。
- 同一图片中不同对象可分别通过或退回，不再要求整张图片整体同进同退。
- 已通过对象的评分保留为当前轮确认结果；退回对象返工后形成新评分记录，以追加方式记录，不覆盖历史记录。
- 最终可按对象分数、对象通过率、退回次数等维度汇总标注人员质量统计。

### 质检员评分
- 质检人员评分用于评价上一轮质检人员的裁决质量，评分记录归属上一轮质检人员。
- 质检人员评分按对象逐个记录，不按整张图片或整次任务给单一总分。
- 质检人员评分仅针对上一轮已完成裁决的对象逐个记录，裁决范围包括 `通过`、`退回`、`无效`。
- 只要对象在当前轮进入质检判断范围，无论最终裁决结果为 `通过`、`退回`、`无效` 还是三检 `入池`，都应纳入对应评分记录。
- 质检人员评分同样不存在统一“最终分数”；每一轮评分都是独立记录，并保留评分原因。
- 二检开始对一检质检员的裁决质量进行评分记录。
- 三检开始对二检质检员的裁决质量进行评分记录。
- 第一版不做质检人员评分的自动加权或自动汇总，只保留逐轮追加的评分记录和评分原因。

## 8. 补充规则

- 默认全部正常样本都进入一检、二检、三检，不依赖复杂分流逻辑，重点依赖人工多轮审核和逐轮校准。
- 第一版允许同一张图片内存在多个 `同类别 + 同一属性组合` 的标注对象，不做唯一限制。
- 一检、二检、三检均不直接修改标注对象，只负责对现有标注对象做评分和裁决。
- 高质量数据池只接收经过质检确认的标准结果，不直接接收任一标注员的原始结果。
- 返工子任务随机分配给标注人员，以避免因原标注人员离职、请假等情况阻塞主流程。
- 一检标记为 `无效` 的对象，二检、三检均可见；若对象仍有明确修正价值，应优先判定为 `退回` 而非 `无效`。

## 9. `退回` 与 `无效` 判定原则

### 总原则
- 可通过返工修正并保留训练价值的对象，优先判定为 `退回`。
- 无明显修正价值，或即使修正也不值得保留的对象，判定为 `无效`。
- 选择 `无效` 时必须填写无效原因；不能仅为加快流转而将本可修正对象直接判为 `无效`。

### 典型场景
| 场景 | 建议裁决 | 说明 |
|------|----------|------|
| 类别标错，但可明确改正 | `退回` | 具备明确修正路径，返工后仍有保留价值 |
| 框、多边形或关键点标注错误，但目标清楚可修 | `退回` | 对象本身可用，应优先返工修正 |
| 重复标注，且其中一个对象明显劣于另一个更优对象 | `无效` | 劣质重复对象无单独保留价值 |
| 属性漏填、属性错填，但主体对象可用 | `退回` | 主体对象仍有训练价值 |
| 目标模糊、遮挡严重，难以形成稳定标注 | `无效` | 即使返工也缺乏稳定可用结果 |
| 明显误标到背景噪声或非目标区域 | `无效` | 对象本身不应存在 |
| 已被更优对象完整替代 | `无效` | 被替代对象无继续修正必要 |
| 当前看不清，且更换人员后大概率仍无法稳定判断 | `无效` | 缺乏有效返工价值 |

## 10. 理由必填规则

| 场景 | 必填内容 |
|------|----------|
| 任一轮将对象裁决为 `无效` | 无效原因 |
| 分数大于或等于阈值，但裁决为 `退回` | 退回理由 |
| 分数低于阈值，但裁决为一检/二检 `通过` | 通过理由 |
| 分数低于阈值，但三检裁决为 `入池` | 入池理由 |
| 三检将二检 `通过` 对象改判为 `无效` | 无效原因 |
| 三检不同意前序 `无效`，并改判为 `退回` | 退回理由 |

## 11. 对象级与图片级范围

| 规则 | 说明 |
|------|------|
| `退回` 统一按对象级定义 | 图片不单独定义 `退回` 结果；只要存在 `退回` 对象，图片级主任务进入等待返工状态 |
| `不入池` 只作为图片级终局状态 | 不定义对象级 `不入池` |
| `无效` 只作为对象级裁决 | 不定义图片级 `无效` |
| 对象级 `入池` 与图片级 `入池` 含义不同 | 对象级 `入池` 表示对象进入最终结果；图片级 `入池` 表示整图进入数据池，两者相关但不等同 |
| 所有评分均为对象级评分 | 不定义图片级总分，也不按整次任务给单一总分 |
