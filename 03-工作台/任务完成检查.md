# 任务完成检查

## 文档定位
- 本文件用于每轮产品设计、PRD、原型或模板任务结束前的固定验收。
- 本文件是 AI 自查与人工复核共用的任务收尾检查清单，暂不引入脚本、CI 或自动化检查。
- 如检查发现影响范围未同步，应继续补齐后再结束任务。

## 通用检查项
| 检查项 | 判断问题 |
|--------|----------|
| PRD 影响 | 修改 PRD 后，是否影响 HTML 原型或 Excel 模板 |
| 字段影响 | 修改字段后，是否影响列表、详情、新增、编辑、导入、导出 |
| 流程影响 | 修改业务流程后，是否同步 `00-项目总览/业务流程.mmd` |
| 原型影响 | 修改后台原型后，是否复用公共组件 |
| 模板影响 | 修改导入规则后，是否同步模板文件和填写说明 |
| 主定义沉淀 | 稳定结论是否已拆回正式 PRD |
| 过程文档边界 | 过程文档是否仍重复承载主定义 |
| 决策归档 | 产品决策变更是否进入 `90-归档记录` |
| 交叉引用 | 文档交叉引用是否仍有效 |
| 中间判断 | 复杂任务是否保留背景、取舍、评审意见和修订原因 |
| 沟通落地 | 本轮讨论产生的结论、取舍、待确认项是否已进入过程文档 |
| 拆回清单 | 稳定结论是否有主定义文档、影响资产、状态和备注 |
| 状态闭环 | 是否还存在已确认但未标记待拆回或已拆回的结论 |

## 收尾要求
- 若只修改过程性沟通内容，应确认是否已经标明待确认项或拆分待办。
- 若修改正式主定义，应确认其他文档只引用或补差异，不重复完整定义。
- 若本轮任务涉及明显取舍或反复修订，应确认关键判断已写入当前需求沟通文档、评审记录或归档记录。
- 若最终规则已拆回正式 PRD，过程文档只保留摘要和链接。
- 若本轮修改来自需求沟通，必须确认相关内容已写入当前需求沟通文档或评审记录。
- 若结论已稳定，必须更新“拆回正式文档清单”。
- 若状态为 `已拆回`，必须保留正式主定义文档链接。
- 若状态为 `待确认` 或 `待拆回`，任务收尾说明必须点明后续动作。
- 若发现本轮任务产生新的通用规则，应优先沉淀到对应目录 README 或专项规则文档，不继续扩大 `AGENTS.md`。
- 可运行 `python 06-工具脚本/check_docs.py` 做基础机械检查；脚本用于发现明显结构问题，不替代 AI 自查与人工复核。

## Throughput 处理规则
- 结构性问题优先小步快修：断链、旧术语、目录缺失、AGENTS 路由缺失等，修改后立即运行 `python 06-工具脚本/check_docs.py`。
- 脚本 `ERROR` 必须修复后再结束任务。
- 脚本 `WARN` 可保留，但任务收尾说明必须交代原因和后续处理建议。
- 涉及业务取舍、产品范围、权限规则、法规匹配、页面交互的变化，不允许仅靠脚本通过，仍需评审或用户确认。
- 每次变更尽量小步处理：一次只解决一个明确结构问题或一个明确产品问题，避免大范围混合修改。
