# 页面架构文档

## 文档定位
- 本文档用于沟通“单个页面的需求架构应该怎么写”，作为页面需求讨论的统一骨架。
- 本文档不是正式业务主定义，不直接替代模块 PRD 或页面 PRD。
- 页面规则确认后，应拆回对应 PRD；本文档只保留页面级需求架构方法和沟通模板。

## 适用范围
- 新页面需求沟通
- 现有页面重构或补规则
- 页面 PRD 结构统一
- 原型与 PRD 对齐前的页面级结构澄清

## 页面架构目标
- 让研发看到单个页面时，能在需求层面直接理解页面要做什么。
- 减少“字段有了但规则不清”“页面画了但状态和异常没定义”的歧义。
- 为后续 PRD、原型、检查脚本提供统一页面骨架。

## 单页面标准结构

### 1. 页面基本信息
- 页面名称
- 所属模块
- 导航层级 / 页面归属路径
- 页面目标

### 2. 页面入口
- 从哪里进入
- 由哪个菜单、按钮、行内操作或上游页面触发
- 与其他页面的跳转关系
- 这里只写主页面入口，不写弹窗 / 抽屉触发入口；弹窗 / 抽屉入口统一放在“页面弹窗 / 抽屉”章节单独说明
- 若存在多个入口，但最终进入的是同一个页面态，则仍只写一套单页面需求，不因入口不同重复定义页面

### 3. ASCII 草图
- 主页面草图
- 这里只承载独立页面本体的草图
- 弹窗 / 抽屉草图放在“页面弹窗 / 抽屉”章节单独定义
- 其他状态下的差异草图，放在对应状态或对应弹窗章节中说明，不混在主页面草图里

### 4. 页面状态
- 空状态
- 有数据状态
- 加载状态
- 这里只写页面本体的正常展示状态，不写无权限、操作失败结果、异常提示或 Toast 反馈

### 5. 字段与展示规则
按页面场景拆分定义，只写当前页面实际存在的字段块，不要求每页都包含全部子类：
- 筛选字段
- 列表字段
- 详情字段
- 新增/编辑字段
- 同名字段允许在不同区域分别描述，但字段含义、数据来源和核心业务口径必须保持一致；各区域只写本区域特有差异

每个字段至少应说明：
- 字段名
- 控件类型 / 展示方式
- 是否必填
- 默认值
- 数据来源
- 展示规则 / 编辑规则
- 字段级校验约束
- 空值表现

### 6. 操作规则
- 优先按动作写，不按页面区域写；每个动作需标注所属区域，如筛选区、列表区、底部操作区、弹窗 / 抽屉
- 查询
- 重置
- 新增
- 编辑
- 删除 / 停用 / 启用
- 导出
- 保存 / 提交

每个操作至少说明：
- 触发条件
- 执行动作
- 作用对象 / 作用范围
- 操作前 / 操作中 / 操作后的校验规则
- 涉及的状态变化
- 状态变化后的页面和数据表现
- 完成后的页面去向 / 刷新策略
- 结果反馈
- 是否影响其他区域或下游数据

### 7. 异常与边界
- 只记录页面级必须单独说明的关键异常，不重复字段校验和操作校验里已经明确的内容
- 不写字段必填失败、格式失败、保存阻断、删除阻断、状态不允许操作等动作级阻断，这些统一进入“操作规则”
- 优先关注：
  - 空状态
  - 加载失败
  - 无权限

每个关键异常至少说明：
- 触发条件
- 页面表现 / 提示文案
- 后续动作

### 8. 页面弹窗 / 抽屉
- 页面可能同时包含多个弹窗、抽屉、二次确认框，不得合并成一个模糊的“弹窗需求”。
- 页面本体结构、字段、状态、操作、校验和异常明确后，再逐个展开相关弹窗 / 抽屉需求。
- 应先列出弹窗 / 抽屉清单，再逐个说明。
- 每个弹窗 / 抽屉本质上都是独立页面需求架构下的子功能描述，需求结构应尽量与单页面架构一致，只做弹窗化裁剪。
- 弹窗 / 抽屉至少分两类：
  - 操作类弹窗 / 抽屉：新增、编辑、选择、详情、配置等，按完整子结构展开
  - 确认类弹窗：删除确认、提交确认、风险提示确认等，允许使用简版结构
- 操作类弹窗 / 抽屉建议按以下子结构展开：
  - 基本信息：名称、用途、适用状态
  - 触发入口：由哪个按钮、行内操作、状态或业务条件触发
  - 草图：弹窗 / 抽屉自己的结构草图
  - 字段与展示规则：包含哪些字段、默认值、只读/可编辑规则、字段级校验约束
  - 操作规则：确认、取消、关闭、保存、删除、提交等按钮及其行为，以及操作触发后的状态变化和结果反馈
  - 异常与边界：该弹窗特有的空态、加载失败、关闭中断、不可操作等情况
  - 权限相关行为：是否受按钮权限、页面权限或数据范围限制
  - 数据联动：与主页面列表、详情、分页、筛选条件、状态刷新之间的关系
- 确认类弹窗建议按以下简版结构展开：
  - 触发入口
  - 触发条件 / 阻断条件
  - 提示文案
  - 按钮
  - 结果反馈
- 若确认类弹窗还包含对象摘要、影响范围说明或风险提示差异，可在简版结构上追加对应展示规则
- 只有主页面独有的章节，如页面导航层级、整页入口背景，不必在每个弹窗里重复展开。

推荐写法：
- 先列“弹窗 / 抽屉清单”，明确本页面一共有几个弹窗 / 抽屉
- 若有多个弹窗 / 抽屉，必须按序号逐个往下展开，不得跳写或合并描述
- 例如：
  - 弹窗 / 抽屉清单
    - 弹窗1：新增项目弹窗
    - 弹窗2：删除确认弹窗
    - 抽屉1：项目详情抽屉
  - 下面依次展开：
    - 弹窗1 的完整需求结构
    - 弹窗2 的完整需求结构
    - 抽屉1 的完整需求结构

### 9. 权限相关行为
- 是否需要页面访问权限
- 无页面权限时如何表现
- 无操作权限时按钮如何表现
- 数据范围是否受权限控制
- 这里只写页面表现，不写角色权限矩阵、页面权限矩阵或权限来源逻辑展开
- 具体角色、页面、操作和数据范围权限统一引用 [../02-PRD文档/后台管理/系统管理.md](../02-PRD文档/后台管理/系统管理.md)

### 10. 模块衔接
- 当前页面依赖谁：上游数据、入口页面、前置条件
- 当前页面影响谁：下游页面、模板、导出、流程图或统计口径
- 这里只回答直接依赖谁 / 直接影响谁，不扩成二级、三级泛化说明区

### 11. 暂缓 / 待研发确认项
- 已经识别并完成产品判断，但本轮暂不落地的内容
- 需要研发补充确认实现边界、数据约束或交互可行性的内容
- 不用于承载产品方案本身尚未定稿的问题

### 12. 待确认问题清单
- 只保留产品方案本身仍未确认、需要继续沟通后才能进入正式定义的项
- 只保留真正阻碍正式定义的未决问题，不作为文末补漏区
- 若某个未决问题会直接影响字段、操作、状态或权限，对应章节必须显式标注“受第 X 条待确认问题影响”
- 已确认内容必须回写到对应正式章节

## 硬边界
- 页面不完整维护角色权限矩阵、页面权限矩阵或操作权限矩阵。
- 角色到页面 / 操作 / 数据范围权限，以 [../02-PRD文档/后台管理/系统管理.md](../02-PRD文档/后台管理/系统管理.md) 为主定义。
- 页面级需求必须把字段、状态、操作、异常写成明确章节，不只散落在自然语言中。
- `页面状态` 只写正常展示状态；无权限、操作失败、阻断和提示反馈不进入本节。
- `字段与展示规则` 只写当前页面实际存在的字段块，不为了套模板强行补齐不存在的区域。
- 同名字段可以分区域分别写，但字段含义、数据来源和核心业务口径必须一致。
- `异常与边界` 只写页面级关键异常；字段失败和动作阻断进入 `操作规则`。
- `模块衔接` 只写直接依赖关系和直接影响关系，不写泛化背景说明。
- 本文档是页面需求骨架，不直接代替正式 PRD 页面定义。

## 推荐使用方式
1. 先按本结构讨论单个页面需求。
2. 讨论中确认“页面目标、核心操作、关键待确认项”。
3. 结构稳定后，再拆回模块 PRD 对应页面章节。
4. 若是高频页面类型，可进一步沉淀为页面级模板。

## 页面架构骨架模板

```md
## 页面名称

### 1. 页面基本信息

### 2. 页面入口

### 5. 字段与展示规则

### 6. 操作规则

### 7. 异常与边界

### 8. 页面弹窗 / 抽屉

### 9. 权限相关行为

### 10. 模块衔接

### 11. 暂缓 / 待研发确认项

### 12. 待确认问题清单
```
