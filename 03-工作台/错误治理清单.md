# 错误治理清单

## 文档定位
- 仓库”错误不再重复”的统一登记入口，只记录已抽象为可复用治理动作的错误类型。
- 历史案例、决策原因和上下文归档至 [../90-归档记录/](../90-归档记录/)。

## 使用规则
- 同类错误首次出现后，登记到本清单并决定沉淀到 `Guide / Golden Path / Sensor / Ratchet` 的哪一层。
- 同类错误再次出现时，必须升级治理动作（规则→模板→脚本检查），不能只口头纠正。
- 已登记错误同时用于后续同类任务的编辑前避错检查：先按”编辑前必查信号”和”默认处理动作”自检，再落笔。
- 本文档”状态”仅表示治理动作推进情况，不替代业务主定义状态。

## 状态说明
| 状态 | 含义 |
|---|---|
| 仅记录 | 已识别错误类型，但还没有形成稳定治理动作 |
| 已加规则 | 已进入 README / 协议 / 清单 |
| 已加模板 | 已提供默认骨架、模板或起手路径 |
| 已加检查 | 已进入脚本传感器 |
| 已闭环 | 规则、默认路径和检查器至少覆盖到当前主要风险 |

## 默认升级顺序
1. 首次出现：登记错误类型，补最小正确规则。
2. 再次出现：对高频场景补模板、骨架或默认起手路径。
3. 三次以上或明显高频：补脚本检查，转成可见背压。
4. 仍无法稳定避免：补评审强关口或人工确认门。

## 本轮优先覆盖面
- 文档治理：主定义漂移、拆回不完整、收尾未闭环
- 原型实现：公共组件未复用、私有平行实现、未接入共享脚本
- 需求沟通：未先评审、未沉淀待确认项、错误未制度化
