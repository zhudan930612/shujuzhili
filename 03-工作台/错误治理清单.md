# 错误治理清单

## 文档定位
- 本文档是仓库内“错误不再重复”的统一登记入口。
- 只记录已经抽象成可复用治理动作的错误类型，不写长篇过程叙事。
- 历史案例、原始决策原因和具体上下文仍归档到 [../90-归档记录/](../90-归档记录/)。

## 使用规则
- 同类错误第一次被指出后，必须登记到本清单，并决定先沉淀到 `Guide / Golden Path / Sensor / Ratchet` 的哪一层。
- 若同类错误再次出现，不能只口头纠正；必须升级治理动作，例如从规则升级到模板、从模板升级到脚本检查。
- 已登记错误不仅用于事后升级，也必须用于后续同类任务的编辑前避错检查；命中同类场景时，应先按清单里的“编辑前必查信号”和“默认处理动作”自检，再落笔修改。
- 本文档中的“状态”只用于表示治理动作的推进情况，不替代业务主定义状态。

## 状态说明
| 状态 | 含义 |
|---|---|
| 仅记录 | 已识别错误类型，但还没有形成稳定治理动作 |
| 已加规则 | 已进入 README / 协议 / 清单 |
| 已加模板 | 已提供默认骨架、模板或起手路径 |
| 已加检查 | 已进入脚本传感器 |
| 已闭环 | 规则、默认路径和检查器至少覆盖到当前主要风险 |

## 默认升级顺序
1. 第一次出现：登记错误类型，并补最小正确规则。
2. 第二次出现：为高频场景补模板、骨架或默认起手路径。
3. 第三次出现或明显高频：补脚本检查，转成可见背压。
4. 若仍无法稳定避免：补评审强关口或人工确认门。

## 本轮优先覆盖面
- 文档治理：主定义漂移、拆回不完整、收尾未闭环。
- 原型实现：公共组件未复用、页面私有平行实现、未接入共享脚本。
- 需求沟通：未先评审、未沉淀待确认项、错误未制度化。
