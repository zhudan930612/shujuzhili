## 当前活跃专题

### 1. 本轮需求标题
- 抽检业务功能需求沟通。

### 2. 背景诉求
- 当前标注质检主链路已收敛为标注提交、一检、二检、三检的责任链，但正式 PRD 已明确：`三检人员后续通过抽检专项考核单独承接`。
- 现阶段缺少一套独立于主质检链路之外的抽检业务能力，用于对已完成样本做质量校准、风险复核、问题追溯和专项考核。
- 本轮需求目标不是把抽检并入主流程做“第四轮质检”，而是补一套主流程完成后的独立抽检机制，优先承接以下场景：
  - 对三检人员或高风险样本做专项考核。
  - 对已入池或已结束未入池样本做质量复核。
  - 对明显异常的裁决结果做二次验证，并沉淀问题类型与改进方向。
- 本轮沟通输出先形成过程性草案，用于确认模块范围、页面拆分、业务对象、状态流和待确认问题；稳定规则后再拆回正式 PRD。

### 3. 功能与场景分析
| 功能 / 场景 | 要解决的问题 | 关联业务对象 | 主要使用对象 / 参与角色建议 | 系统需要支持的能力 | 成功状态 | 状态 |
|---|---|---|---|---|---|---|
| 发起抽检任务 | 当前缺少对已完成样本进行独立复核的任务载体 | 样本、对象、原质检链结果、抽检任务 | 质量负责人、抽检管理员 | 从已结束样本中选择候选并生成抽检任务 | 可按规则或人工发起抽检任务 | 待确认 |
| 执行抽检复核 | 当前没有独立记录抽检结论、问题标签和处理建议的位置 | 抽检任务、抽检对象、抽检结论 | 抽检人员、资深质检人员、领域工程师 | 查看原链路结果、再次复核并提交抽检结论 | 每个抽检对象都有可追溯结论 | 待确认 |
| 触发问题回流 | 抽检发现严重问题后，缺少标准化后续动作 | 抽检结论、回流动作、整改记录 | 抽检人员、质量负责人 | 根据抽检结果触发回流、培训或仅记录 | 严重问题能进入后续闭环 | 待确认 |
| 抽检考核统计 | 三检或专项人员考核缺少独立数据来源 | 抽检结论、考核周期、人员统计 | 质量负责人、管理者 | 汇总抽检准确率、问题分布和样本命中情况 | 能支撑专项考核与过程复盘 | 待确认 |

## 模块 1：抽检管理

### 模块定位
- 所属端：后台管理。
- 涉及模块：标注质检管理 / 抽检管理。
- 功能目标：为主质检链路之外的样本复核、专项考核和问题回流提供独立任务机制。
- 成功状态：抽检任务可发起、可执行、可留痕、可回流、可统计。
- 不做范围：
  - 不把抽检写成主流程第四轮。
  - 不在第一版扩展成完整的策略配置中心、自动调参中心或复杂运营看板。
  - 不替代原有一检、二检、三检责任链的主裁决逻辑。
- 拆回目标文档：`02-PRD文档/后台管理/标注质检管理.md`、`00-项目总览/业务流程.mmd`（如主流程图需补充抽检旁路说明）。

### 通用规则 / 跨页面共用规则
> 仅记录抽检管理模块内跨页面复用的规则草案。稳定后应拆回正式 PRD。

#### 业务对象规则
- `抽检任务` 是抽检的执行载体，至少包含任务编号、抽检类型、抽检范围、发起方式、发起人、执行人、任务状态和时间信息。
- `抽检对象` 是任务内实际被复核的最小业务单元，建议沿用主流程已有对象粒度，不重新创造新的评分对象。
- `抽检结论` 用于记录复核判断、问题标签、严重程度、建议动作和与原裁决的差异结果。
- `抽检问题` 建议至少区分：裁决类型错误、评分偏差过大、规则理解偏差、漏标/错标、资料异常、无需处理。

#### 状态规则
- 抽检任务建议状态：`待分配`、`待抽检`、`抽检中`、`已完成`、`已关闭`。
- 抽检对象建议状态：`待处理`、`已提交结论`、`需回流处理`、`已忽略`。
- 抽检发现的问题回流后，不改变抽检任务本身的已留痕事实；回流处理结果应作为后续关联记录回写。

#### 字段 / 编码 / 校验共用规则
- 抽检任务编号建议独立编码，避免与主质检任务编号混用。
- 发起抽检时必须明确抽检类型、抽检范围、抽检对象来源和执行人。
- 若抽检任务内存在未完成对象，则任务不可标记为 `已完成`。
- 抽检结论提交后默认不可静默覆盖；如需修正，应保留修正记录。

#### 数据沉淀与追溯规则
- 抽检必须能追溯到原始样本、对象、主质检链路责任人和原裁决结果。
- 抽检结论、问题标签、回流建议、最终处理动作应留痕，供后续专项考核和复盘使用。
- 抽检统计默认读取抽检结论聚合结果，不直接改写原始主流程评分记录。

##### 6. 操作规则

###### 发起抽检任务
- 所属区域：页面操作区。
- 触发条件：用户具备抽检任务创建权限。
- 执行动作：打开 `发起抽检任务弹窗`，选择抽检类型、范围、对象来源和执行人后生成任务。
- 作用对象 / 作用范围：符合条件的已结束样本 / 已入池样本 / 风险命中样本。
- 操作前 / 操作中 / 操作后的校验规则：必须明确任务范围和执行人；如候选对象为空则阻断创建。
- 涉及的状态变化：新任务进入 `待抽检` 或 `待分配`。
- 状态变化后的页面和数据表现：列表新增对应任务并刷新计数。
- 完成后的页面去向 / 刷新策略：关闭弹窗并刷新当前列表。
- 结果反馈：提示创建成功或失败原因。
- 是否影响其他区域或下游数据：会生成抽检任务和待处理对象。

###### 批量分配抽检人
- 所属区域：页面操作区 / 列表批量操作。
- 触发条件：选中待分配或待抽检任务。
- 执行动作：为选中任务批量指定抽检执行人。
- 作用对象 / 作用范围：所选抽检任务。
- 操作前 / 操作中 / 操作后的校验规则：已完成任务不可再次分配。
- 涉及的状态变化：`待分配` 更新为 `待抽检`。
- 状态变化后的页面和数据表现：执行人字段与状态字段更新。
- 完成后的页面去向 / 刷新策略：停留列表页并刷新数据。
- 结果反馈：提示批量分配结果。
- 是否影响其他区域或下游数据：影响任务处理责任人。

###### 查看任务详情
- 所属区域：列表操作列。
- 触发条件：点击任务编号或 `查看`。
- 执行动作：进入抽检任务详情页。
- 作用对象 / 作用范围：单个抽检任务。
- 操作前 / 操作中 / 操作后的校验规则：任务不存在或已删除时提示异常。
- 涉及的状态变化：无强制状态变化。
- 状态变化后的页面和数据表现：打开详情页并加载任务内对象。
- 完成后的页面去向 / 刷新策略：进入详情页。
- 结果反馈：正常跳转或错误提示。
- 是否影响其他区域或下游数据：无。

| 抽检范围 | 下拉单选 | 是 | 空 | 业务规则 | 建议值：已入池 / 已结束未入池 / 指定任务结果 | 必须选择 | 待确认 |
| 候选对象条件 | 多字段组合 | 否 | 空 | 主流程结果 | 仅在范围允许时展示筛选条件 | 条件组合口径待确认 | 待确认 |
| 执行人 | 选择器 | 是 | 空 | 用户中心 | 支持单人或多人分配待确认 | 至少选择 1 人 | 待确认 |
| 任务说明 | 多行文本 | 否 | 空 | 人工录入 | 用于补充本次抽检目的 | 长度限制待确认 | 待确认 |

**操作规则**
- `确认创建`：
  - 提交前校验：必填项完整，且候选对象数大于 0。
  - 成功结果：生成抽检任务并返回列表。
  - 失败结果：保留已填内容并提示失败原因。
  - 状态：待确认。

**异常与边界**
- 若按当前条件筛不到候选对象，则不允许创建任务。

**数据联动**
- 创建成功后向任务主表和任务对象表写入记录。

###### 弹窗 / 抽屉 2：批量分配抽检人弹窗

**基本信息**
- 名称：批量分配抽检人弹窗。
- 用途：为多个抽检任务统一指定执行人。
- 适用状态：选中多个任务时。

**触发入口**
- 点击 `批量分配抽检人`。

**字段与展示规则**
| 字段 | 展示方式 | 是否必填 | 默认值 | 数据来源 | 展示 / 编辑规则 | 字段级校验约束 | 状态 |
|---|---|---|---|---|---|---|---|
| 执行人 | 选择器 | 是 | 空 | 用户中心 | 建议只允许选择具备抽检权限人员 | 必选 | 待确认 |
| 说明 | 多行文本 | 否 | 空 | 人工录入 | 可补充分配原因 | 长度限制待确认 | 待确认 |

**操作规则**
- `确认分配`：
  - 提交前校验：至少选中 1 个可分配任务。
  - 成功结果：更新选中任务执行人。
  - 失败结果：提示不可分配原因。
  - 状态：待确认。

**异常与边界**
- 已完成、已关闭任务不可重新分配。

**数据联动**
- 更新任务执行人及最近更新时间。

##### 6. 操作规则

###### 提交抽检结论
- 所属区域：详情区操作按钮。
- 触发条件：当前对象处于 `待处理` 或允许重新编辑状态。
- 执行动作：打开 `提交抽检结论弹窗`，填写结论、问题标签、严重程度和建议动作。
- 作用对象 / 作用范围：当前抽检对象。
- 操作前 / 操作中 / 操作后的校验规则：必须选择抽检结论；触发回流时必须补充原因。
- 涉及的状态变化：对象从 `待处理` 变为 `已提交结论` 或 `需回流处理`。
- 状态变化后的页面和数据表现：左侧对象状态刷新，任务完成进度更新。
- 完成后的页面去向 / 刷新策略：停留当前页面并刷新当前对象数据。
- 结果反馈：提示提交成功或失败原因。
- 是否影响其他区域或下游数据：写入抽检结论和回流建议。

###### 标记问题回流
- 所属区域：详情区操作按钮。
- 触发条件：抽检判断存在严重问题，需进入后续处理。
- 执行动作：打开 `抽检问题回流确认弹窗`，确认回流对象、原因和建议动作。
- 作用对象 / 作用范围：当前抽检对象及其关联责任链。
- 操作前 / 操作中 / 操作后的校验规则：必须明确回流原因和回流去向。
- 涉及的状态变化：对象标记为 `需回流处理`。
- 状态变化后的页面和数据表现：对象状态与任务待处理计数变化。
- 完成后的页面去向 / 刷新策略：停留详情页并更新状态。
- 结果反馈：提示已标记回流。
- 是否影响其他区域或下游数据：会进入后续返工、复盘或专项处理流程。

###### 完成任务
- 所属区域：页面顶部操作区。
- 触发条件：当前任务下所有对象都已提交结论或明确忽略。
- 执行动作：将任务标记为 `已完成`。
- 作用对象 / 作用范围：当前抽检任务。
- 操作前 / 操作中 / 操作后的校验规则：存在待处理对象时阻断完成。
- 涉及的状态变化：任务状态改为 `已完成`。
- 状态变化后的页面和数据表现：任务进度 100%，列表页状态同步更新。
- 完成后的页面去向 / 刷新策略：可返回列表页或停留当前页。
- 结果反馈：提示任务完成。
- 是否影响其他区域或下游数据：使该任务进入统计范围。
