## 需求沟通专题：行政区域层级与辖区权限

### 背景诉求
- 后续平台可能在不同省、市、区开展业务，当前项目、巡查、法规库尚未形成统一行政区域或辖区管理口径。
- 业务上存在“巡查人员只能看到自己辖区内项目数据”的诉求，同时不同地区可能存在不同法规、标准或监管要求。
- 本专题处于需求沟通阶段；当前已确认先只涉及后台管理系统，结论稳定后再拆回项目管理、巡查员账号、后台巡查管理、法规库和法规匹配相关正式文档。

### 增加行政区域划分的原因
- 支撑跨地区业务开展：项目后续会分布在不同省、市、区，如果缺少行政区域归属，后台项目、巡查记录和法规数据会混在同一数据池，难以按地区管理。
- 支撑辖区数据权限：巡查员账号需要按负责辖区查看项目和巡查数据，行政区域是判断“哪些项目属于该账号可见范围”的基础条件。
- 支撑地方化法规引用：不同地区可能有本地安全监管要求或地方标准，法规库需要用适用地区区分全国通用法规与地方适用法规。
- 支撑后台查询与运营统计：项目管理、后台巡查管理和法规库都需要按地区筛选，便于运营人员按区域排查数据、统计工作量和发现缺口。
- 降低后续返工风险：先建立项目属地、账号辖区、法规适用地区的统一口径，后续扩展移动端、报表或跨区协作时可复用，不需要重新改造底层规则。

### 业务场景与需求
| 场景 | 业务描述 | 对应需求 |
|------|----------|----------|
| 多地区开展业务 | 平台后续可能在不同省、市、区开展安责险事故预防服务 | 平台需要识别项目所属行政区域，避免所有项目混在全局项目池 |
| 项目来自不同备案系统 | 不同地区可能有自己的备案系统或项目来源口径 | 项目主数据需要记录项目属地、来源系统和同步来源，便于追溯 |
| 巡查员只负责指定辖区 | 巡查员只负责某个区或多个区的项目 | 巡查员账号需要绑定可见辖区，后台项目选择与数据查看按辖区过滤 |
| 区级/市级管理人员查看辖区数据 | 区级管理员看本区，市级管理员看全市 | 后台需要支持区域级数据权限 |
| 平台运营查看全量数据 | 平台管理员或总部运营需要跨区域查看、统计和配置 | 需要保留全局管理员权限 |
| 巡查记录按项目归属隔离 | 巡查记录是项目产生的数据 | 巡查记录默认从项目继承区域权限，不单独维护区域 |
| 后台上传巡查记录 | 后台人员手动上传巡查记录时选择项目 | 上传页选择项目范围需要按当前账号可见辖区过滤 |
| 巡查记录详情纠错 | 详情页编辑关联项目时可能改到其他项目 | 编辑态项目选择范围同样受辖区权限限制 |
| 后续移动端扫码进入项目 | 巡查员可能通过二维码或项目编号进入项目 | 移动端后续单独评估，扫码或搜索后仍需校验项目是否在账号可见辖区内 |
| 跨区临时支援 | 巡查员临时支援其他区项目 | 账号需要支持绑定多个辖区；临时授权可后续扩展 |
| 法规存在地方差异 | 不同省、市、区可能有不同地方标准或监管要求 | 法规库需要增加适用地区，支持全国、省、市、区等层级 |
| 隐患识别/报告引用法规 | 同一隐患在不同地区可能引用不同法规依据 | 法规匹配应优先匹配项目所在地法规，再回退上级或全国法规 |
| 统计分析按区域汇总 | 管理层需要看各区项目数、巡查完成率和隐患量 | 报表和列表筛选需要支持行政区域维度 |
| 数据迁移和历史数据 | 现有项目可能没有区域字段 | 需要定义历史项目区域补录或默认归属规则 |
| 区域调整 | 行政区划或业务辖区可能变化 | 区域字典需要启停、层级维护，被引用后不能随意删除 |
| 保险公司/服务机构分工 | 部分数据可能还要按保险公司或服务机构隔离 | 权限模型需预留“区域 + 机构”的组合能力 |

### 需求拆分
| 需求类别 | 核心需求 | 说明 |
|----------|----------|------|
| 区域基础数据 | 建立统一行政区域字典 | 作为项目、账号、法规共同引用的唯一来源 |
| 项目属地 | 项目新增、导入、同步时记录所属行政区域 | 项目是区域权限和法规匹配的基础 |
| 数据权限 | 用户绑定可见辖区，后台列表、后台搜索、后台选择项目都按权限过滤 | 解决巡查人员只能看到自己辖区项目的核心诉求 |
| 法规适用 | 法规库增加适用地区 | 解决不同省、市、区法规要求不同的问题 |

### 行政区域层级口径
- 本阶段项目行政区域采用 `省 / 市 / 区县 / 街镇 / 社区` 五级结构；项目批量导入、新增和编辑至少必须维护到第四级 `街镇`，第五级 `社区` 可按实际数据补充。
- 项目行政区域未达到 `街镇` 层级时，不允许导入或保存；若行政区域字典中某区县下缺少街镇数据，应先补齐基础字典或作为异常数据处理，不再按区县直接视为有效最终层级。
- 巡查员账号的可见辖区、后台巡查管理的区域筛选与项目行政区域保持一致，一级包含 `全国`；其中巡查员服务区域支持继续选择到社区，法规库适用地区只到区县一级。

### 项目管理功能设计沟通

#### 行政区域字段位置
- 新增项目弹窗中，`行政区域` 放在 `项目地址` 后方展示。
- 推荐录入顺序为：`项目名称 → 施工类型 → 项目地址 → 行政区域 → 施工时间 → 关联保险公司 → 施工单位 → 负责人姓名/电话 → 备注`。
- 原因：项目地址与行政区域都属于项目基础归属信息；行政区域放在项目地址之后，便于录入人员先确认地址，再选择或核对标准行政区域。

#### 项目地址与行政区域生成规则
| 场景 | 规则 |
|------|------|
| 批量导入项目 | 模板中显式填写 `省`、`市`、`区县`、`街镇`、`社区` 五个行政区域字段；其中 `省`、`市`、`区县`、`街镇` 必填，`社区` 可选 |
| 新增项目 | 用户手动选择行政区域，至少必须选择到 `街镇`；如已有社区数据，可继续选择到社区 |
| 编辑项目 | 项目地址沿用现有规则保持只读；行政区域允许修改，至少必须选择到 `街镇` |
| 层级校验 | `街镇` 有值时 `省`、`市`、`区县` 必填；`社区` 有值时 `省`、`市`、`区县`、`街镇` 必填 |
| 字典校验 | 填写或选择的行政区域必须能匹配统一行政区域字典，且上下级关系必须一致 |
| 保存校验 | 新增、编辑项目保存时必须至少选择到 `街镇`；未达到第四级时不允许保存，并提示”行政区域必须至少选择到街镇层级” |

#### 初步规则
- `项目地址` 仍为必填字段。
- 批量导入模板新增行政区域字段，按 `省`、`市`、`区县`、`街镇`、`社区` 五列拆分填写。
- `省`、`市`、`区县`、`街镇` 为批量导入必填字段；`社区` 为选填字段。
- 导入时不再依赖 `项目地址` 自动解析行政区域；系统仅使用 `项目地址` 作为详细地址字段，使用五个行政区域列作为项目标准属地来源。
- 导入预览必须展示合并后的行政区域完整路径，并展示行政区域校验结果。
- 行政区域层级未达到 `街镇`、层级跳填、上下级关系不匹配、无法匹配行政区域字典时，均作为错误行处理，不能导入。
- 新增项目和编辑项目时，用户可手动调整行政区域；保存时必须至少选择到 `街镇`，社区可选。
- 项目管理列表页仅增加行政区域筛选条件，不在列表字段中新增行政区域列。
- 项目详情页需要展示项目所属行政区域。
- 项目编辑态允许修改行政区域，项目地址仍按现有规则保持只读。
- 项目行政区域修改后，按项目最新归属影响后续筛选、权限过滤和法规匹配。

#### 地址解析说明
- 项目批量导入主流程不采用地址解析生成行政区域，避免解析不完整导致项目进入下游业务时出现权限、巡查关联和法规匹配歧义。
- 后续如需引入地址解析能力，仅作为新增/编辑时的辅助填充能力，最终仍以用户选择或模板填写并通过行政区域字典校验后的标准区域编码为准。

### 巡查员账号功能设计沟通

#### 服务区域字段口径
- 当前系统巡查员账号中已存在 `服务区域` 字段，后续复用该字段承接可见辖区配置，不新增平行字段。
- 文档口径：`服务区域 = 巡查员可见辖区 = 后台数据权限范围`。
- `服务区域` 继续复用现有级联多选组件，一级包含 `全国`，并支持按行政区域层级继续选择到社区。

#### 服务区域选择规则
| 规则项 | 说明 |
|--------|------|
| 是否必填 | 巡查员账号必填 |
| 选择方式 | 级联多选 |
| 支持层级 | 全国 / 省 / 市 / 区县 / 街镇 / 社区 |
| 全国选项 | `全国` 与各省/直辖市同属一级选项，不作为各省/直辖市的父级 |
| 选择上级区域 | 选择省、市、区县等上级区域时，默认包含其下级区域 |
| 多区域配置 | 支持一个巡查员绑定多个服务区域 |
| 街镇/社区数据 | 项目导入至少要求到街镇；社区为第五级选填层级，区域数据补齐后继续沿用同一字段 |

#### 数据权限生效范围
| 应用位置 | 权限规则 |
|----------|----------|
| 项目管理 | 巡查员仅能查看服务区域内的项目 |
| 后台上传巡查记录 | 选择项目时，仅展示当前账号服务区域内的项目 |
| 后台巡查记录列表 | 仅展示服务区域内项目产生的巡查记录 |
| 巡查记录详情 | 巡查记录所属项目不在服务区域内时，不允许查看 |

#### 后续同步提醒
- 后续同步原型和 PRD 时，需检查巡查员账号新增/编辑弹窗中的 `所属单位` placeholder 是否存在复用错误；当前参考图中疑似显示为“请输入巡检人员名称”，应按字段语义修正。

#### 权限与项目选择规则
- 巡查记录列表默认只展示当前账号服务区域内项目产生的巡查记录。
- 行政区域筛选项应按当前账号服务区域裁剪；普通账号只能筛选自己服务区域内的区域，平台管理员可全量筛选。
- 上传巡查记录页搜索/选择项目时，只展示当前账号服务区域内的项目。
- 巡查记录详情页编辑态修改关联项目时，只允许选择当前账号服务区域内的项目。

### 法规库功能设计沟通

#### 适用地区字段口径
- 法规库增加 `适用地区` 字段，用于表达法规条款适用于哪些行政区域。
- `适用地区` 是法规匹配和筛选字段，不作为账号数据权限字段。
- 适用地区默认值为 `全国`。
- 适用地区支持选择全国、省、市、区县任一层级，不支持街镇。
- 适用地区使用省 / 市 / 区县三级联动下拉控件；在三级下拉中，省、市、区县任一层级均可直接选中并保存，不强制选到区县。
- 一级下拉第一个选项固定显示 `全国`。
- `全国` 与各省/直辖市同属一级选项，不作为各省/直辖市的父级。
- 用户选择 `全国` 时，不再继续展开下级区域；用户选择省、市时，再按层级联动展示下级区域；选择到区县后停止展开。

#### 法规批量导入适用地区规则
- 法规库批量导入模板中不使用单个自由文本 `适用地区` 列，改为拆分为 `省`、`市`、`区县` 三列，导入后由系统合并展示为一个 `适用地区` 字段。
- 法规批量导入至少选择到省级；全国适用时在 `省` 列选择 `全国`，`市`、`区县` 留空。
- 仅填写 `省` 时，导入后适用地区为省级；填写 `省 + 市` 时，导入后适用地区为市级；填写 `省 + 市 + 区县` 时，导入后适用地区为区县级。
- `市` 有值时 `省` 必填；`区县` 有值时 `省`、`市` 均必填。
- 填写的省、市、区县必须能匹配统一行政区域字典，且层级关系必须一致；无法匹配、层级不连续或填写到街镇层级时，该行作为导入失败项处理。
- 法规库导入不设置 `待补充` 状态；适用地区属于法规业务属性，不能像项目导入一样由项目地址解析后再补齐。
- 法规列表页、详情页、新增/编辑弹窗仍统一展示一个合并后的 `适用地区` 字段。
- 法规唯一性校验使用合并后的标准区域编码参与判断，即 `适用行业 + 适用地区 + 法规编号 + 条款编号`。

#### 列表与详情展示
- 法规库列表页增加 `适用地区` 筛选条件。
- 法规库列表字段中新增 `适用地区` 列。
- 法规详情页展示 `适用地区`。
- 新增/编辑法规时维护 `适用地区`。

#### 编辑适用地区规则
- 编辑法规时允许修改 `适用地区`。
- `适用地区` 变更后，仅影响后续法规匹配和新生成报告；历史已生成报告不自动更新。
- 已关联隐患的关联关系保留，后续匹配时按新的适用地区生效。
- 保存时不做二次确认，按普通编辑保存流程提交。

#### 编辑态法规类型勘误
- 法规类型参与条款编码生成，条款编码创建后不可修改，因此编辑法规时 `法规类型` 不允许修改。
- 编辑法规弹窗应只读展示 `条款编码`、`适用行业`、`法规编号`、`法规类型`，仅允许修改法规名称、适用地区、条款编号、条款内容、状态、备注等非编码结构字段。
- 复制法规属于新建记录，允许调整法规类型，保存后由系统重新生成新的条款编码。

### 法规匹配功能设计沟通

#### 报告/识别结果默认匹配规则
- 法规匹配依据为：`项目所属行政区域 + 隐患关联法规 + 法规适用地区`。
- 项目行政区域以项目最新所属行政区域为准。
- 法规适用地区以法规库当前启用法规的适用地区为准。
- 默认匹配按法规适用地区层级分层全部展示，优先级为：`区县 > 市 > 省 > 全国`。
- 同一层级命中多条法规时，全部展示。
- 不匹配项目所属行政区域路径的其他地区法规，默认不展示。
- 停用法规不参与后续新匹配。
- 已生成报告不因后续法规适用地区调整而自动更新。

#### 分层展示示例
```text
项目：广东省 / 深圳市 / 南山区 / 粤海街道
隐患：临边防护缺失

默认展示：
1. 南山区适用法规
2. 深圳市适用法规
3. 广东省适用法规
4. 全国适用法规

默认不展示：
- 福田区适用法规
- 广州市适用法规
```

#### 人工选择其他适用地区
- 默认按项目所属行政区域路径分层展示法规，但用户可以切换或选择其他适用地区查看法规候选。
- 选择其他适用地区后，仅改变当前法规候选展示范围，不修改项目所属行政区域。
- 用户从其他适用地区选择法规时，应记录为人工选择结果，优先于默认匹配结果。
- 人工选择结果仅作用于当前业务结果或当前报告生成，不反向修改法规库适用地区。

#### 隐患点关联法规弹窗规则
- 隐患点关联法规发生在知识库维护场景中，隐患点本身没有项目地址或项目行政区域，不能根据项目行政区域默认筛选法规。
- 一个隐患点可以同时关联多个不同适用地区的法规；地区差异通过法规的适用地区区分，不需要为每个地区单独创建一个隐患点。
- 关联法规弹窗只增加 `适用地区` 筛选条件和候选法规列表中的 `适用地区` 字段。
- `适用地区` 筛选默认值为 `全部` 或不选中具体地区，由用户手动选择适用地区查看法规候选。
- 切换适用地区只影响弹窗候选法规，不修改法规库中法规的适用地区。
- 项目行政区域驱动的法规适用地区匹配仅用于报告生成、识别结果展示等存在具体项目上下文的场景，不用于隐患点知识库维护时的关联法规弹窗默认筛选。
- 项目维度仅在报告/识别结果生成时，从该隐患点已关联法规中按项目行政区域筛选适用法规。
