### 取舍与评审
- 推荐优先级：先做“标注任务与质检闭环”，而不是继续补周边管理功能。

| 候选方向 | 价值 | 当前问题 | 建议 |
|---|---|---|---|
| 标注任务与质检闭环 | 直接承接平台核心价值，决定照片能否变成训练数据 | 当前只有流程节点，没有任务分配、标注结果、质检裁决、驳回回流、待确认处理的页面规则 | 第一优先级 |
| 数据集/高质量数据池管理 | 承接 S6 和 AI 训练侧使用 | 依赖标注和质检结果，过早设计容易空转 | 第二优先级，跟在标注质检之后 |
| 报告生成/导出 | 更贴近保险公司交付 | 当前平台定位不是先做报告交付，且法规匹配、隐患识别结果尚未闭环 | 暂缓 |
| 行政区域字典后台维护 | 补强当前区域权限专题 | 系统管理已明确当前不新增独立行政区域管理页面，先按基础数据维护 | 暂缓，除非区域数据来源无法保障 |
| 隐患案例库页面 | 丰富知识库 | 知识库 PRD 已明确当前暂不展开案例库列表、录入、详情、导入页面 | 暂缓 |

- 评审意见：
  - 继续做采集前置功能的边际收益已经下降；真正卡住平台闭环的是采集后的治理处理。
  - 如果没有标注/质检模块，当前“数据治理平台”容易停在“项目与图片管理系统”，无法证明高质量数据池成立。
  - 标注质检必须与知识库回流一起设计；在新口径下，回流对象需要从“新隐患 / 规则缺失”扩展为“新物品类别 / 安全要素类别缺失 / 隐患规则缺失”。
  - 不建议先做 AI 训练或报告生成；训练侧需要稳定数据集，报告侧需要稳定识别结果和法规匹配结果，当前条件不足。
  - 口径变更风险：现有 [../01-产品架构/知识体系设计.md](../01-产品架构/知识体系设计.md) 与 [../02-PRD文档/后台管理/知识库管理.md](../02-PRD文档/后台管理/知识库管理.md) 当前以“隐患编码”为 AI 识别目标，若确认改为物品/安全要素标注，需要补充“物品/安全要素库”或调整知识体系层级，不能只改标注页面。

#### Q1 沟通记录：标注作业对象
- 待讨论点：
  - 第一版标注对象是否从“隐患”调整为“物品/安全要素”。
  - 物品/安全要素类别如何组织，例如安全帽、灭火器、脚手架、配电箱、防护栏、洞口盖板等。
  - 一张图片是否允许存在多个物品/安全要素标注框。
  - 是否还保留图片级“无目标/无可标注对象”结果，用于负样本或空样本沉淀。
  - 物品/安全要素标注结果如何与后续隐患判断、法规匹配和整改建议衔接。
  - 训练目标是否为目标检测模型训练，还是视觉大模型微调/样本学习。
- 初始评审：
  - 该调整有合理性：很多隐患判断依赖先识别现场对象及状态，例如先识别“安全帽”“灭火器”“脚手架”“防护栏”，再判断是否佩戴、是否缺失、是否过期、是否搭设异常。
  - 物品标注比隐患标注更接近视觉模型训练的基础任务，标注员理解成本通常低于直接判断复杂隐患，也更容易形成稳定样本。
  - 但这会改变当前知识体系：现有文档把“具体隐患编码”作为 AI 识别目标；若改为物品/安全要素标注，后续需要增加“物品/安全要素 -> 隐患规则 -> 法规/整改建议”的推理或匹配层。
  - 不能把“物品类别”直接塞进现有“隐患库”的四级具体隐患里，否则会混淆“对象是什么”和“问题是什么”两个概念。
  - “告知大模型什么是安全帽、灭火器、脚手架”需要进一步明确训练目标：是训练目标检测模型、微调视觉大模型，还是构建带框样本供后续模型评测。不同目标会影响导出格式和质量标准。
- 当前建议：
  - 第一版标注对象调整为“物品/安全要素”，不直接标注“隐患”。
  - 一张图片支持多个物品/安全要素框；每个框绑定一个物品/安全要素类别。
  - 物品/安全要素类别应独立建库或作为知识体系新增层，不与现有隐患库混放。
  - “无隐患”暂不作为标注标签；如图片中没有任何可标注物品/安全要素，记录为图片级“无可标注对象”。
  - 后续隐患判断通过“物品/安全要素识别结果 + 隐患判定规则/知识库”承接，不在本轮 Q1 中直接定义。
- 已确认结论：
  - 第一版训练目标为目标检测模型训练。
  - 标注任务需要框出物品/安全要素的位置，输出对象类别和坐标。
  - 标注对象为安全帽、灭火器、脚手架等物品/安全要素，不直接标注隐患。
  - 一张图片允许多个物品/安全要素框。
  - “无隐患”不作为标注标签；若图片无可标注物品/安全要素，记录为图片级“无可标注对象”。
  - 该结论后续需拆回知识体系与标注质检 PRD，并影响训练侧导出格式。

#### Q2 沟通记录：标注轮次与质检裁决
- 用户想法：
  - 不限制标注轮次。
  - 质检人员可以手动选择查看经过几个轮次的标注结果。
  - 质检人员基于查看结果决策是否进入高质量数据池。
- 初始评审：
  - 该思路适合目标检测训练数据治理：多轮标注可以沉淀不同人员对同一对象框和类别的判断差异，质检员再基于差异做最终裁决。
  - 相比固定 2 人或 3 人投票，可变轮次更灵活，适合早期类别标准还在校准的阶段。
  - 风险是如果完全不设流程边界，任务可能反复标注、质检成本失控，且“何时可以进入质检”不清晰。
  - 建议把“不限制轮次”理解为“业务上不固定必须几轮”，但系统仍需要记录轮次、标注人、时间、版本、标注结果和质检裁决，避免结果不可追溯。
- 当前建议：
  - 标注任务支持多轮标注，不强制固定为 2 人或 3 人。
  - 每轮标注结果独立留痕，不覆盖上一轮结果。
  - 质检工作台支持查看：最新一轮、指定轮次、全部轮次对比。
  - 质检员可选择某一轮结果作为基础进行修正，也可直接重新绘制标准结果。
  - 质检裁决结果包括：进入高质量数据池、退回继续标注、不入池。
  - 进入高质量数据池时，以质检员确认的“标准框 + 标准类别”为最终入池结果，不直接以某个标注员原始结果入池。
  - 系统应显示轮次差异，例如同一对象类别不一致、框位置偏差明显、漏框/多框，但差异算法可作为辅助，不替代质检员裁决。
- 已确认结论：
  - 标注任务支持多轮标注，不强制固定为 2 人或 3 人。
  - 每轮标注结果独立留痕，不覆盖上一轮结果。
  - 质检工作台支持查看最新一轮、指定轮次和全部轮次对比。
  - 质检员可选择某一轮结果作为基础进行修正，也可重新绘制标准结果。
  - 质检裁决结果包括：进入高质量数据池、退回继续标注、不入池。
  - 进入高质量数据池时，以质检员确认的“标准框 + 标准类别”为最终入池结果，不直接以某个标注员原始结果入池。
  - 系统可辅助显示轮次差异，例如类别不一致、框位置偏差明显、漏框/多框，但差异算法不替代质检员裁决。

#### Q3 沟通记录：质检范围与标准结果生成
- 待讨论点：
  - 质检工作台按图片组织，还是按单个对象框组织。
  - 质检员在裁决阶段是否只能选择某个标注员/某一轮的结果。
  - 质检员是否允许自行新增、修改、删除标注框，并调整对象类别。
- 初始评审：
  - 如果质检员只能选择既有标注结果，最终标准结果会被已有标注质量限制；遇到所有标注员都漏框、框偏差都较大、类别都错时，只能退回，效率低。
  - 目标检测训练需要高质量标准框，质检员应被定义为最终标准结果的责任人，而不只是投票选择人。

##### Q4A 字段及规则草案

###### 1. 列表字段

| 字段 | 展示规则 | 说明 |
|---|---|---|
| 类别名称 | 展示类别中文名称 | 如安全帽、灭火器、脚手架 |

列表不展示数据库内部编码；不展示创建人、创建时间、更新人、更新时间。

###### 2. 类别项字段

| 字段 | 必填 | 规则 | 示例 |
|---|---|---|---|
| 类别内部编码 | 数据库生成 | 全局唯一；创建后不可修改；用户端不展示、不填写；用于训练导出、历史标注映射和系统识别 | - |
| 类别名称 | 是 | 展示给领域工程师、标注员、质检员的中文名称；允许修改，但不得改变内部编码 | 安全帽、灭火器、脚手架 |

###### 3. 属性字段

| 字段 | 必填 | 规则 | 示例 |
|---|---|---|---|
| 所属类别 | 是 | 属性必须归属于一个类别；每个类别至少配置一个属性 | 安全帽 |
| 属性名称 | 是 | 类别下的可选属性；同一类别下属性名称不可重复；标注员只能从领域工程师维护的属性名称中选择，不允许自由输入 | 白色、红色、正常、损坏 |
| 属性状态 | 是 | 枚举：启用、停用；启用属性可用于新标注，停用属性仅用于历史追溯 | 启用 |

###### 4. 维护规则

| 规则项 | 规则 |
|---|---|
| 维护角色 | 仅领域工程师维护类别、属性和属性图片 |
| 类别结构 | MVP 采用平铺类别项列表，暂不做类别组 |
| 类别稳定标识 | 数据库生成内部编码，创建后不可修改；用户端不展示、不填写；如类别名称调整，内部编码仍保持不变 |
| 属性要求 | 每个类别至少配置一个属性；如果暂不需要细分，配置默认属性名称，如 `通用`、`未区分` 或 `默认` |
| 属性唯一性 | 同一类别下属性名称不可重复；不同类别下可存在相同属性名称，如安全帽/红色与警示牌/红色 |

| 属性状态 | 属性支持启用/停用；启用属性可用于新标注，停用属性仅用于历史展示和导出追溯 |
| 删除规则 | 类别和属性不允许物理删除，仅允许停用 |
| 标注可选范围 | 标注下拉只展示启用类别和启用属性 |
| 历史追溯 | 历史标注继续保留原类别内部编码和属性名称；停用后不影响历史展示与导出 |
| 待确认类别 | 标注员遇到缺失类别时选择 `待确认类别`，不直接新增正式类别 |

###### 5. 标注使用规则

| 场景 | 规则 |
|---|---|
| 正常标注 | 标注员框选对象后，必须选择类别和该类别下的属性名称 |
| 类别无可选属性 | 不允许进入标注；类别发布前必须至少配置一个启用属性 |
| 属性无法判断 | MVP 阶段可通过领域工程师配置 `未区分` 属性承接，标注员不得自由输入属性 |

| 入池要求 | 入高质量数据池的标准结果必须有正式类别和正式属性；`待确认类别` 不可直接入池 |

  - 第一版训练目标为目标检测模型训练。
  - 可导出的数据来源应为高质量数据池。
  - 入池数据包含图片、质检确认后的标准框、正式类别、正式属性。
  - 带 `待确认类别` 的图片不得进入高质量数据池，也不应进入训练导出。
- 待研发确认问题：
  - MVP 训练导出是否需要做，还是第一版只做到高质量数据池查询。
  - 若需要导出，采用 YOLO、COCO 还是研发自定义格式。
  - 属性如何进入训练标签：按 `类别+属性` 合并成训练类别，还是只导出类别、属性放入附加映射文件。

  - 导出任务是否需要异步处理、下载有效期和导出记录。
  - 类别/属性停用后，历史入池数据导出时如何映射。
  - 后续是否需要对接训练平台、模型版本或训练任务管理。
- 暂定产品边界：
  - 复杂训练平台对接、模型版本管理和自动训练暂缓。
  - 待研发确认后，再拆回正式 PRD 和数据集导出规则。

##### Q8-1 标注任务列表

###### 需求背景
- 标注任务列表是标注员进入标注工作的任务入口。
- 标注任务的最小处理对象是图片，而不是项目或巡查记录。
- 标注员需要先通过缩略图快速识别图片，再进入标注工作台处理。

###### 设计目标
| 目标 | 说明 |
|---|---|
| 快速找图 | 用图片网格展示任务，降低表格扫图成本 |
| 区分任务池 | 用状态统计卡片区分全部、待标注、已标注、待确认类别、质检退回 |
| 支持重标 | 待确认类别、质检退回图片可以重新进入标注 |
| 控制信息密度 | 卡片只展示标注员处理任务所需的最小信息 |

###### 方案取舍
| 方案 | 优点 | 问题 | 结论 |
|---|---|---|---|
| 表格列表 | 字段承载能力强 | 图片缩略图弱，标注员扫图效率低 | 不采用 |
| 图片网格卡片 | 图片优先，适合标注任务入口 | 项目信息、时间、轮次等字段需收敛 | 采用 |

###### 任务来源规则
| 规则项 | 规则 |
|---|---|
| 图片来源 | 标注任务图片来源为巡查记录图片，包括 App 上传和后台上传 |
| 生成粒度 | 每张巡查图片生成一条图片级标注任务 |
| 项目类型 | 图片继承关联项目的项目类型，用于列表展示和筛选 |
| 排除来源 | 类别库维护图片、知识库图片不进入标注任务 |
| 删除影响 | 已删除巡查图片不再进入标注任务；已删除巡查图片对应未入池任务置为不可标注/已失效 |
| 入池后追溯 | 已入池图片的删除追溯口径后续在数据池规则中确认 |

###### 状态卡片规则
| 规则项 | 规则 |
|---|---|
| 状态卡片 | 页面顶部用状态统计卡片展示任务池和数量 |
| 状态范围 | 全部、待标注、已标注、待确认类别、质检退回 |
| 默认状态 | 默认选中 `全部` |
| 切换行为 | 状态卡片作为点击切换入口，当前选中状态高亮 |
| 数量统计 | 状态卡片数量受项目类型筛选影响 |

###### 筛选规则
| 筛选项 | 规则 |
|---|---|
| 项目类型 | 沿用项目管理选项：住宅装修、小型工程、零星作业 |
| 是否无可标注对象 | 仅在 `已标注` 状态下展示筛选项，选项为全部、是、否 |
| 查询 | 按当前状态卡片和项目类型筛选刷新网格 |
| 重置 | 清空项目类型筛选，状态卡片恢复 `全部` |

###### 卡片展示规则
| 元素 | 展示规则 |
|---|---|
| 图片缩略图 | 必须展示，作为卡片主视觉 |
| 项目类型 | 展示图片关联项目的项目类型 |
| 标注状态 | 不在图片卡片内展示，当前状态由顶部状态卡片表达 |
| 草稿标签 | 存在已保存未提交内容时展示 `有草稿` 标签 |

| 进入方式 | 不展示操作按钮，点击图片卡片任意位置进入标注工作台 |

| 普通标注员 | 不展示删除入口 |

###### 排序、分页与空状态

##### Q8-2 标注工作台

###### 需求背景
- 标注工作台是标注员执行图片框选和类别/属性选择的核心页面。
- 当前训练目标为目标检测模型训练，标注结果必须产出对象框、正式类别和正式属性。
- 标注工作台需要同时支持首次标注、待确认类别重标和质检退回重标。

###### 设计目标
| 目标 | 说明 |
|---|---|
| 完成框选 | 支持在图片上绘制、调整、删除对象框 |
| 绑定标注类别 | 每个对象框通过一个 `类别` 级联下拉选择类别及其下级属性 |
| 支持待确认 | 类别缺失时允许选择 `待确认类别` |
| 支持重标 | 待确认类别、质检退回图片可重新进入工作台处理 |
| 支持多种标注形式 | MVP 支持指针、旋转、魔术棒、矩形、多边形、点标注 |
| 自动识别能力待研发确认 | 是否提供 AI 自动识别辅助、实现方式和交互细节需与研发沟通确定 |

###### 页面布局建议
| 区域 | 说明 |
|---|---|
| 顶部操作区 | 返回、上一张/下一张、保存、提交标注；不展示当前序号/总数 |
| 左侧工具栏 | 展示标注工具：指针、旋转、魔术棒、自动识别、矩形、多边形、点标注；自动识别方案待研发确认 |
| 中间画布区 | 展示当前图片，支持按所选工具标注、缩放、拖动画布 |
| 右侧标注列表 | 展示当前图片所有标注对象及其形状类型、类别 |

###### 标注操作流程
| 步骤 | 规则 |
|---|---|
| 1. 选择标注形式 | 标注员先在左侧工具栏选择指针、旋转、魔术棒、自动识别、矩形、多边形或点标注 |
| 2. 图中标注 | 标注员在中间图片画布上进行标注 |
| 3. 生成对象 | 一次标注完成后，右侧标注列表立即新增一条标注对象 |
| 4. 选择类别 | 标注员在右侧对象卡片中通过 `类别` 级联下拉选择类别及其下级属性 |
| 5. 二级联动 | 类别一级选项来自启用类别，二级选项来自该类别下启用属性 |
| 6. 保存/提交 | 类别级联选择完成后，可保存或提交标注 |
| 自动识别辅助 | 是否支持、入口位置、触发方式、识别范围、结果回填方式待与研发沟通后确定 |

###### 标注对象规则
| 规则项 | 规则 |
|---|---|
| 标注形状 | 支持矩形、多边形、点标注、魔术棒生成区域 |
| 标注数量 | 一张图片允许多个标注对象 |
| 标注内容 | 每个标注对象必须完成 `类别` 级联选择；待确认类别除外 |
| 类别来源 | 来自启用的标注要素类别库 |
| 下级选项来源 | 来自所选类别下启用的属性，页面不单独展示 `属性` 字段 |
| 待确认类别 | 类别缺失时选择 `待确认类别` |
| 形状保留 | 保留原始标注形状，不强制统一转矩形；训练导出规则归入 Q7 待研发确认 |
| 旋转工具 | 仅旋转视图，不修改原图，不改变保存坐标系 |
| 魔术棒 | 标注员用鼠标涂抹/点选后，系统按物品轮廓自动填充生成标注区域 |
| 自动识别 | 产品侧已有需求，但实现方案、支持的形状类型、识别精度要求、性能约束待与研发沟通确认 |
| 对象选中 | 点击右侧对象卡片时，画布中对应标注对象高亮并定位 |
| 对象锁定 | 锁定后不可编辑标注区域，不可拖动、缩放或调整节点；仍可修改类别级联选择 |
| 对象可见 | 可见时画布展示该对象标注区域 |
| 对象不可见 | 不可见时画布隐藏该对象标注区域；右侧对象卡片仍保留，提交时仍计入标注结果 |
| 对象固定 | 固定后仍可编辑区域节点及拖动对象，用于保持对象在列表中置顶/便于连续处理 |
| 更多菜单 | 右侧对象卡片右上角显示 `⋮`，点击后展开 `复制`、`删除` |

###### 画布交互规则
| 操作 | 规则 |
|---|---|
| 鼠标滚轮 | 支持以当前鼠标位置为中心放大/缩小图片画布 |
| 指针长按拖动 | 指针状态下，长按图片空白区域可拖动画布位置 |
| 指针点击对象 | 指针状态下，点击已有标注对象可选中对象 |
| 指针拖动对象 | 未锁定对象可被拖动；锁定对象不可拖动 |
| 整体拖动 | 非锁定状态下，可直接拖动整个标注区域移动位置 |
| 节点拖动 | 非锁定状态下，可拖动标注区域节点调整形状 |
| 直接删除 | 非锁定状态下，可通过快捷键或对象菜单直接删除当前对象 |
| 缩放影响 | 画布缩放仅影响查看和编辑体验，不改变原图和保存坐标系 |

###### 图片切换规则
| 场景 | 规则 |
|---|---|
| 无未保存改动 | `上一张`、`下一张` 可点击 |
| 有未保存改动 | `上一张`、`下一张` 置灰不可点击，并提示先保存或提交标注 |
| 保存成功 | 留在当前图片，`上一张`、`下一张` 恢复可点击 |
| 保存失败 | 留在当前图片，`上一张`、`下一张` 保持置灰 |
| 提交标注成功 | 自动进入下一张待处理图片 |
| 提交无可标注对象成功 | 自动进入下一张待处理图片 |
| 提交失败 | 留在当前图片，提示失败原因 |
| 有待确认类别 | 不允许提交，只能保存；保存后不自动切换 |
| 最后一张提交成功 | 提示当前任务池已完成，返回任务列表或停留当前页待原型确认 |

###### 多边形节点编辑规则
| 操作 | 规则 |
|---|---|
| 绘制多边形 | 选择多边形工具后，标注员在图片上连续点击生成节点 |
| 闭合完成 | 点击回到开始节点，或让结束节点与开始节点相连时，表示多边形区域选择完成 |
| 完成后生成对象 | 多边形闭合完成后，右侧标注列表新增对应标注对象 |
| 选中节点 | 非锁定多边形对象选中后，可点击某个节点选中该节点 |
| 拖动节点 | 左键长按已选中节点并拖动，可调整该节点位置 |
| 删除节点 | 右键点击节点可删除该节点 |
| 删除限制 | 删除节点后若多边形不足 3 个节点，不允许删除并提示至少保留 3 个节点 |
| 锁定限制 | 锁定状态下不可选中、拖动或删除节点 |

###### 魔术棒标注规则
| 操作 | 规则 |
|---|---|
| 进入模式 | 选择魔术棒后，进入魔术棒辅助标注模式 |
| 常驻提示 | 魔术棒模式下画布展示常驻提示文案：`按“N”键完成区域选择` |
| 用户提示 | 标注员点击目标物品区域后，移动鼠标时实时显示识别候选区域 |
| 多次点击 | 标注员可在识别过程中多次点击生成节点，逐步补充或修正候选轮廓 |
| 轮廓生成 | 系统根据点击位置和目标边缘生成候选多边形区域 |
| 结果展示 | 候选区域以半透明填充、轮廓线和节点展示 |
| 完成识别 | 按键盘 `N` 完成区域选择 |
| 生成对象 | 按 `N` 完成后，右侧标注列表新增对应标注对象 |
| 结果修正 | 魔术棒结果可按多边形规则继续编辑，包括拖动节点、删除节点、整体拖动 |
| 生成失败 | 提示“未识别到有效区域，请调整点选位置或改用手动标注” |
| 保存形状 | 底层按多边形节点保存，来源标记为 `魔术棒生成` |
| 右侧展示 | 右侧对象卡片可展示为 `形状：魔术棒区域` |

###### 矩形标注规则
| 操作 | 规则 |
|---|---|
| 绘制矩形 | 选择矩形工具后，在图片上按下鼠标并拖拽生成矩形区域 |
| 完成矩形 | 松开鼠标后完成矩形标注 |
| 生成对象 | 矩形完成后，右侧标注列表新增对应标注对象 |
| 调整矩形 | 非锁定状态下，可拖动矩形整体或拖动边角节点调整大小 |
| 锁定限制 | 锁定状态下不可拖动矩形整体，不可调整边角节点 |

###### 键盘快捷操作规则
| 快捷键 | 规则 |
|---|---|
| `Ctrl + Z` | 撤销上一步标注编辑操作 |
| `Delete` / `Backspace` | 删除当前选中的标注对象 |
| 删除限制 | 锁定对象不可通过快捷键删除 |
| 输入态限制 | 当焦点在类别下拉、搜索框等输入控件中时，快捷键不触发画布操作 |
| 撤销范围 | MVP 撤销范围限定为当前图片、当前工作台会话内的标注编辑操作 |
| 不做项 | MVP 暂不定义完整快捷键体系，后续按使用频率扩展 |

###### 对象颜色规则
| 规则项 | 规则 |
|---|---|
| 颜色用途 | 颜色用于区分同一张图片中的不同标注对象，方便标注员查看和定位 |
| 分配方式 | 系统提供固定颜色组，新增标注对象时按顺序轮询分配颜色 |
| 颜色数量 | MVP 固定 5 种高对比颜色；同图对象数量超过 5 个时从第一种颜色重新轮询 |
| 固定颜色组 | `#E11D48` 红、`#2563EB` 蓝、`#16A34A` 绿、`#F59E0B` 黄、`#9333EA` 紫 |
| 用户维护 | MVP 不提供手动改色能力，避免把颜色误解为业务属性 |
| 同步展示 | 画布中的标注区域边框颜色与右侧对象卡片色块颜色保持一致 |
| 不表达类别 | 颜色不代表类别、属性、状态或质检结论，不参与保存语义 |
| 选中态 | 当前选中对象在画布中加粗/高亮，右侧对象卡片同步高亮 |
| 不可见 | 对象设为不可见后，画布隐藏该对象颜色和区域；右侧卡片保留颜色标识 |
| 复制对象 | 复制对象时生成新的对象颜色，避免与原对象混淆 |

###### 对象快捷操作规则

|---|---|
| 锁定 | 锁定当前对象的标注区域，禁止拖动、缩放、调整节点和删除区域 |
| 解锁 | 恢复当前对象区域编辑能力 |
| 可见/不可见 | 控制当前对象标注区域在画布中的显示，不改变标注数据 |
| 固定/取消固定 | 控制对象在右侧列表中的固定展示状态；固定对象仍允许编辑区域节点及拖动 |
| 复制 | 进入复制放置模式，鼠标显示复制区域预览，点击画布后生成新对象 |
| 删除 | 删除当前对象，不做二次确认；可通过撤销恢复当前会话内误删 |

###### 提交规则
| 场景 | 规则 |
|---|---|
| 无框提交 | 图片中没有对应可标注物品时，允许提交为 `无可标注对象`，提交后进入 `已标注` |
| 有正式框 | 所有框均完成正式 `类别` 级联选择时，可提交 |
| 有待确认类别并保存 | 保存后任务进入/保持 `待确认类别` 状态，并展示 `有草稿` 标签 |
| 有待确认类别并提交 | 不允许提交，提示先补齐正式类别后再提交 |
| 字段缺失 | 存在未完成 `类别` 级联选择的标注对象时，不允许提交 |
| 保存草稿 | 保存当前编辑内容；无待确认类别时不改变任务状态；有待确认类别时进入/保持 `待确认类别` |
| 提交标注 | 仅正式类别级联完整时可提交，提交后进入 `已标注` |

###### 保存、草稿与待确认类别整理结论
| 事项 | 结论 |
|---|---|
| 草稿性质 | 草稿是编辑进度，不作为独立状态卡片 |
| 草稿定义 | 用户点击 `保存` 后，保存内容尚未成功提交，即存在草稿 |
| 草稿展示 | 可编辑状态下存在草稿时，图片卡片展示 `有草稿` 标签 |
| 待标注保存 | 保存内容无 `待确认类别` 时，任务仍在 `待标注`，并标记为有草稿 |
| 待标注保存且含待确认类别 | 任务从 `待标注` 进入 `待确认类别`，并标记为有草稿 |
| 待确认类别保存 | 任务保持 `待确认类别`，并标记为有草稿 |
| 质检退回保存 | 任务保持 `质检退回`，并标记为有草稿 |
| 已标注处理 | `已标注` 默认只读查看，不允许普通标注员继续保存草稿 |
| 待确认类别提交 | 不允许提交，需先补齐正式类别级联选择 |
| 正式类别提交 | 所有标注对象均完成正式类别级联选择后，提交进入 `已标注`，并清除草稿标签 |
| 无可标注对象提交 | 无标注对象时可提交为 `无可标注对象`，进入 `已标注`，并在已标注列表中支持标签展示和筛选 |
| 状态关系 | `待确认类别` 是业务异常状态，`有草稿` 是编辑进度标记，二者可以同时存在 |
| 列表入口 | 卡片不展示操作按钮，点击整张卡片进入标注工作台 |
| 卡片状态 | 图片卡片不展示任务状态，状态由顶部状态卡片表达 |

###### 类别级联选择规则
| 场景 | 规则 |
|---|---|
| 未选择 | `类别` 控件显示 `请选择类别` |
| 选择正式类别 | 展开二级选项，展示该类别下启用属性 |
| 完成选择 | 选中结果展示为 `类别 / 属性`，如 `安全帽 / 白色` |
| 切换一级类别 | 清空原二级选择，重新展示新类别下的启用属性 |
| 选择待确认类别 | 不展示二级选项 |
| 类别无启用属性 | 不应出现在可选类别中；若异常出现，提示类别配置异常 |
