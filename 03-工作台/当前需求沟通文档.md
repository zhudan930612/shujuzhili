### 取舍与评审
- 推荐优先级：先做“标注任务与质检闭环”，而不是继续补周边管理功能。

| 候选方向 | 价值 | 当前问题 | 建议 |
|---|---|---|---|
| 标注任务与质检闭环 | 直接承接平台核心价值，决定照片能否变成训练数据 | 当前只有流程节点，没有任务分配、标注结果、质检裁决、驳回回流、待确认处理的页面规则 | 第一优先级 |
| 数据集/高质量数据池管理 | 承接 S6 和 AI 训练侧使用 | 依赖标注和质检结果，过早设计容易空转 | 第二优先级，跟在标注质检之后 |
| 报告生成/导出 | 更贴近保险公司交付 | 当前平台定位不是先做报告交付，且法规匹配、隐患识别结果尚未闭环 | 暂缓 |
| 行政区域字典后台维护 | 补强当前区域权限专题 | 系统管理已明确当前不新增独立行政区域管理页面，先按基础数据维护 | 暂缓，除非区域数据来源无法保障 |
| 隐患案例库页面 | 丰富知识库 | 知识库 PRD 已明确当前暂不展开案例库列表、录入、详情、导入页面 | 暂缓 |

- 评审意见：
  - 继续做采集前置功能的边际收益已经下降；真正卡住平台闭环的是采集后的治理处理。
  - 如果没有标注/质检模块，当前“数据治理平台”容易停在“项目与图片管理系统”，无法证明高质量数据池成立。
  - 标注质检必须与知识库回流一起设计；在新口径下，回流对象需要从“新隐患 / 规则缺失”扩展为“新物品类别 / 安全要素类别缺失 / 隐患规则缺失”。
  - 不建议先做 AI 训练或报告生成；训练侧需要稳定数据集，报告侧需要稳定识别结果和法规匹配结果，当前条件不足。
  - 口径变更风险：现有 [../01-产品架构/知识体系设计.md](../01-产品架构/知识体系设计.md) 与 [../02-PRD文档/后台管理/知识库管理.md](../02-PRD文档/后台管理/知识库管理.md) 当前以“隐患编码”为 AI 识别目标，若确认改为物品/安全要素标注，需要补充“物品/安全要素库”或调整知识体系层级，不能只改标注页面。

#### Q1 沟通记录：标注作业对象
- 待讨论点：
  - 第一版标注对象是否从“隐患”调整为“物品/安全要素”。
  - 物品/安全要素类别如何组织，例如安全帽、灭火器、脚手架、配电箱、防护栏、洞口盖板等。
  - 一张图片是否允许存在多个物品/安全要素标注框。
  - 是否还保留图片级“无目标/无可标注对象”结果，用于负样本或空样本沉淀。
  - 物品/安全要素标注结果如何与后续隐患判断、法规匹配和整改建议衔接。
  - 训练目标是否为目标检测模型训练，还是视觉大模型微调/样本学习。
- 初始评审：
  - 该调整有合理性：很多隐患判断依赖先识别现场对象及状态，例如先识别“安全帽”“灭火器”“脚手架”“防护栏”，再判断是否佩戴、是否缺失、是否过期、是否搭设异常。
  - 物品标注比隐患标注更接近视觉模型训练的基础任务，标注员理解成本通常低于直接判断复杂隐患，也更容易形成稳定样本。
  - 但这会改变当前知识体系：现有文档把“具体隐患编码”作为 AI 识别目标；若改为物品/安全要素标注，后续需要增加“物品/安全要素 -> 隐患规则 -> 法规/整改建议”的推理或匹配层。
  - 不能把“物品类别”直接塞进现有“隐患库”的四级具体隐患里，否则会混淆“对象是什么”和“问题是什么”两个概念。
  - “告知大模型什么是安全帽、灭火器、脚手架”需要进一步明确训练目标：是训练目标检测模型、微调视觉大模型，还是构建带框样本供后续模型评测。不同目标会影响导出格式和质量标准。
- 当前建议：
  - 第一版标注对象调整为“物品/安全要素”，不直接标注“隐患”。
  - 一张图片支持多个物品/安全要素框；每个框绑定一个物品/安全要素类别。
  - 物品/安全要素类别应独立建库或作为知识体系新增层，不与现有隐患库混放。
  - “无隐患”暂不作为标注标签；如图片中没有任何可标注物品/安全要素，已调整为通过 `无效图片` 原因 `无可标注对象` 处理。
  - 后续隐患判断通过“物品/安全要素识别结果 + 隐患判定规则/知识库”承接，不在本轮 Q1 中直接定义。
- 已确认结论：
  - 第一版训练目标为目标检测模型训练。
  - 标注任务需要框出物品/安全要素的位置，输出对象类别和坐标。
  - 标注对象为安全帽、灭火器、脚手架等物品/安全要素，不直接标注隐患。
  - 一张图片允许多个物品/安全要素框。
  - “无隐患”不作为标注标签；若图片无可标注物品/安全要素，通过 `无效图片` 原因 `无可标注对象` 处理。
  - 该结论后续需拆回知识体系与标注质检 PRD，并影响训练侧导出格式。

#### Q2 沟通记录：标注轮次与质检裁决
- 用户想法：
  - 不限制标注轮次。
  - 质检人员可以手动选择查看经过几个轮次的标注结果。
  - 质检人员基于查看结果决策是否进入高质量数据池。
- 初始评审：
  - 该思路适合目标检测训练数据治理：多轮标注可以沉淀不同人员对同一对象框和类别的判断差异，质检员再基于差异做最终裁决。
  - 相比固定 2 人或 3 人投票，可变轮次更灵活，适合早期类别标准还在校准的阶段。
  - 风险是如果完全不设流程边界，任务可能反复标注、质检成本失控，且“何时可以进入质检”不清晰。
  - 建议把“不限制轮次”理解为“业务上不固定必须几轮”，但系统仍需要记录轮次、标注人、时间、版本、标注结果和质检裁决，避免结果不可追溯。
- 当前建议：
  - 标注任务支持多轮标注，不强制固定为 2 人或 3 人。
  - 每轮标注结果独立留痕，不覆盖上一轮结果。

#### Q3 沟通记录：质检范围与标准结果生成

#### Q8-6 沟通记录：标注要素类别库

#### Q5 沟通记录：待确认类别处理
- 用户想法：
  - 如果有标记为 `待确认类别` 的图片，标注人员可以筛选查看。
  - 标注人员通过其他方式告知领域工程师存在待标注情况，请其查看并维护类别库。
  - 领域工程师更新标注类别库后，标注人员可以再次查看这些待确认类别图片，并重新进行标注。
- 初始评审：
  - 该方案适合 MVP：系统不做复杂审批流，只提供筛选、识别和重标入口，把领域工程师确认动作放在类别库维护中完成。
  - 关键边界是带 `待确认类别` 的标注结果不能进入高质量数据池；必须重新标注为正式类别和正式属性后，才允许进入后续质检/入池。
  - “其他方式告知领域工程师”不需要在 MVP 做消息通知或工单流，但系统应能让标注员筛选出待确认图片，方便人工沟通时提供依据。
- 当前建议：
  - 标注员在标注时遇到类别缺失，选择 `待确认类别`。
  - 标注任务列表或标注记录列表提供 `是否待确认类别` 筛选项。
  - 标注员可筛选查看所有包含 `待确认类别` 的图片。
  - 标注员通过线下沟通、即时通讯或其他方式通知领域工程师补充类别库；MVP 不内置审批流、消息通知或工单。
  - 领域工程师在标注要素类别库中新增类别/属性，或启用已有类别/属性。
  - 类别库更新后，标注员回到待确认类别筛选结果，对相关图片重新标注为正式类别和正式属性。
  - 重新标注完成后，原 `待确认类别` 状态解除，图片进入后续质检流程。
  - 带 `待确认类别` 的图片不得进入高质量数据池。
- 已确认结论：
  - 标注员在标注时遇到类别缺失，选择 `待确认类别`。
  - 标注任务列表或标注记录列表提供 `是否待确认类别` 筛选项。
  - 标注员可筛选查看所有包含 `待确认类别` 的图片。
  - 标注员通过线下沟通、即时通讯或其他方式通知领域工程师补充类别库；MVP 不内置审批流、消息通知或工单。
  - 领域工程师在标注要素类别库中新增类别/属性，或启用已有类别/属性。
  - 类别库更新后，标注员回到待确认类别筛选结果，对相关图片重新标注为正式类别和正式属性。
  - 重新标注完成后，原 `待确认类别` 状态解除，图片进入后续质检流程。
  - 带 `待确认类别` 的图片不得进入高质量数据池。

#### Q6 沟通记录：数据池入库条件
- 已确认结论：
  - MVP 采用“质检通过即入池”，不做批次发布/版本冻结。
  - 图片进入高质量数据池必须同时满足：所有标准框使用正式类别、所有标准框选择正式属性、质检员已确认标准结果、图片级裁决为 `进入高质量数据池`。
  - 入池结果以质检员确认的标准框、类别和属性为准。
  - 带 `待确认类别` 的图片不得进入高质量数据池。
  - 入池后不允许普通标注员修改。
  - 入池后如发现问题，后续通过抽查/复查流程处理，不直接改写原入池结果。
  - 入池记录需保留标注轮次、质检结果、质检员和裁决时间等留痕信息。

#### Q7 沟通记录：训练侧导出
- 当前状态：
  - 导出需求需要研发确认沟通，产品侧本轮不直接确定导出格式、属性映射和训练数据包结构。
- 产品侧已知前提：
  - 第一版训练目标为目标检测模型训练。
  - 可导出的数据来源应为高质量数据池。
  - 入池数据包含图片、质检确认后的标准框、正式类别、正式属性。
  - 带 `待确认类别` 的图片不得进入高质量数据池，也不应进入训练导出。
- 待研发确认问题：
  - MVP 训练导出是否需要做，还是第一版只做到高质量数据池查询。
  - 若需要导出，采用 YOLO、COCO 还是研发自定义格式。
  - 属性如何进入训练标签：按 `类别+属性` 合并成训练类别，还是只导出类别、属性放入附加映射文件。
  - 坐标格式采用归一化坐标、像素坐标，还是按目标框格式要求输出。
  - 导出包是否包含原图，还是只输出标注文件和图片引用地址。
  - 导出任务是否需要异步处理、下载有效期和导出记录。
  - 类别/属性停用后，历史入池数据导出时如何映射。
  - 后续是否需要对接训练平台、模型版本或训练任务管理。
- 暂定产品边界：
  - 复杂训练平台对接、模型版本管理和自动训练暂缓。
  - 待研发确认后，再拆回正式 PRD 和数据集导出规则。

##### Q8-1 标注任务列表

###### 需求背景
- 标注任务列表是标注员进入标注工作的任务入口。
- 标注任务的最小处理对象是图片，而不是项目或巡查记录。
- 标注员需要先通过缩略图快速识别图片，再进入标注工作台处理。

###### 设计目标
| 目标 | 说明 |
|---|---|
| 快速找图 | 用图片网格展示任务，降低表格扫图成本 |
| 区分任务池 | 用状态统计卡片区分全部、待标注、已标注、待确认类别、质检退回、无效图片 |
| 支持重标 | 待确认类别、质检退回图片可以重新进入标注 |
| 控制信息密度 | 卡片只展示标注员处理任务所需的最小信息 |

###### 方案取舍
| 方案 | 优点 | 问题 | 结论 |
|---|---|---|---|
| 表格列表 | 字段承载能力强 | 图片缩略图弱，标注员扫图效率低 | 不采用 |
| 图片网格卡片 | 图片优先，适合标注任务入口 | 项目信息、时间、轮次等字段需收敛 | 采用 |

###### 任务来源规则
| 规则项 | 规则 |
|---|---|
| 阶段粒度 | 标注阶段按 `标注任务` 处理，质检阶段按 `图片` 处理 |
| 标注任务 | 标注任务是图片与标注员的关系记录；同一图片分配给不同标注员时，生成多条标注任务 |
| 质检任务 | 质检任务是图片级汇总记录；同一图片只生成一条质检任务，汇总多个标注员结果 |
| 图片来源 | 标注任务图片来源为巡查记录图片，包括 App 上传和后台上传 |
| 资产边界 | 巡查记录图片属于巡查服务过程证据；标注训练样本属于数据治理资产，两者生命周期独立 |
| MVP 分配机制 | 巡查记录图片先进入 Q8-0 任务分配管理；管理员创建任务批次并指定标注人员后，系统生成个人标注任务 |
| 生成粒度 | 批次创建成功后，每张图片按标注人员生成标注任务；同一图片保留统一图片 ID，可关联多份人员标注结果 |
| 项目类型 | 图片继承关联项目的项目类型，用于列表展示和筛选 |
| 排除来源 | 类别库维护图片、知识库图片不进入标注任务 |
| 删除影响 | 未生成任务批次的巡查图片被删除后，同步从 Q8-0 待分配范围移除；已生成任务批次的样本图片不自动删除、不自动失效 |
| 来源追溯 | 巡查记录图片被删除后，已进入标注链路的样本继续保留标注、质检和入池记录，并在来源追溯中标记 `来源巡查图片已删除` |

###### 状态卡片规则
| 规则项 | 规则 |
|---|---|
| 状态卡片 | 页面顶部用状态统计卡片展示任务池和数量 |
| 展示位置 | 状态卡片位于筛选条件上方，作为页面主切换入口；筛选条件位于状态卡片下方 |
| 状态范围 | 全部、待标注、已标注、待确认类别、质检退回、无效图片 |
| 状态口径 | 状态统计按当前标注员可见的标注任务记录计数，不按图片去重 |
| 默认状态 | 默认选中 `全部` |
| 切换行为 | 状态卡片作为点击切换入口，当前选中状态高亮 |
| 状态颜色 | 状态卡片按状态使用不同低饱和色区分：全部蓝灰、待标注品牌蓝、已标注绿色、待确认类别橙色、质检退回红色、无效图片灰色 |
| 数量统计 | 状态卡片数量受项目类型筛选影响 |

###### 筛选规则
| 筛选项 | 规则 |
|---|---|
| 项目类型 | 沿用项目管理选项：住宅装修、小型工程、零星作业 |
| 是否有草稿 | 选项为全部、有、无 |
| 查询 | 按当前状态卡片、项目类型、是否有草稿筛选刷新网格 |
| 重置 | 清空项目类型和是否有草稿筛选，状态卡片恢复 `全部` |

###### 卡片展示规则
| 元素 | 展示规则 |
|---|---|
| 图片缩略图 | 必须展示，作为卡片主视觉 |
| 缩略图尺寸 | 缩略图固定为正方形，按图片中心裁切展示 |
| 缩略图内容 | 缩略图只展示原始图片，不展示标注框、伪标注线或状态覆盖层 |
| 项目类型 | 展示图片关联项目的项目类型 |
| 标注状态 | 不在图片卡片内展示，当前状态由顶部状态卡片表达 |
| 草稿标签 | 存在已保存未提交内容时展示 `有草稿` 标签 |
| 无效图片标签 | 标记为无效图片的标注任务，在 `无效图片` 状态下展示无效原因 |
| 进入方式 | 不展示操作按钮，点击图片卡片任意位置进入标注工作台 |
| 刷新按钮 | 列表不提供刷新按钮，通过查询、重置和分页刷新数据 |
| 待确认类别 | 保存草稿中存在 `待确认类别` 时，任务展示在 `待确认类别` 状态卡下 |
| 不展示项 | 不展示项目名称、巡查时间和标注轮次 |

###### 权限规则
| 角色 | 规则 |
|---|---|
| 标注员 | 查看分配给自己的标注任务 |
| 其他角色 | 按后台角色权限配置 |
| 删除任务 | MVP 不提供删除标注任务操作；异常图片通过 `标记无效` 处理，源图片删除导致任务失效 |

###### 排序、分页与空状态
| 规则项 | 规则 |
|---|---|
| 默认排序 | 按任务更新时间倒序 |
| 特殊排序 | 质检退回和待确认类别按最近更新时间靠前 |
| 分页 | 默认每页 24 张，支持分页 |
| 无任务空状态 | 当前状态无任务时显示“当前暂无待处理图片” |
| 筛选无结果 | 显示“未找到符合条件的图片，请调整筛选条件” |

###### 功能目标
| 目标 | 说明 |

###### 标注对象与类别规则
| 规则项 | 规则 |
|---|---|
| 标注对象 | 一张图片允许多个标注对象 |
| 支持形状 | 矩形、多边形、魔术棒区域；点标注保留入口，规则待沟通 |
| 形状保存 | 保留原始形状，不强制转矩形；魔术棒底层按多边形节点保存并标记来源 |
| 类别控件 | 右侧对象卡片只展示一个 `类别` 级联控件 |
| 级联展示 | 选择后展示为 `类别 / 属性`，如 `安全帽 / 白色` |
| 属性多选 | 同一标注对象内支持在单一类别下多选多个属性，如 `安全帽 / 白色、红色` |
| 跨类别限制 | 同一标注对象内不允许跨不同类别同时选择属性；如已选择 `安全帽` 类属性，则不可再同时选择 `灭火器` 类属性 |
| 类别来源 | 一级来自启用的标注要素类别库 |
| 下级来源 | 二级来自所选类别下启用属性 |
| 待确认类别 | 类别/属性面板固定第一项展示 `待确认类别`；选择后不展示二级选项，且不可与正式类别/属性同时共存 |
| 搜索能力 | MVP 暂不支持类别或属性搜索 |
| 提交校验 | 正式标注对象必须完成类别级联选择，并至少选择 1 个属性；含 `待确认类别` 时不允许提交 |

###### 工具栏规则
| 工具 | 规则 |
|---|---|
| 指针 | 选择对象、拖动画布、拖动非锁定对象 |

###### 保存、提交与状态流转
| 场景 | 规则 |
|---|---|
| 保存草稿 | 保存当前编辑内容；保存后仍留在当前图片 |
| 草稿定义 | 用户点击保存后，保存内容尚未成功提交，即存在草稿 |
| 草稿展示 | 可编辑状态下存在草稿时，标注任务卡片展示 `有草稿` |
| 待标注保存 | 无 `待确认类别` 时保持 `待标注`；含 `待确认类别` 时进入 `待确认类别` |
| 待确认类别保存 | 保持 `待确认类别`，并展示 `有草稿` |
| 质检退回保存 | 保持 `质检退回`，并展示 `有草稿` |
| 正式提交 | 所有对象均完成正式类别级联后，提交进入 `已标注`，清除草稿 |
| 待确认提交 | 含 `待确认类别` 时不允许提交，提示先补齐正式类别 |
| 字段缺失 | 存在未完成类别级联的对象时不允许提交 |
| 进入质检 | MVP 阶段同一图片只要存在一份正式类别完整的正常标注结果，即进入质检任务池 |
| 后续轮次 | 图片进入质检后，后续新增正常标注结果继续汇总到同一图片质检任务下 |
| 不进质检 | `待确认类别` 不进入质检任务池；单个标注员提交的 `无效图片` 结果不单独进入质检 |

###### 无效图片
| 规则项 | 规则 |
|---|---|
| 定义 | 标注员认为当前图片不适合标注或进入训练链路 |
| 结果性质 | `无效图片` 是单个标注员的标注结果，不直接代表图片全局无效 |
| 主入口 | 顶部操作区展示 `标记无效` |
| 无对象提交 | 当前无标注对象时点击 `提交标注`，直接打开无效图片弹窗，并默认勾选 `无可标注对象` |
| 原因 | 支持多选，至少选择 1 项：图片质量差、图片损坏/无法加载、内容无关、非施工现场、遮挡严重、重复图片、截图/拼图/水印干扰、无可标注对象、其他 |
| 无可标注对象 | 作为无效图片原因之一，不作为独立提交结果、标签、筛选或质检/入池判断 |
| 其他原因 | 选择 `其他` 时必须输入具体原因 |
| 弹窗标题 | `确认标记为无效图片？` |
| 标记影响 | 确认标记无效后，清空当前草稿和已绘制标注对象 |
| 流转 | 标记后进入 `无效图片` 状态 |
| 多人标注 | 同一图片可同时存在正常标注、无效图片等不同人员结果 |
| 进入质检 | 同一图片只要存在正常标注结果，仍进入质检；质检页展示正常标注结果和无效标记记录 |
| 后续 | 单个无效图片结果不直接进入质检任务池、不进入高质量数据池、不参与训练导出 |
| 质检结论影响 | 图片级质检结论不反写覆盖标注员个人任务状态 |
| 最终无效 | 图片最终是否判为无效，由质检员/管理员在后续裁决阶段确认 |
| 查看 | 在标注任务列表 `无效图片` 状态卡查看，进入工作台后只读展示无效原因 |
| 恢复 | 标注员可将无效图片恢复为 `待标注` 状态，恢复后可重新标注 |
| 恢复追溯 | 恢复后原无效记录保留为操作日志，不作为当前有效标注结果 |

###### 任务来源与汇总规则
| 规则项 | 规则 |
|---|---|
| 阶段粒度 | 标注阶段按标注任务处理，质检阶段按图片处理 |
| 质检任务 | 同一图片只生成一条图片级质检任务 |
| 任务来源 | MVP 阶段同一图片存在至少一份正常标注结果时进入质检任务池 |
| 后续汇总 | 图片进入质检后，后续新增正常标注结果继续汇总，不重复生成图片级质检任务 |
| 排除来源 | 仅有 `待确认类别`、仅有 `无效图片` 或无正常标注结果的图片不进入质检任务池 |
| 无可标注对象 | 已并入 `无效图片` 原因，不进入质检、不入池、不导出 |
| 无效记录 | 若同一图片同时存在正常标注和无效图片结果，仍进入质检；无效标记记录在 Q8-4 展示，内容包括标记人、标记时间、无效原因 |

###### 状态定义与统计口径
| 状态 | 含义 | 统计口径 |
|---|---|---|
| 全部 | 当前可见的全部图片级质检任务 | 按图片计数 |
| 待质检 | 已进入质检池，但质检员未完成裁决 | 按图片计数 |
| 已质检 | 质检员已完成裁决，且该图片进入高质量数据池 | 按图片计数 |
| 退回 | 质检员裁决为需标注员返工 | 按图片计数 |
| 不入池 | 质检员已完成裁决，但该图片不进入高质量数据池 | 按图片计数 |

###### 状态统计规则
| 规则项 | 规则 |
|---|---|
| 统计粒度 | Q8-3 全部状态卡片均按图片级质检任务统计 |
| 不按标注任务计数 | 同一图片无论有几个标注员结果，在质检列表只算 1 条 |
| 后续新增标注 | 后续新增正常标注结果只汇总到同一图片质检任务，不新增列表卡片 |
| 数量统计 | 状态卡片数量受项目类型、标注轮次筛选影响 |

###### 已质检与不入池规则
| 规则项 | 规则 |
|---|---|
| 已质检 | 表示图片已完成质检裁决，并进入高质量数据池 |
| 不入池 | 表示图片已完成质检裁决，但不进入高质量数据池 |
| 不入池后续 | MVP 阶段 `不入池` 为只读终止态，不进入高质量数据池，不参与训练导出 |
| 恢复裁决 | MVP 暂不支持从 `不入池` 恢复或重新裁决；如后续需要，由管理员/质检负责人权限单独定义 |

| 规则项 | 规则 |

| 图片级结论 | 图片级质检任务可进入 `已质检` 并入池，入池使用质检员确认的标准结果，不使用该标注员无效结果 |

###### 退回规则
| 规则项 | 规则 |
|---|---|
| 退回定位 | 退回是质量管理动作，不是逐框纠错动作 |
| 优先修正 | 单个对象小错、少量框不准或类别/属性错，质检员优先直接修正并生成标准结果 |
| 退回条件 | 当某条标注记录整体质量不可接受、需要标注员返工时，才执行退回 |
| 退回粒度 | 退回整条标注记录，即某个标注员对某张图片的一次提交结果 |
| 不支持 | 不支持单个标注对象退回 |
| 退回原因 | 退回时必须填写退回原因 |
| 标注员侧 | 被退回的标注记录对应标注任务进入 `质检退回` |
| 质检列表状态 | 图片下存在待返工标注记录时，图片级质检任务显示为 `退回` |
| 重新提交 | 标注员重新提交后，该图片回到/保持 `待质检`，等待质检员再次裁决 |

| 质检员视角 | 质检员看到的是图片级质检任务处于退回状态 |
| 其他标注记录 | 同一图片下未被退回的其他标注记录不受影响 |
| 标准结果 | 质检员直接修正产生图片级标准结果，不覆盖原标注记录 |

###### 异常与边界

###### 质检工作台场景
| 场景 | 说明 | 结果 | MVP |
|---|---|---|---|
| S1 查看对象组 | 同一图片下同类/相近位置的标注对象被聚合成对象组 | 质检员按对象组对比候选标注 | 必做 |
| S2 查看来源记录 | 按标注员查看整条标注记录和来源对象 | 判断整条记录质量，必要时退回 | 必做 |
| S3 采纳参考对象 | 某个候选对象或来源对象质量较好，可作为标准对象基础 | 生成标准结果草稿对象 | 必做 |
| S4 直接修正少量错误 | 漏标少、框不准、类别/属性错 | 质检员直接改标准结果 | 必做 |
| S5 自行新增标准对象 | 所有标注员都漏标某个对象 | 质检员新增对象 | 必做 |
| S6 删除错误对象 | 标注员误标了不存在或无关对象 | 质检员删除对象 | 必做 |
| S7 退回低质量标注记录 | 某条标注记录整体质量不可接受 | 退回该标注记录，标注员返工 | 必做 |
| S8 裁决入池 | 标准结果完整、类别属性准确 | 图片进入高质量数据池 | 必做 |
| S9 裁决不入池 | 图片质量、内容或标注价值不满足入池要求 | 图片进入不入池状态 | 必做 |
| S10 查看无效记录 | 同图有标注员提交无效图片 | 作为质检参考，不直接决定结论 | 必做 |
| S11 保存质检草稿 | 质检未完成，需要稍后继续 | 图片级质检任务展示有草稿 | 必做 |
| S12 查看任务记录 | 追溯标注、无效、退回、草稿、入池/不入池过程 | 打开图片级任务记录 | 必做 |
| S13 被退回后重新质检 | 标注员返工重新提交后 | 图片回到待质检，质检员再次裁决 | 流程结果 |

| 二次确认 | MVP 不弹二次确认窗 |
| 校验失败 | 停留当前页，并提示具体未通过原因 |
| 校验通过 | 图片级质检任务进入 `已质检`，标准结果进入高质量数据池 |
| 草稿处理 | 入池成功后清除该图片的质检草稿 |
| 记录触发 | 生成图片级任务记录：操作类型 `质检通过入池` |
| 页面跳转 | 入池成功后自动进入下一张待质检图片；若无下一张，返回 Q8-3 质检任务列表 |

###### 不入池规则
| 规则项 | 规则 |
|---|---|
| 操作入口 | 顶部 `不入池` 按钮 |
| 使用场景 | 图片虽进入质检，但最终不适合作为高质量训练数据 |
| 弹窗确认 | 点击 `不入池` 后打开确认弹窗 |
| 原因要求 | 必须选择不入池原因 |
| 备注 | MVP 不要求备注 |
| 原因选项 | 图片质量差、标注对象不清晰、场景不符合训练目标、标准结果无法确认、多人标注差异过大、重复图片、其他 |
| 退回阻断 | 当前图片存在待返工的退回记录时，不允许不入池 |
| 退回提示 | 存在退回记录时提示“当前图片存在待返工的退回记录，暂不能不入池。” |
| 确认结果 | 图片级质检任务进入 `不入池` |
| 入池/导出 | 不进入高质量数据池，不参与训练导出 |
| 草稿处理 | 确认不入池后清除该图片的质检草稿 |
| 记录触发 | 生成图片级任务记录：操作类型 `不入池`，说明记录所选原因 |
| 页面跳转 | 确认不入池后自动进入下一张待质检图片；若无下一张，返回 Q8-3 质检任务列表 |
| 恢复处理 | MVP 默认不可恢复，`不入池` 状态只读查看 |

###### 退回阻断规则
| 规则项 | 规则 |
|---|---|
| 阻断范围 | 当前图片存在待返工的退回记录时，阻断图片级最终裁决 |
