### 取舍与评审
- 推荐优先级：先做“标注任务与质检闭环”，而不是继续补周边管理功能。

| 候选方向 | 价值 | 当前问题 | 建议 |
|---|---|---|---|
| 标注任务与质检闭环 | 直接承接平台核心价值，决定照片能否变成训练数据 | 当前只有流程节点，没有任务分配、标注结果、质检裁决、驳回回流、待确认处理的页面规则 | 第一优先级 |
| 数据集/高质量数据池管理 | 承接 S6 和 AI 训练侧使用 | 依赖标注和质检结果，过早设计容易空转 | 第二优先级，跟在标注质检之后 |
| 报告生成/导出 | 更贴近保险公司交付 | 当前平台定位不是先做报告交付，且法规匹配、隐患识别结果尚未闭环 | 暂缓 |
| 行政区域字典后台维护 | 补强当前区域权限专题 | 系统管理已明确当前不新增独立行政区域管理页面，先按基础数据维护 | 暂缓，除非区域数据来源无法保障 |
| 隐患案例库页面 | 丰富知识库 | 知识库 PRD 已明确当前暂不展开案例库列表、录入、详情、导入页面 | 暂缓 |

- 评审意见：
  - 继续做采集前置功能的边际收益已经下降；真正卡住平台闭环的是采集后的治理处理。
  - 如果没有标注/质检模块，当前“数据治理平台”容易停在“项目与图片管理系统”，无法证明高质量数据池成立。
  - 标注质检必须与知识库回流一起设计；在新口径下，回流对象需要从“新隐患 / 规则缺失”扩展为“新物品类别 / 安全要素类别缺失 / 隐患规则缺失”。
  - 不建议先做 AI 训练或报告生成；训练侧需要稳定数据集，报告侧需要稳定识别结果和法规匹配结果，当前条件不足。
  - 口径变更风险：现有 [../01-产品架构/知识体系设计.md](../01-产品架构/知识体系设计.md) 与 [../02-PRD文档/后台管理/知识库管理.md](../02-PRD文档/后台管理/知识库管理.md) 当前以“隐患编码”为 AI 识别目标，若确认改为物品/安全要素标注，需要补充“物品/安全要素库”或调整知识体系层级，不能只改标注页面。

#### Q1 沟通记录：标注作业对象
- 待讨论点：
  - 第一版标注对象是否从“隐患”调整为“物品/安全要素”。
  - 物品/安全要素类别如何组织，例如安全帽、灭火器、脚手架、配电箱、防护栏、洞口盖板等。
  - 一张图片是否允许存在多个物品/安全要素标注框。
  - 是否还保留图片级“无目标/无可标注对象”结果，用于负样本或空样本沉淀。
  - 物品/安全要素标注结果如何与后续隐患判断、法规匹配和整改建议衔接。
  - 训练目标是否为目标检测模型训练，还是视觉大模型微调/样本学习。
- 初始评审：
  - 该调整有合理性：很多隐患判断依赖先识别现场对象及状态，例如先识别“安全帽”“灭火器”“脚手架”“防护栏”，再判断是否佩戴、是否缺失、是否过期、是否搭设异常。
  - 物品标注比隐患标注更接近视觉模型训练的基础任务，标注员理解成本通常低于直接判断复杂隐患，也更容易形成稳定样本。
  - 但这会改变当前知识体系：现有文档把“具体隐患编码”作为 AI 识别目标；若改为物品/安全要素标注，后续需要增加“物品/安全要素 -> 隐患规则 -> 法规/整改建议”的推理或匹配层。
  - 不能把“物品类别”直接塞进现有“隐患库”的四级具体隐患里，否则会混淆“对象是什么”和“问题是什么”两个概念。
  - “告知大模型什么是安全帽、灭火器、脚手架”需要进一步明确训练目标：是训练目标检测模型、微调视觉大模型，还是构建带框样本供后续模型评测。不同目标会影响导出格式和质量标准。
- 当前建议：
  - 第一版标注对象调整为“物品/安全要素”，不直接标注“隐患”。
  - 一张图片支持多个物品/安全要素框；每个框绑定一个物品/安全要素类别。
  - 物品/安全要素类别应独立建库或作为知识体系新增层，不与现有隐患库混放。
  - “无隐患”暂不作为标注标签；如图片中没有任何可标注物品/安全要素，记录为图片级“无可标注对象”。
  - 后续隐患判断通过“物品/安全要素识别结果 + 隐患判定规则/知识库”承接，不在本轮 Q1 中直接定义。
- 已确认结论：
  - 第一版训练目标为目标检测模型训练。
  - 标注任务需要框出物品/安全要素的位置，输出对象类别和坐标。
  - 标注对象为安全帽、灭火器、脚手架等物品/安全要素，不直接标注隐患。
  - 一张图片允许多个物品/安全要素框。
  - “无隐患”不作为标注标签；若图片无可标注物品/安全要素，记录为图片级“无可标注对象”。
  - 该结论后续需拆回知识体系与标注质检 PRD，并影响训练侧导出格式。

#### Q2 沟通记录：标注轮次与质检裁决
- 用户想法：
  - 不限制标注轮次。
  - 质检人员可以手动选择查看经过几个轮次的标注结果。
  - 质检人员基于查看结果决策是否进入高质量数据池。
- 初始评审：
  - 该思路适合目标检测训练数据治理：多轮标注可以沉淀不同人员对同一对象框和类别的判断差异，质检员再基于差异做最终裁决。
  - 相比固定 2 人或 3 人投票，可变轮次更灵活，适合早期类别标准还在校准的阶段。
  - 风险是如果完全不设流程边界，任务可能反复标注、质检成本失控，且“何时可以进入质检”不清晰。
  - 建议把“不限制轮次”理解为“业务上不固定必须几轮”，但系统仍需要记录轮次、标注人、时间、版本、标注结果和质检裁决，避免结果不可追溯。
- 当前建议：
  - 标注任务支持多轮标注，不强制固定为 2 人或 3 人。
  - 每轮标注结果独立留痕，不覆盖上一轮结果。
  - 质检工作台支持查看：最新一轮、指定轮次、全部轮次对比。
  - 质检员可选择某一轮结果作为基础进行修正，也可直接重新绘制标准结果。
  - 质检裁决结果包括：进入高质量数据池、退回继续标注、不入池。
  - 进入高质量数据池时，以质检员确认的“标准框 + 标准类别”为最终入池结果，不直接以某个标注员原始结果入池。
  - 系统应显示轮次差异，例如同一对象类别不一致、框位置偏差明显、漏框/多框，但差异算法可作为辅助，不替代质检员裁决。
- 已确认结论：
  - 标注任务支持多轮标注，不强制固定为 2 人或 3 人。
  - 每轮标注结果独立留痕，不覆盖上一轮结果。
  - 质检工作台支持查看最新一轮、指定轮次和全部轮次对比。
  - 质检员可选择某一轮结果作为基础进行修正，也可重新绘制标准结果。
  - 质检裁决结果包括：进入高质量数据池、退回继续标注、不入池。
  - 进入高质量数据池时，以质检员确认的“标准框 + 标准类别”为最终入池结果，不直接以某个标注员原始结果入池。
  - 系统可辅助显示轮次差异，例如类别不一致、框位置偏差明显、漏框/多框，但差异算法不替代质检员裁决。

#### Q3 沟通记录：质检范围与标准结果生成
- 待讨论点：
  - 质检工作台按图片组织，还是按单个对象框组织。
  - 质检员在裁决阶段是否只能选择某个标注员/某一轮的结果。
  - 质检员是否允许自行新增、修改、删除标注框，并调整对象类别。
- 初始评审：
  - 如果质检员只能选择既有标注结果，最终标准结果会被已有标注质量限制；遇到所有标注员都漏框、框偏差都较大、类别都错时，只能退回，效率低。
  - 目标检测训练需要高质量标准框，质检员应被定义为最终标准结果的责任人，而不只是投票选择人。

##### Q4A 字段及规则草案

###### 1. 列表字段

| 字段 | 展示规则 | 说明 |
|---|---|---|
| 类别名称 | 展示类别中文名称 | 如安全帽、灭火器、脚手架 |

列表不展示数据库内部编码；不展示创建人、创建时间、更新人、更新时间。

###### 2. 类别项字段

| 字段 | 必填 | 规则 | 示例 |
|---|---|---|---|
| 类别内部编码 | 数据库生成 | 全局唯一；创建后不可修改；用户端不展示、不填写；用于训练导出、历史标注映射和系统识别 | - |
| 类别名称 | 是 | 展示给领域工程师、标注员、质检员的中文名称；允许修改，但不得改变内部编码 | 安全帽、灭火器、脚手架 |

###### 3. 属性字段

| 字段 | 必填 | 规则 | 示例 |
|---|---|---|---|
| 所属类别 | 是 | 属性必须归属于一个类别；每个类别至少配置一个属性 | 安全帽 |
| 属性名称 | 是 | 类别下的可选属性；同一类别下属性名称不可重复；标注员只能从领域工程师维护的属性名称中选择，不允许自由输入 | 白色、红色、正常、损坏 |
| 属性状态 | 是 | 枚举：启用、停用；启用属性可用于新标注，停用属性仅用于历史追溯 | 启用 |

###### 4. 维护规则

| 规则项 | 规则 |
|---|---|
| 维护角色 | 仅领域工程师维护类别、属性和属性图片 |
| 类别结构 | MVP 采用平铺类别项列表，暂不做类别组 |
| 类别稳定标识 | 数据库生成内部编码，创建后不可修改；用户端不展示、不填写；如类别名称调整，内部编码仍保持不变 |
| 属性要求 | 每个类别至少配置一个属性；如果暂不需要细分，配置默认属性名称，如 `通用`、`未区分` 或 `默认` |
| 属性唯一性 | 同一类别下属性名称不可重复；不同类别下可存在相同属性名称，如安全帽/红色与警示牌/红色 |

| 属性状态 | 属性支持启用/停用；启用属性可用于新标注，停用属性仅用于历史展示和导出追溯 |
| 删除规则 | 类别和属性不允许物理删除，仅允许停用 |
| 标注可选范围 | 标注下拉只展示启用类别和启用属性 |
| 历史追溯 | 历史标注继续保留原类别内部编码和属性名称；停用后不影响历史展示与导出 |
| 待确认类别 | 标注员遇到缺失类别时选择 `待确认类别`，不直接新增正式类别 |

###### 5. 标注使用规则

| 场景 | 规则 |
|---|---|
| 正常标注 | 标注员框选对象后，必须选择类别和该类别下的属性名称 |
| 类别无可选属性 | 不允许进入标注；类别发布前必须至少配置一个启用属性 |
| 属性无法判断 | MVP 阶段可通过领域工程师配置 `未区分` 属性承接，标注员不得自由输入属性 |

| 入池要求 | 入高质量数据池的标准结果必须有正式类别和正式属性；`待确认类别` 不可直接入池 |

##### Q8-1 标注任务列表

###### 需求背景
- 标注任务列表是标注员进入标注工作的任务入口。
- 标注任务的最小处理对象是图片，而不是项目或巡查记录。
- 标注员需要先通过缩略图快速识别图片，再进入标注工作台处理。

###### 设计目标
| 目标 | 说明 |
|---|---|
| 快速找图 | 用图片网格展示任务，降低表格扫图成本 |
| 区分任务池 | 用状态统计卡片区分全部、待标注、已标注、待确认类别、质检退回、无效图片 |
| 支持重标 | 待确认类别、质检退回图片可以重新进入标注 |
| 控制信息密度 | 卡片只展示标注员处理任务所需的最小信息 |

###### 方案取舍
| 方案 | 优点 | 问题 | 结论 |
|---|---|---|---|
| 表格列表 | 字段承载能力强 | 图片缩略图弱，标注员扫图效率低 | 不采用 |
| 图片网格卡片 | 图片优先，适合标注任务入口 | 项目信息、时间、轮次等字段需收敛 | 采用 |

###### 任务来源规则
| 规则项 | 规则 |
|---|---|
| 阶段粒度 | 标注阶段按 `标注任务` 处理，质检阶段按 `图片` 处理 |
| 标注任务 | 标注任务是图片与标注员的关系记录；同一图片分配给不同标注员时，生成多条标注任务 |
| 质检任务 | 质检任务是图片级汇总记录；同一图片只生成一条质检任务，汇总多个标注员结果 |
| 图片来源 | 标注任务图片来源为巡查记录图片，包括 App 上传和后台上传 |
| 生成粒度 | 每张巡查图片按分配人生成标注任务；同一图片保留统一图片 ID，可关联多份人员标注结果 |
| 项目类型 | 图片继承关联项目的项目类型，用于列表展示和筛选 |
| 排除来源 | 类别库维护图片、知识库图片不进入标注任务 |
| 删除影响 | 已删除巡查图片不再进入标注任务；已删除巡查图片对应未入池任务置为不可标注/已失效 |
| 入池后追溯 | 已入池图片的删除追溯口径后续在数据池规则中确认 |

###### 状态卡片规则
| 规则项 | 规则 |
|---|---|
| 状态卡片 | 页面顶部用状态统计卡片展示任务池和数量 |
| 状态范围 | 全部、待标注、已标注、待确认类别、质检退回、无效图片 |
| 状态口径 | 状态统计按当前标注员可见的标注任务记录计数，不按图片去重 |
| 默认状态 | 默认选中 `全部` |
| 切换行为 | 状态卡片作为点击切换入口，当前选中状态高亮 |
| 数量统计 | 状态卡片数量受项目类型筛选影响 |

###### 筛选规则
| 筛选项 | 规则 |
|---|---|
| 项目类型 | 沿用项目管理选项：住宅装修、小型工程、零星作业 |
| 是否无可标注对象 | 仅在 `已标注` 状态下展示筛选项，选项为全部、是、否 |
| 查询 | 按当前状态卡片和项目类型筛选刷新网格 |
| 重置 | 清空项目类型筛选，状态卡片恢复 `全部` |

###### 卡片展示规则
| 元素 | 展示规则 |
|---|---|
| 图片缩略图 | 必须展示，作为卡片主视觉 |
| 项目类型 | 展示图片关联项目的项目类型 |
| 标注状态 | 不在图片卡片内展示，当前状态由顶部状态卡片表达 |
| 草稿标签 | 存在已保存未提交内容时展示 `有草稿` 标签 |
| 无可标注对象标签 | 提交为 `无可标注对象` 的图片，在 `已标注` 状态下展示 `无可标注对象` 标签 |
| 无效图片标签 | 标记为无效图片的标注任务，在 `无效图片` 状态下展示无效原因 |
| 进入方式 | 不展示操作按钮，点击图片卡片任意位置进入标注工作台 |

| 不展示项 | 不展示项目名称、巡查时间和标注轮次 |

###### 权限规则
| 角色 | 规则 |
|---|---|
| 标注员 | 查看分配给自己的标注任务 |
| 管理员 | 有删除权限 |
| 其他角色 | 按后台角色权限配置 |
| 普通标注员 | 不展示删除入口 |

###### 排序、分页与空状态
| 规则项 | 规则 |
|---|---|
| 默认排序 | 按任务更新时间倒序 |
| 特殊排序 | 质检退回和待确认类别按最近更新时间靠前 |
| 分页 | 默认每页 24 张，支持分页 |
| 无任务空状态 | 当前状态无任务时显示“当前暂无待处理图片” |
| 筛选无结果 | 显示“未找到符合条件的图片，请调整筛选条件” |

###### 保存、提交与状态流转
| 场景 | 规则 |
|---|---|
| 保存草稿 | 保存当前编辑内容；保存后仍留在当前图片 |
| 草稿定义 | 用户点击保存后，保存内容尚未成功提交，即存在草稿 |
| 草稿展示 | 可编辑状态下存在草稿时，标注任务卡片展示 `有草稿` |
| 待标注保存 | 无 `待确认类别` 时保持 `待标注`；含 `待确认类别` 时进入 `待确认类别` |
| 待确认类别保存 | 保持 `待确认类别`，并展示 `有草稿` |
| 质检退回保存 | 保持 `质检退回`，并展示 `有草稿` |
| 正式提交 | 所有对象均完成正式类别级联后，提交进入 `已标注`，清除草稿 |
| 待确认提交 | 含 `待确认类别` 时不允许提交，提示先补齐正式类别 |
| 字段缺失 | 存在未完成类别级联的对象时不允许提交 |
| 进入质检 | MVP 阶段同一图片只要存在一份正式类别完整的正常标注结果，即进入质检任务池 |
| 后续轮次 | 图片进入质检后，后续新增正常标注结果继续汇总到同一图片质检任务下 |
| 不进质检 | `待确认类别` 不进入质检任务池；单个标注员提交的 `无效图片` 结果不单独进入质检 |

###### 无可标注对象
| 规则项 | 规则 |
|---|---|
| 定义 | 标注员认为当前图片有效，但没有当前类别库需要标注的物品/安全要素 |
| 结果性质 | `无可标注对象` 是单个标注员的标注结果，不直接代表图片全局无对象 |
| 入口 | 不单独展示按钮，通过 `提交标注` 处理 |
| 触发 | 当前图片无标注对象时点击 `提交标注` |
| 弹窗标题 | `确认无可标注对象？` |
| 弹窗正文 | `当前图片未添加任何标注对象。确认后，系统将把该图片记录为“无可标注对象”，并进入下一张图片。` |
| 勾选项 | `我知道了，以后不显示`，勾选后后续无对象提交不再弹出提示 |
| 确定 | 提交为 `无可标注对象`，进入 `已标注`，自动进入下一张 |
| 取消 | 关闭弹窗，停留当前图片，不提交 |
| 列表展示 | 已标注列表展示 `无可标注对象` 标签，并支持筛选 |
| 多人标注 | 同一图片若同时存在无可标注对象和正常标注结果，仍按正常标注结果进入质检 |
| 后续边界 | 单个无可标注对象结果是否参与质检展示/入池，在 Q8-3/Q8-4 继续确认 |

###### 无效图片
| 规则项 | 规则 |
|---|---|
| 定义 | 标注员认为当前图片不适合标注或进入训练链路 |
| 结果性质 | `无效图片` 是单个标注员的标注结果，不直接代表图片全局无效 |
| 入口 | 顶部操作区展示 `标记无效` |
| 原因 | 必选：图片质量差、图片损坏/无法加载、内容无关、非施工现场、遮挡严重、重复图片、截图/拼图/水印干扰、其他 |
| 其他原因 | `其他` 仅作为固定选项之一，不需要填写备注 |
| 弹窗标题 | `确认标记为无效图片？` |
| 标记影响 | 确认标记无效后，清空当前草稿和已绘制标注对象 |
| 流转 | 标记后进入 `无效图片` 状态 |
| 多人标注 | 同一图片可同时存在正常标注、无可标注对象、无效图片等不同人员结果 |
| 进入质检 | 同一图片只要存在正常标注结果，仍进入质检；质检页展示正常标注结果和无效标记记录 |
| 后续 | 单个无效图片结果不直接进入质检任务池、不进入高质量数据池、不参与训练导出 |
| 最终无效 | 图片最终是否判为无效，由质检员/管理员在后续裁决阶段确认 |
| 查看 | 在标注任务列表 `无效图片` 状态卡查看，进入工作台后只读展示无效原因 |
| 恢复 | 标注员可将无效图片恢复为 `待标注` 状态，恢复后可重新标注 |
| 恢复追溯 | 恢复后原无效记录保留为操作日志，不作为当前有效标注结果 |

##### Q8-3 质检任务列表

###### 需求背景
- 质检任务列表是质检员进入质检工作的任务入口。
- 质检对象按图片组织，质检员进入详情后查看多轮标注结果并生成标准结果。
- 标注阶段按标注任务处理，质检阶段按图片处理；同一图片只生成一条图片级质检任务。
- 质检任务 MVP 阶段接收存在至少一份正常标注结果的图片，不接收仅有 `待确认类别` 或仅有 `无效图片` 结果的图片。
- 同一图片若同时存在正常标注和无效图片结果，仍进入质检，质检员可查看无效标记记录。
- 图片进入质检后，后续新增正常标注结果继续汇总到同一图片质检任务下。

###### 设计目标
| 目标 | 说明 |
|---|---|
| 找到待质检图片 | 让质检员快速看到需要处理的图片任务 |
| 区分质检状态 | 区分待质检、已质检、退回、不入池等处理结果 |
| 查看标注轮次 | 展示图片已有标注轮次，辅助判断标注充分度 |
| 进入质检工作台 | 点击图片任务进入质检详情，查看多轮结果并裁决 |

###### 页面初始建议
| 规则项 | 建议 |
|---|---|
| 展示方式 | 采用图片网格卡片，延续标注任务列表体验 |
| 任务来源 | MVP 阶段同一图片存在至少一份正常标注结果时进入质检任务池 |
| 后续汇总 | 图片进入质检后，后续新增正常标注结果继续汇总，不重复生成图片级质检任务 |
| 排除来源 | 仅有 `待确认类别`、仅有 `无效图片` 或无正常标注结果的图片不进入质检任务池 |
| 无效记录展示 | 若同一图片同时存在无效图片结果，质检工作台需展示无效标记人、原因、时间 |
| 状态卡片 | 顶部展示 `全部`、`待质检`、`已质检`、`退回`、`不入池` |
| 默认状态 | 默认选中 `待质检` |
| 筛选项 | 项目类型、标注轮次 |
| 卡片字段 | 图片缩略图、项目类型、标注轮次、草稿标签 |
| 卡片入口 | 点击整张卡片进入质检工作台 |
| 不展示项 | 不展示项目名称、巡查时间 |
