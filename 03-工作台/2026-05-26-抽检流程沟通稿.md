# 抽检流程沟通稿

## 文档定位
- 本文档只用于单独沟通 `抽检流程`，不替代正式 PRD，不承载页面字段、权限矩阵或完整交互主定义。
- 抽检功能的完整需求草案仍以 [2026-05-26-抽检业务功能-需求沟通.md](2026-05-26-抽检业务功能-需求沟通.md) 为准。
- 本文档重点回答：抽检在整体业务里的位置、抽检从哪里来、怎么执行、发现问题后怎么处理、结果怎么进入考核与复盘。

## 一、流程定位

### 1. 抽检不是第四轮质检
- 当前主质检链路仍然是：`标注提交 -> 一检 -> 二检 -> 三检`。
- 抽检不插入这条主链路中间，也不替代任何一轮的主裁决职责。
- 抽检定位为：`主质检链路完成后的独立质量校准机制`。

### 2. 抽检要解决的问题
- 对已完成样本做二次质量校准，验证主链路结果是否稳定。
- 对高风险样本、异常裁决结果、重点人员结果做专项复核。
- 为三检或专项人员考核提供独立数据来源。
- 为后续返工、复盘、培训和规则优化提供问题样本与证据。

### 3. 抽检与主流程的关系
| 项目 | 主质检链路 | 抽检 |
|---|---|---|
| 定位 | 生产主流程 | 结果后的独立校准旁路 |
| 目标 | 形成正式裁决结果 | 复核质量、发现风险、形成考核与复盘输入 |
| 触发时机 | 样本进入生产处理时 | 主链路完成后 |
| 是否直接决定入池 | 是 | 否，抽检只做校准与问题发现 |
| 是否可触发后续动作 | 是 | 是，可触发回流建议或复盘动作 |

## 二、流程总览

### 1. 流程一句话概括
`主流程完成 -> 产生抽检候选 -> 发起抽检任务 -> 分配抽检人 -> 逐对象复核 -> 提交抽检结论 -> 必要时标记回流 -> 任务完成 -> 进入统计 / 考核 / 复盘`

### 2. 流程图（沟通版）
```text
主质检链路完成
    ↓
进入抽检候选范围
    ↓
质量负责人发起抽检任务
    ↓
分配抽检执行人
    ↓
抽检人逐对象复核
    ↓
提交抽检结论
    ├─ 无明显问题 → 记录结论
    ├─ 一般问题   → 记录问题标签，纳入复盘/培训
    └─ 严重问题   → 标记回流建议，进入后续处理
    ↓
任务内对象全部处理完成
    ↓
抽检任务完成
    ↓
进入专项考核统计 / 质量复盘 / 规则优化
```

## 三、流程分步骤说明

### 步骤 1：主质检链路完成
- 前提是样本已经走完标注、一检、二检、三检。
- 抽检只处理“主流程已经有结果”的样本，不介入主流程中的待处理样本。
- 当前建议可进入抽检候选的来源包括：
  - 已入池样本
  - 已结束未入池样本
  - 风险命中样本

### 步骤 2：产生抽检候选
- 系统或人工先圈定可抽检范围。
- 候选对象建议沿用主流程已有的 `对象粒度`，不重新造一个新的评分对象。
- 这一步的核心不是直接开始审核，而是先把“哪些结果值得再看一遍”圈出来。

### 步骤 3：发起抽检任务
- 由质量负责人或抽检管理员发起。
- 发起时至少要确定：
  - 抽检类型
  - 抽检范围
  - 候选对象来源
  - 执行人
  - 任务说明（可选）
- 如果当前条件下没有候选对象，不允许创建空任务。

### 步骤 4：分配抽检执行人
- 抽检任务创建后，进入 `待分配` 或 `待抽检`。
- 已明确执行人的，可直接进入 `待抽检`。
- 未明确执行人的，需要先分配，再进入处理阶段。
- 已完成或已关闭的任务不可重新分配。

### 步骤 5：抽检人逐对象复核
- 抽检人在任务详情页按对象逐条处理。
- 每个对象至少要能看到：
  - 原始样本
  - 标注信息
  - 原裁决链摘要
  - 当前对象已有处理痕迹
- 抽检的核心动作是“重新判断当前结果是否站得住”，不是在抽检页直接改主流程结果。

### 步骤 6：提交抽检结论
- 抽检人对每个对象提交结论。
- 当前沟通稿里的建议字段包括：
  - 抽检结论
  - 问题标签
  - 严重程度
  - 差异说明
  - 建议动作
- 提交后，对象状态从 `待处理` 变为：
  - `已提交结论`
  - 或 `需回流处理`

### 步骤 7：发现严重问题时标记回流
- 如果抽检发现的是严重问题，不在抽检环节直接改主流程最终结果。
- 抽检只负责：
  - 记录回流原因
  - 记录回流去向
  - 记录责任建议
- 后续是否自动创建返工任务，当前不在首版默认范围内。
- 这一步的原则是：`抽检负责发现问题和提出后续动作，不直接吞并主流程职责`。

### 步骤 8：任务完成
- 当任务内所有对象都处理完成后，任务才能标记为 `已完成`。
- 只要还有未处理对象，就不能完成任务。
- 任务完成意味着：本次抽检复核已经有完整留痕，可进入后续统计和复盘。

### 步骤 9：进入统计、考核与复盘
- 已完成抽检任务进入抽检统计范围。
- 后续可输出的结果包括：
  - 抽检覆盖量
  - 问题命中率
  - 回流率
  - 人员准确率
  - 典型问题分布
- 这些结果主要服务于：
  - 三检或专项人员考核
  - 质量复盘
  - 培训优化
  - 规则优化

## 四、流程里的关键判断

### 1. 什么样的样本进入抽检
- 当前建议：`已入池`、`已结束未入池`、`风险命中样本` 都可以进入候选范围。
- 这里的关键不是“再做一轮普查”，而是“有目的地做质量校准”。

### 2. 抽检的最小处理粒度是什么
- 当前默认建议沿用主流程 `对象粒度`。
- 原因：
  - 能直接复用主流程的责任口径。
  - 能定位具体问题对象。
  - 便于后续统计、回流和专项考核。
- 如果提升到整图或整任务粒度，会让问题定位和后续追责变粗。

### 3. 抽检发现问题后怎么处理
- 当前默认方案不是在抽检里直接重写主流程结果。
- 更稳的做法是分层处理：
  - 小问题：记录结论即可
  - 一般问题：记录问题标签，纳入复盘 / 培训
  - 严重问题：标记回流建议，进入后续处理

### 4. 抽检结果是否直接进入人员考核
- 当前方向是“可以作为专项考核输入”，尤其承接三检专项考核。
- 但考核公式和是否直接生成最终考核结论，建议放第二阶段确认。

## 五、流程状态流

### 1. 抽检任务状态
| 状态 | 含义 | 进入条件 | 退出条件 |
|---|---|---|---|
| 待分配 | 任务已创建但未明确执行人 | 发起任务后未指定执行人 | 分配执行人 |
| 待抽检 | 已有执行人，待开始处理 | 发起任务并已指定执行人 | 开始处理对象 |
| 抽检中 | 任务内对象已开始处理 | 至少一个对象进入处理 | 所有对象处理完成 |
| 已完成 | 本次抽检任务处理结束 | 所有对象已提交结论或明确忽略 | 进入统计/归档 |
| 已关闭 | 任务被主动关闭 | 人工关闭 | 通常不再继续流转 |

### 2. 抽检对象状态
| 状态 | 含义 | 进入条件 | 退出条件 |
|---|---|---|---|
| 待处理 | 尚未提交抽检结论 | 任务创建后生成对象 | 提交结论 |
| 已提交结论 | 已完成抽检判断 | 提交普通结论 | 需要修正时保留修订记录 |
| 需回流处理 | 抽检判断存在严重问题 | 提交回流建议 | 进入后续闭环 |
| 已忽略 | 本次不再处理 | 人工明确忽略 | 通常不再流转 |

## 六、流程产出物
| 阶段 | 产出物 | 用途 |
|---|---|---|
| 发起任务 | 抽检任务 | 作为抽检执行载体 |
| 生成候选 | 抽检对象 | 作为逐条复核单元 |
| 提交结论 | 抽检结论、问题标签、严重程度 | 留痕、统计、复盘 |
| 标记回流 | 回流建议记录 | 进入后续返工或专项复盘 |
| 任务完成 | 统计聚合结果 | 支撑考核、培训、规则优化 |

## 七、当前建议口径
- 抽检按 `独立质量校准机制` 设计，不进主流程状态机。
- 抽检默认沿用主流程 `对象粒度` 做复核。
- 第一版先做 `任务闭环`，统计页可以作为第二阶段。
- 第一版对严重问题先做 `回流建议留痕`，是否自动打通返工闭环后续再定。

## 八、待确认问题
| 编号 | 问题 | 当前建议 |
|---|---|---|
| Q1 | 第一版抽检类型保留哪些枚举 | 先保留 `随机抽检 / 风险抽检 / 专项抽检` |
| Q2 | 候选范围是否同时覆盖 `已入池` 与 `已结束未入池` | 默认同时覆盖 |
| Q3 | 抽检问题回流是“只记录建议”还是“必须自动闭环” | 默认先记录建议 |
| Q4 | 三检专项考核是否第一版同步做统计页 | 默认第二阶段再做 |
| Q5 | 回流去向是回到一检、二检、三检还是进入独立复盘池 | 待结合主流程闭环再定 |
