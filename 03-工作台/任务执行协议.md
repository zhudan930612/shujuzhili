# 任务执行协议

## 文档定位
- 本文件定义 AI 或人工处理常见产品设计任务时“怎么完成一类任务”。
- 本文件不承载业务主定义，不替代正式 PRD、产品架构、业务流程或归档决策。
- 任务执行时应先找到主定义，再判断影响范围，最后同步受影响资产。

## Harness 定义
- 本仓库 Harness = `AGENTS.md` + 目录 README + 任务执行协议 + 任务完成检查 + 工具脚本 + 人工确认点。
- `AGENTS.md`：顶层规则和目录地图。
- 目录 README：局部规则和资产归位。
- 任务执行协议：任务开始前的流程引导。
- 任务完成检查：任务结束前的收尾检查。
- [../06-工具脚本/check_docs.py](../06-工具脚本/check_docs.py)：结构性机械检查。
- 人工确认点：业务取舍、产品范围、权限规则、法规匹配、页面交互。

## 通用执行顺序
| 步骤 | 动作 | 输出 |
|------|------|------|
| 1 | 理解输入 | 明确用户诉求、来源资料、约束和待解决问题 |
| 2 | 查找主定义 | 找到业务规则、页面规则、字段规则或流程规则所在主文档 |
| 3 | 评审合理性 | 指出完整性、边界条件、潜在问题和可替代方案 |
| 4 | 更新目标文档 | 只在主定义或当前阶段应承载的文档中修改 |
| 5 | 同步受影响资产 | 检查 PRD、原型、模板、流程图、归档记录之间的影响 |
| 6 | 完成检查 | 按 [任务完成检查.md](任务完成检查.md) 做收尾验证 |

## 中间产物保留规则
- 复杂文档任务应保留关键中间判断，而不是只保留最终 PRD。
- 应保留的中间判断包括：需求背景、约束、方案取舍、评审意见、修订原因、待确认问题。
- 中间判断优先进入 [当前需求沟通文档.md](当前需求沟通文档.md) 或 [评审记录.md](评审记录.md)。
- 稳定规则必须拆回正式 PRD、产品架构、业务流程或归档记录。
- 过程文档只保留判断依据、取舍摘要和链接，不长期承载完整主定义。

## 需求沟通落地闭环
- 需求沟通中出现明确结论、待确认问题、方案取舍、用户否定项时，必须写入文档，不只停留在对话中。
- 过程讨论优先写入 [当前需求沟通文档.md](当前需求沟通文档.md)；评审性复盘优先写入 [评审记录.md](评审记录.md)。
- 稳定规则必须拆回正式 PRD、产品架构、业务流程或归档记录。
- 每个复杂需求专题必须维护“拆回正式文档清单”，记录结论、主定义文档、影响资产、状态和备注。
- 未拆回前，过程文档可承载阶段性结论；拆回后，过程文档只保留摘要、原因和链接。
- 落地状态统一使用：`待确认`、`沟通中`、`已确认`、`待拆回`、`已拆回`、`待归档`、`已归档`、`已拒绝`。

## 任务类型协议
| 任务类型 | 输入 | 必须阅读 | 主要产出 | 完成标准 |
|---|---|---|---|---|
| 新需求沟通 | 用户描述、会议记录、来源资料 | [需求池.md](需求池.md)、[当前需求沟通文档.md](当前需求沟通文档.md)、[../00-项目总览/业务上下文.md](../00-项目总览/业务上下文.md) | 当前需求沟通文档更新 | 有背景、问题、取舍、待确认项 |
| 稳定结论拆回 PRD | 已确认需求结论 | [../01-产品架构/模块地图.md](../01-产品架构/模块地图.md)、对应 PRD、[当前需求沟通文档.md](当前需求沟通文档.md) | 正式 PRD 更新 | 字段、页面、规则进入主定义 |
| PRD 页面调整 | 页面规则变更 | 对应 PRD、[../01-产品架构/模块地图.md](../01-产品架构/模块地图.md)、相关原型 | PRD 更新 | 不重复定义，引用有效 |
| 后台原型调整 | PRD、参考图、页面需求 | [../AGENTS.md](../AGENTS.md)、[../04-原型效果图/后台管理/assets/README.md](../04-原型效果图/后台管理/assets/README.md)、组件预览、对应 PRD | HTML 原型更新 | 复用公共组件，风格一致 |
| Excel 模板调整 | 导入字段或校验规则 | 对应 PRD、[../04-原型效果图/后台管理/模板文件/README.md](../04-原型效果图/后台管理/模板文件/README.md)、已有模板 | Excel 模板更新 | 字段、说明、格式与 PRD 一致 |
| 决策归档 | 已完成或变更的产品决策 | [当前需求沟通文档.md](当前需求沟通文档.md)、相关 PRD | 归档记录更新 | 说明原因、取舍和影响范围 |

## 执行约束
- 过程文档用于承接讨论，不长期承担业务规则主定义。
- 稳定结论应拆回最靠近判断逻辑的正式文档。
- 同一规则不得在多个文档重复完整展开。
- 任务完成前必须检查是否影响 PRD、原型、模板、流程图或归档记录。
