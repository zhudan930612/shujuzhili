# 数据治理平台产品总览

## 文档定位
- 本文档定义产品架构层的整体边界。
- 本文档负责说明系统由哪些模块组成、涉及哪些端，以及各类文档如何分工。
- 具体页面规则以对应模块主 PRD 内的页面章节为准。

## 当前产品范围
当前产品围绕“采集 -> 治理 -> 沉淀 -> 反哺 AI”这条主链展开，覆盖两个核心端：
- App：巡查员使用移动设备进行现场或事后图片上传，并查看个人巡查信息。
- 后台管理系统：运营、标注、质检、知识库维护和系统配置使用。

## 模块划分
- 项目管理：承接项目主数据、支撑项目列表、创建、编辑、导入和详情查看。
- 巡查管理：承接巡查员采集链路和后台巡查记录管理。
- 知识库管理：承接隐患库与法规库的后台页面维护能力。
- 知识体系设计：承接隐患库、法规库、案例库及报告生成的知识结构设计（知识层）。
- 系统管理：承接后台字典配置等系统基础能力。

## 文档分工
- 模块主 PRD：按端内模块整合文档定位、模块边界、通用规则、页面清单、页面设计和跨页面数据流。\n- 页面章节：作为模块主 PRD 内章节，定义页面字段、状态、交互、异常、入口出口，是页面规则主定义。
- 知识层文档：定义长期稳定的知识结构和编码体系，不承载页面交互主定义。
- 资产目录：只保存 HTML 原型和 Excel 模板，不承担规则主定义；业务流程主图单独维护在 [../02-业务流程.mmd](../02-业务流程.mmd)。

## 维护原则
- 页面变化默认只改对应模块主 PRD 内的页面章节，不在其他文档重复定义。
- 端内模块职责或端划分改变时，更新对应端目录下的模块主 PRD。
- 流程变化只有在角色流转或步骤顺序变化时才改 [../02-业务流程.mmd](../02-业务流程.mmd)。
- 业务定位、术语和长期约束只在 [../01-上下文.md](../01-上下文.md) 中维护。
