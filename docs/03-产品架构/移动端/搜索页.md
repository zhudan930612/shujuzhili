## 设计内容
**页面用途**：从项目列表页点击搜索框进入，支持按项目名称搜索，展示搜索历史和搜索结果。

**页面布局**：

```
┌─────────────────────────────┐
│ ← 搜索                      │
├─────────────────────────────┤
│  ┌─────────────────────┐   │
│  │ 🔍 请输入项目名称 [搜索]│   │
│  └─────────────────────┘   │
│  搜索历史          [清空]   │
│  ┌─────────────────────┐   │
│  │ ┌────┐ ┌────┐       │   │
│  │ │万科│ │前海│ ...   │   │
│  │ └────┘ └────┘       │   │
│  └─────────────────────┘   │
└─────────────────────────────┘
```

**搜索历史功能**：
- 历史标签点击直接搜索
- 清空历史需二次确认
- 最多保存10条
- 搜索成功后才保存

**搜索结果**：与项目列表样式一致，支持筛选
**空状态**：显示"未找到相关项目"

**时间轴设计说明**：

| 元素 | 说明 |
|------|------|
| **● 日期节点** | 实心圆点标记日期，同一天的多条记录共享一个日期节点 |
| **│ 时间线** | 竖线连接同一天内的多次巡查记录 |
| **时间** | 精确到分钟，显示在日期下方 |
| **项目信息** | 缩进显示，包含项目名称、地址、图片数量 |
| **同一天多次巡查** | 以空心圆○标记，缩进对齐显示 |

**时间轴样式规则**：

| 场景 | 展示方式 |
|------|---------|
| **不同日期** | 新的●日期节点，与前一条记录有明显间距 |
| **同一天多次** | 共享日期，用│连接，下方以○标记具体时间 |
| **最新记录** | 最上方，●节点可高亮（如蓝色或加粗）|
| **历史记录** | 正常显示，按时间倒序排列 |

**排序规则**：按巡查时间**倒序排列**（最新的巡查记录在最上面）。

**巡查记录判定规则**：

巡查记录以**完整上传会话**为粒度进行区分，具体规则如下：

| 规则项 | 说明 |
|--------|------|
| **会话开始时机** | 用户从项目详情页发起一次新的上传操作，且当前项目下不存在草稿或失败记录 |
| **记录创建条件** | 当前上传会话内至少1张图片成功上传，即生成一条巡查记录 |
| **同一项目多次巡查** | 同一项目可有多次独立巡查；仅当前一上传会话已完成或被清空后，下一次上传才生成新记录 |
| **失败重传处理** | 同一会话内如部分图片上传失败，失败图片后续重传成功时补入原巡查记录，不生成新记录 |
| **草稿处理** | 草稿仅表示未完成会话，不生成巡查记录；草稿后续上传成功时归入当前会话对应的巡查记录 |

**场景示例**：
- 场景1：巡查员A对项目X进行巡查，一次性上传15张图片全部成功 → 生成1条巡查记录（15张）
- 场景2：巡查员A对项目X巡查，选择20张图片上传，因网络问题仅10张成功 → 先生成1条巡查记录；剩余10张稍后在待上传页重传成功 → 补入原巡查记录，不新增记录
- 场景3：巡查员A周一巡查项目X上传8张，周三再次巡查同一项目上传12张 → 生成2条独立巡查记录

**设计理由**：
- 保持“一次巡查 = 一次完整上传会话”的用户心智，避免同一次巡查被拆成多条记录
- 网络不稳定场景下，成功数据可先入库，失败图片后续补齐，不影响巡查次数统计
- 草稿、失败、重传都围绕同一未完成会话处理，业务边界更清晰
