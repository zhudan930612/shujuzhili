# 数据治理平台业务背景文档

> **文档用途**：回答"为什么要做数据治理平台"，为产品决策提供战略依据

---

## 一、业务定位与价值链

### 1.1 角色定位

```
┌──────────────┐      ┌──────────────┐      ┌──────────────┐
│   施工单位    │─────→│   保险公司    │─────→│ 我方（第三方）│
│  （被保险人）  │      │ （采购服务方） │      │（服务执行方）  │
└──────────────┘      └──────────────┘      └──────────────┘
                                                        ↓
                                                ┌──────────────┐
                                                │  巡查人员    │
                                                │（现场执行）   │
                                                └──────────────┘
```

### 1.2 核心价值链

| 环节 | 主体 | 动作 | 产出 |
|------|------|------|------|
| 投保 | 施工单位 | 购买安责险 | 保险合同 |
| 采购 | 保险公司 | 购买事故预防服务 | 服务订单 |
| 执行 | 我方 | 安排巡查人员现场服务 | 巡查记录/图片 |
| 交付 | 我方 | 出具巡检报告 | 报告文档 |
| 闭环 | 保险公司 | 向施工单位反馈整改 | 风险降低 |

### 1.3 业务本质与战略决策

> **核心命题**：通过现场巡查采集隐患数据，经过**高质量的数据治理**（多轮标注、审核、校准），形成**可复用的数字资产**，支撑**AI隐患识别**及其他未来数据应用场景，最终实现从劳动密集型服务向技术驱动型产品的商业模式跃迁。

#### 核心价值定义

| 层级 | 价值 | 说明 |
|------|------|------|
| **直接价值** | 知识沉淀与复用 | 将巡查员个人经验转化为可复用的知识库（隐患类型、法规、整改建议） |
| **中期价值** | 服务提效 | 规范化报告输出，提高交付质量和效率，降低对个别专家的依赖 |
| **长期价值** | AI能力构建 | 积累高质量训练数据，支撑AI隐患识别模型开发，形成技术壁垒 |

#### 战略决策依据

**数据治理作为核心壁垒的决策逻辑**：

| 维度 | 决策依据 |
|------|----------|
| **数据应用场景** | 未来数据的核心应用场景是AI隐患识别，质量直接决定模型效果 |
| **质量决定效果** | 高质量数据通过数据治理保证，给AI训练的数据必须没问题 |
| **商用价值** | 只有数据质量达标，才能确保AI隐患识别工具的准确性及商用价值 |
| **竞争壁垒** | 行业数据是瓶颈而非算法，先建立数据壁垒者占据先发优势 |

**自建平台而非采购现成工具的决策逻辑**：

| 维度 | 决策依据 |
|------|----------|
| **核心战略** | 公司核心战略是沉淀数据资产，必须将数据掌握在自己服务器上 |
| **改造成本** | 通用工具需二次改造，投入产出比低，且无法满足行业特定需求 |
| **数据安全** | 使用第三方工具，数据沉淀在别人平台，不利于公司长期发展 |
| **定制需求** | 多轮标注、校准机制、法规关联等行业需求无法被通用工具满足 |

## 二、外部驱动与战略必要性

### 2.1 政策背景：安责险的强制性要求

#### 安责险制度演进

| 时间 | 政策文件 | 核心要求 | 影响 |
|------|----------|----------|------|
| 2006年 | 《国务院关于保险业改革发展的若干意见》 | 首次提出建立安全生产责任保险制度 | 制度萌芽 |
| 2016年 | 中共中央 国务院《关于推进安全生产领域改革发展的意见》 | **在高危行业领域强制实施安全生产责任保险** | 从自愿到强制 |
| 2019年 | 应急管理部《安全生产责任保险实施办法》 | 明确保险公司应提供**事故预防服务**，费用不低于保费21% | 明确服务标准 |
| 2021年 | 新《安全生产法》修订 | **高危行业企业必须投保安责险**，否则将面临罚款 | 法律强制 |
| 2023年 | 住建部《关于在房屋市政工程领域推进安全生产责任保险的实施意见》 | 小散工程纳入监管范围，要求实现安责险全覆盖 | 市场扩大 |

#### 政策带来的刚性需求

```
政策链条
─────────
新《安全生产法》强制投保
        ↓
施工单位必须购买安责险
        ↓
保险公司必须提供事故预防服务（≥21%保费）
        ↓
需要专业第三方执行现场巡查
        ↓
巡查质量影响保险公司赔付率
```

**关键洞察**：
- **政策不是可选项，是必选项**：高危行业企业不投保即违法，保险公司不提供服务即违规
- **市场空间确定**：只要有高危行业企业存在，就持续存在事故预防服务需求
- **质量要求提升**：监管部门对事故预防服务的检查日趋严格，形式化服务难以为继

### 2.2 行业趋势：从"事后赔付"到"事前预防"

#### 保险行业转型压力

| 趋势 | 说明 | 数据支撑 |
|------|------|----------|
| **赔付率上升** | 建筑施工安全事故频发，安责险赔付压力增大 | 部分保险公司安责险赔付率超过80%，接近盈亏平衡点 |
| **监管趋严** | 银保监会对保险公司事故预防服务有明确考核 | 未按要求提供服务将被行政处罚 |
| **竞争加剧** | 安责险市场参与者增多，价格战压缩利润空间 | 纯保费竞争难以为继 |
| **技术赋能** | 头部保险公司开始探索科技降本路径 | 平安、人保等已试点AI风控 |

#### 事故预防服务的价值重构

```
传统模式                          新模式
─────────                        ─────────
投保 → 出险 → 赔付              投保 → 预防 → 降险 → 少赔/不赔
     ↓                                  ↓
 成本中心                          风险管理伙伴
     ↓                                  ↓
 被动赔付                          主动干预
     ↓                                  ↓
 不可控成本                        可控投入，ROI可计算
```

**核心转变**：
- **保险公司诉求**：从"出了事能赔"转向"尽量不出事"，事故预防服务从合规成本变为风险管理投资
- **服务质量要求**：从"有报告就行"转向"真能降低事故率"，巡查质量直接影响保单利润
- **数据驱动决策**：保险公司需要可量化的风控效果，支撑精算模型和定价策略

### 2.3 竞争格局：机会窗口与差异化定位

#### 市场参与者分析

| 参与者类型 | 代表 | 优势 | 劣势 | 我们的机会 |
|------------|------|------|------|------------|
| **传统安全咨询公司** | 各地安监系统下属机构、安全评价公司 | 行业经验丰富，政府关系深厚 | 缺乏技术能力，服务模式传统，难以规模化 | 用技术+数据建立效率壁垒 |
| **保险公估公司** | 泛华公估、中衡公估等 | 与保险公司合作紧密，查勘网络覆盖广 | 缺乏施工领域专业能力，事故预防非主业 | 垂直深耕施工安全领域 |
| **互联网安全平台** | 各类安全生产SaaS | 技术能力较强，产品化程度高 | 缺乏线下执行能力，"最后一公里"无法落地 | 线上数据治理+线下巡查执行闭环 |
| **AI创业公司** | 各类计算机视觉公司 | AI技术先进，算法能力强 | 缺乏行业数据，模型无法落地 | 用数据治理积累训练数据，反向赋能AI |

#### 我们的差异化定位

```
                        技术能力
                           ↑
                           │
         AI创业公司 ───────┼─────── 我们
         （有技术）         │        （数据+技术）
                           │
    ───────────────────────┼────────────────────────→ 线下执行能力
                           │
         传统咨询公司 ─────┼─────── 保险公估
         （有执行）         │        （有网络）
                           │
                           ↓
                      互联网安全平台
                      （有产品，无执行）
```

**核心竞争优势构建路径**：

1. **短期（6-12个月）**：通过数据治理平台，建立巡查质量标准和数据资产壁垒
2. **中期（1-2年）**：基于高质量数据训练AI模型，实现隐患识别的半自动化
3. **长期（2-3年）**：AI隐患识别产品化，从服务提供商升级为技术解决方案商

#### 窗口期判断

| 因素 | 判断 | 依据 |
|------|------|------|
| **政策窗口** | 确定且持续 | 安全生产监管只会越来越严，不会放松 |
| **技术窗口** | 正在收窄 | 大模型能力快速进步，行业数据成为瓶颈而非算法 |
| **竞争窗口** | 1-2年 | 传统公司尚未技术转型，AI公司尚未积累行业数据 |
| **客户窗口** | 当下 | 保险公司利润承压，迫切需要降本增效方案 |

**结论**：现在正是建立数据壁垒的战略机遇期，错过则难以追赶。

## 三、核心术语表

| 术语 | 定义 | 上下文 |
|------|------|--------|
| **安责险** | 安全生产责任保险，施工单位必须投保的险种 | 政策强制要求 |
| **事故预防服务** | 保险公司为安责险投保单位提供的风险评估、隐患排查等服务 | 保险法定义务 |
| **小散工程** | 小型、分散的工程项目（如装修、维修等） | 监管重点领域 |
| **隐患** | 可能导致事故的风险点或不安全状态 | 巡查核心发现物 |
| **风险点** | 具有潜在危险的具体位置或情形 | 隐患的具象化描述 |
| **巡检报告** | 巡查人员现场检查后出具的正式文档 | 交付给保险公司的核心产出 |
| **整改建议** | 针对发现隐患提出的改进措施 | 与法规关联的可操作建议 |
| **数据治理** | 对隐患图片进行标注、审核、关联法规的过程 | 平台核心功能 |
| **多轮标注** | 同一数据由多个人员依次标注+审核的质量控制机制 | 确保AI训练数据质量 |
| **标注校准** | 定期检验标注员间的一致性，统一标准理解 | 质量控制手段 |
| **AI隐患识别** | 未来目标产品：通过计算机视觉自动识别施工隐患 | 最终产品形态 |

## 四、业务痛点与问题定义

### 4.1 当前痛点

```
┌─────────────────────────────────────────────────────────────┐
│                      当前业务痛点                            │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  【巡查执行端】                                              │
│   • 巡查质量高度依赖个人经验，初级/中级/高级人员差异大           │
│   • 非标作业导致保险公司巡查成本和第三方成本居高不下            │
│   • 难以规模化复制服务能力，业务增长受限于人力                  │
│                                                             │
│  【数据采集端】                                              │
│   • 巡查人员拍摄的图片质量参差不齐（模糊、角度差、光线不足）       │
│   • 缺乏统一的采集规范，导致后续处理困难                        │
│   • 图片与具体隐患位置的关联关系不明确                         │
│                                                             │
│  【数据处理端】                                              │
│   • 隐患图片与法律法规、整改建议的关联依赖人工经验               │
│   • 标注标准不统一，不同人员理解有偏差                         │
│   • 缺乏质量校验机制，低质量数据流入训练集                      │
│                                                             │
│  【价值沉淀端】                                              │
│   • 积累的数据资产无法有效检索和复用                          │
│   • 数据版本管理混乱，无法追溯                                │
│   • 无法支撑AI模型训练的高质量数据需求                         │
│                                                             │
│  【商业变现端】                                              │
│   • 完全依赖人工巡查，成本高、效率低                          │
│   • 无法规模化复制服务能力                                    │
│   • 缺乏技术壁垒，竞争门槛低                                  │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 4.2 问题分层与解决方向

| 层级 | 问题 | 根本原因 | 影响 |
|------|------|----------|------|
| **业务层** | 人工巡查成本高，难以规模化 | 依赖个人经验，质量不稳定，非标作业 | 限制业务增长 |
| **数据层** | 数据质量不可控，标注标准不统一 | 隐患判断主观性强，缺乏治理机制 | AI训练效果差 |
| **技术层** | 缺乏数据治理基础设施 | 数据分散，无版本管理，无法追溯 | 无法沉淀数据资产 |
| **战略层** | 没有技术壁垒，易被模仿 | 核心能力在人不在系统 | 长期竞争力弱 |

**业务层问题解决方向**：人工巡查模式存在根本性瓶颈，无法支撑业务规模化。经验依赖导致质量不可控、成本高昂且效率受限。解决方向是通过AI技术降低巡查成本，实现标准化和规模化，从"卖人头"转向"卖产品"。

**数据层问题解决方向**：隐患判断的主观性是导致标注一致性难以达成的核心挑战。建立数据治理体制，采用多轮标注+投票机制（如5人4一致进入下一轮），通过定期校准不断提高一致性，MVP阶段目标≥75%，逐步提升至≥85%。

---

采集规范需在质量与便捷性之间取得平衡：先推出1.0版本，基于真实数据迭代优化；既能保证数据采集质量，也能保证巡查人员的便捷性；对数据采集有规范要求，如点位、角度、张数、光线等。

**巡查员配合保障**：巡查人员是我们自己的人，具备配合基础；移动设备 App 端设计极简单，核心路径不超过3步，方便线下巡检使用；配套激励机制，确保配合度和数据质量。

## 五、业务风险与待澄清问题

### 5.1 已确认/已缓解的风险

以下风险已通过决策或资源投入得到确认或缓解：

| 风险项 | 状态 | 缓解措施 |
|--------|------|----------|
| **存储规划不确定性** | 已缓解 | MVP阶段先小规模验证，确认实际量级后再做存储规划 |
| **标注团队组建** | 已确认 | 第一阶段自建3-5人团队跑通流程，验证SOP后再引入外包 |
| **种子客户缺失** | 已缓解 | 上海已有保险公司深度对接，可共建标准 |
| **数据授权合规** | 已确认 | 可与保险公司达成书面数据使用授权协议，满足合规底线 |

### 5.2 待澄清的高优先级风险

以下风险尚未有明确答案，需在适当时机确认：

| 风险项 | 影响 | 建议跟进动作 |
|--------|------|--------------|
| **法规库结构化程度** | 影响标注准确性和知识库建设进度 | MVP阶段先用通用法规，同时启动专业人员招聘 |
| **AI团队/外部合作方** | 影响Phase 3规划和技术路线选择 | 需在Phase 2结束前确认，建议同步接触潜在合作方 |
