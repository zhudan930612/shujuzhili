# Layer Governance Rules

## 唯一判断规则

以下 6 条规则是当前仓库分层治理的唯一判断标准：

1. 凡是「每个会话都应该知道」的东西，进顶层默认层；当前仓库默认优先放 `AGENTS.md`，如果没有合适的 `AGENTS.md` 承载位，再考虑 `CLAUDE.md`。`CLAUDE.md` 在当前仓库主要作为薄指针或兜底入口，不作为首选主承载位。
2. 凡是「多步流程、专题检查、分支决策」，进 `skill`；当前仓库默认落到全局技能文件夹，例如 `~/.agents/skills/<skill-name>/SKILL.md`。
3. 凡是「只对某目录或某类文件生效」的内容，进路径作用域规则层（`path-scoped rules`）。当前仓库默认优先使用目录 `README.md` 作为该层主文件；如果某个工具支持目录级懒加载，也可以增加同目录 `CLAUDE.md` 或等价 path rules 作为适配层，但不应替代 `README.md` 作为主定义。未来如果引入同目录 `CLAUDE.md`、其他路径级规则文件或 IDE/CLI 原生 path rules，它们只作为适配层，仍视为同一层。
4. 凡是「必须每次执行、不能靠模型自觉」，进 `hook`；当前仓库默认先作为 `hook` 候选输出，参考 `.claude/settings.local.json` 及未来独立 hook 配置。
5. 凡是「模型需要真实执行或查询」，进 `CLI`、`MCP` 或 `scripts`；当前仓库默认优先落到 `06-工具脚本/*.py`、`python 06-工具脚本/run_checks.py --scope ...` 等现有执行入口。
6. 凡是已经从「专题经验」变成「所有相关任务都应该遵守的通用约束」，从 `skill` 上移到顶层默认层；当前仓库默认优先上移到 `AGENTS.md`，只有 `AGENTS.md` 不适合承载时才考虑 `CLAUDE.md`。

如果以上 6 条都不命中，不要强行升级。应明确说明当前暂不沉淀，保留在当前对话、本轮过程文档或现有位置。

## 当前仓库补充出口

以下内容不属于上面 1-6 条里的协作规则层，而属于当前仓库必须单独处理的正式主定义出口：

- 稳定业务规则
- 页面规则
- 字段规则
- 流程主定义
- 历史决策原因

这些内容不应长期留在 `03-工作台/*.md`。应根据内容拆回：

- `00-项目总览/`
- `01-产品架构/`
- `02-PRD文档/`
- `90-归档记录/`

审计或分诊时，如果判断对象本质上是业务主定义而不是协作规则、流程规则或执行动作，必须明确指出“应拆回正式主定义层”，不要误判到 `AGENTS.md`、README、skill、hook 或 script。
