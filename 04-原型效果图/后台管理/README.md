# 后台管理原型规范

## 目录定位
当前目录用于存放后台管理系统的页面原型文件。后台原型先按页面上下文组织，再在页面内部表达不同状态。

## 主要内容
- `*.html`：后台管理页面原型。
- [assets/](assets/)：后台原型公共样式、公共交互和组件契约。
- [模板文件/](模板文件/)：后台页面直接配套的 Excel 模板、示例附件。
- [后台管理-组件预览.html](后台管理-组件预览.html)：后台公共组件组合示例。

## 相关入口
- 后台 PRD：[../../02-PRD文档/后台管理/](../../02-PRD文档/后台管理/)
- 公共组件说明：[assets/README.md](assets/README.md)

## 文件组织规则
- 后台原型按页面上下文组织，而不是按弹窗类型组织。
- 默认采用 `一页一文件`：列表页、详情页、上传页、字典管理页等各自对应一个 HTML。
- 同一页面触发的弹窗、确认框、阻断提示、特殊模式，优先并入该页面 HTML 内展示。
- 只有本身就是独立页面流程的内容，才适合单独形成一个 HTML 文件。

## 归位规则
- 页面级原型直接放在当前目录。
- 公共样式、公共脚本和可复用组件契约放在 [assets/](assets/)。
- 模板、示例文件等附件放在 [模板文件/](模板文件/)。
- 移动端原型不放在当前目录，统一放在 [../移动端/](../移动端/)。

## 维护约定
- 修改后台原型前，先查看 [assets/README.md](assets/README.md) 和 [后台管理-组件预览.html](后台管理-组件预览.html)。
- 已有公共组件能覆盖时，优先复用公共组件，不新增页面私有平行实现。
- 当前目录只承载视觉和交互表达，业务规则主定义仍以 [../../02-PRD文档/后台管理/](../../02-PRD文档/后台管理/) 为准。

## 同一 HTML 的推荐结构
1. 页面骨架
2. 一级状态切换
3. 每个主状态下的页面主体
4. 必要时在主状态内再加二级切换
5. 弹窗覆盖层始终叠加在所属页面上

## 推荐实现方式
- 使用 `data-view-scope` 作为状态切换作用域。
- 使用 `state-button` 作为一级或二级状态切换按钮。
- 使用 `data-view-panel` 承载不同状态面板。
- 弹窗继续使用 `modal-stage`、`modal` 等已有结构，但展示上依附于所属页面。

## 状态分层规则
- 一级状态：页面主状态，例如空状态、详情状态、编辑状态、批量管理态。
- 二级状态：当前主状态下的关键交互态，例如删除确认、保存确认、阻断提示。
- 轻量差异：不单独切状态，例如按钮禁用、文案差异、数量变化、轻量校验提示。

## 示例
### 上传巡查记录页
- 一级状态：空状态 / 已上传状态 / 修改状态
- 二级状态：删除确认弹窗 / 保存确认弹窗 / 阻断提示
- 表达方式：先切换页面主体，再在当前主体上叠加弹窗或阻断提示

### 字典管理页
- 一级状态：页面态 / 新增弹窗 / 编辑弹窗 / 详情弹窗
- 二级状态：不同字典类型在同类弹窗中的子态切换
- 表达方式：页面主体保持稳定，弹窗态和字典类型子态通过页内按钮切换展示
